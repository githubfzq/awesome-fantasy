# 责任分散（旁观者效应）（diffusion of responsibility / bystander effect）

## R — 原文 (Reading)

> “直接负责人”有助于避免责任分散（dif f usion of responsibility）。这个概念也被称为旁观者效应（bystander effect），也就是人们身处团队中时无法对某事负起责任，因为他们认为那个责任应该由其他人承担。
>
> — 《思维模型》, 第8章 > 为谁安排什么岗位

---

## I — 方法论骨架 (Interpretation)

当责任落在一群人身上时，每个人感受到的"我的责任"都比实际小——它被摊薄到所有成员身上了。结果就是：所有人都以为别人会做，最后谁都没做。这就是责任分散，也称旁观者效应。

达利与拉塔内 1968 年的实验把它量化了：**一对一情境下 85% 的人施以援手；当受试者认为有 4 个以上旁观者时，只有 31%。** 关键变量不是冷漠，而是"以为还有别人"。

典型场景：会后每个与会者都以为别人会跟进。所以解法非常直接：**指定一名直接负责人（DRI, directly responsible individual）**，把责任从群体收回到一个具体的人身上。

这个模型还有反向用法：既然人会因为"以为别人会做"而退后，那么反过来，**有些人受到任务激励或想展示能力时会立刻挺身而出**——这就是"可控权力真空"（power vacuum）得以成立的前提：故意留出一个没人负责的位置，等想表现的人来填。

关键判据：**这件事现在能不能指名道姓说出"谁负责"？** 说不出，就是责任分散；说得出，就不是。

---

## A1 — 书中的应用 (Past Application)

### 案例: 达利与拉塔内的旁观者介入实验

- **问题**: 紧急情况发生时，旁观者越多，受害者得到帮助的概率反而越低。
- **方法论的使用**: 1968 年达利与拉塔内发表《紧急情况下的旁观者介入：责任的扩散》。实验中受试者听到"癫痫发作"的录音：以为只有自己听到时，85% 的人求助；以为有 4 人以上也听到了时，只有 31% 求助。
- **结论**: 责任被分散到每个成员身上，而不是集中在真正有责任的人身上；人数增加不会增加帮助概率，反而降低它。由此推出的组织解法是指定直接负责人。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 会议/群聊里讨论了一件事，一周后没人跟进，大家互相以为对方在做。
2. 一个跨部门项目说"由三个团队共同负责"，进度停滞。
3. 需要设计机制让团队成员主动认领任务（而不是被指派）。
4. 出现需要有人立刻出面的突发情况，但现场一堆人在观望。

### 语言信号 (用户的话里出现这些就应激活)

- "我以为他会做，他以为我会做"
- "这个事到底谁负责"
- "大家一起负责吧"（这是最高危的一句话）
- "群里发了通知没人响应"
- "上次开会说好的，怎么没人动"
- "Nobody took ownership / I assumed someone else would handle it"

### 与相邻 skill 的区分

- 与 `mm-directly-responsible-individual` 的区别: DRI 是解决责任分散的**具体制度工具**；责任分散是被解释的**现象**。先诊断现象，再上工具。
- 与 `mm-free-rider-problem` 的区别: 搭便车是"别人做我享受成果"的理性算计；责任分散是"以为别人会做所以我不用做"的认知错位，当事人往往并非有意偷懒。
- 与 `mm-groupthink` 的区别: 群体思维是"为了一致而压制异议"，发生在意见形成阶段；责任分散发生在执行阶段。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **检测责任归属是否唯一**
   - 完成标准: 尝试为这件事指名一个具体的人；说不出即确认责任分散成立。
   - 判停条件: 若已有明确唯一负责人，退出本 skill，转去查执行障碍。
2. **清点"潜在旁观者"数量**
   - 完成标准: 列出所有"以为别人会做"的人；人数越多，个体行动概率越低（可用 85%→31% 作参照量级）。
3. **指定直接负责人（DRI）**
   - 完成标准: 输出一个人名（而非团队名）+ 他需要交付的具体结果 + 时间点。
4. **公开化责任分配**
   - 完成标准: 明确责任分配要在所有相关人可见的场合宣布——私下一对一指派达不到消除"别人会做"认知的效果。
5. **（可选）反向设计权力真空**
   - 完成标准: 若目标是让人主动认领，则明确留出一个无人负责的位置并公开说明它在等认领，同时确认团队中存在受任务激励或想展示能力的人。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已经存在明确唯一责任人的任务——再加一个 DRI 只会制造混乱。
- 任务失败的真实原因是能力/资源不足，而非责任不清——指定负责人解决不了资源问题。
- 需要集体共识才能推进的决策事项（此时强行指派会绕过必要的认同）。

### 书中警告的失败模式 / 容易误用的地方

- 书中提到的反例：在某些情况下人们会立刻挺身而出，尤其是**受到手头任务激励或想展示自身能力**的时候——这正是可控权力真空得以成立的前提。也就是说，责任分散不是铁律。
- （推导, 非书中明示）DRI 泛滥会失效：如果每件事都指定同一个人，或一个人被指定为十几件事的 DRI，责任实际上又被稀释了。
- （推导, 非书中明示）在问责文化缺失的组织里，指名负责人但无后果，责任分散会以"名义 DRI"的形式复发。

### 容易混淆的邻近模型

- **搭便车现象（free rider problem）**: 有意占便宜，而非认知错位。
- **权力真空（power vacuum）**: 本模型的反向利用手法。
