# 合取谬误（conjunction fallacy）

## R — 原文 (Reading)

> 这种谬误之所以会出现，是因为两件事同时发生（合取）的概率总是小于或等于其中一件事单独发生的概率。
>
> — 《思维模型》, 第1章 少犯错 > 保持简洁，笨蛋！

---

## I — 方法论骨架 (Interpretation)

数学上，两个事件同时发生的概率不可能高于其中任一个单独发生的概率：

> P(A 且 B) ≤ P(A)，且 P(A 且 B) ≤ P(B)

因为"A 且 B"是 A 的子集——所有满足 A 又满足 B 的情况，本来就已经包含在满足 A 的情况里了，只是可能更少，绝不可能更多。

但人的直觉系统不按这个规则运行。它用的是**代表性启发**：一个描述越具体、越像某个典型形象、越容易在脑中生成一个连贯的故事，我们就越觉得它"可能发生"。细节增加了**叙事的可信度**，却降低了**事件的实际概率**，而我们把前者误读成了后者。

这就是为什么"银行出纳员且积极参与女权运动"会被多数人判断为比"银行出纳员"更可能：前者对琳达这个人物描述来说更"像"，但它在概率上严格更小。

这个谬误不只出现在心理学实验里。它在日常中长这样：

- 计划越详细越"真实"（写了 20 步的创业方案，感觉比 3 步的更可能成功——但每多一步都是一个必须成立的条件）。
- 画像越具体越可信（"35 岁、一线城市、养猫、爱露营的独立开发者"听起来是一个真实用户，但符合全部条件的人远少于只符合其中一条的人）。
- 加了限定条件的需求/方案，感觉比宽泛版本更可行。

关键判据：**选项之间是不是包含关系？** 如果一个选项是另一个选项"再加一些条件"的版本，那么它的概率必然更低，不管它听起来多像真的。

书中把合取谬误与过拟合并列为"不简化假设会落入的两个陷阱"：前者是概率层面的，后者是建模层面的。

## A1 — 书中的应用 (Past Application)

### 案例: 琳达实验（Linda problem）
- **问题**: 研究者向被试描述一位女性：31 岁、单身、直率、非常聪明，大学主修哲学，学生时代深切关注歧视与社会公正问题，还参加过反核示威。然后请被试判断哪个更可能。
- **方法论的使用**: 给出两个选项——"琳达是银行出纳员"（A）与"琳达是银行出纳员且积极参与女权运动"（A 且 B）。第二个是第一个的子集，概率严格更小。
- **结论**: 大多数受过统计训练的人仍选择了第二个，因为它的描述与琳达的形象更"匹配"。这正是代表性启发压过概率规则的经典证据，也是作者用它说明"生动的叙事细节会损害概率判断"的原因。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **估算多个场景发生的可能性，其中一个场景明显更具体**: "我们会先在小城市打开市场" vs "我们会先在小城市打开市场，然后被大厂收购"。
2. **方案越写越细，团队越觉得靠谱**: 详细的计划让人安心，但每多一个环节都在乘上一个小于 1 的概率。
3. **用户画像/目标客群被描述得极其具体**: 需要提醒：条件越多，人群越小。
4. **需求文档里的"且"链条**: "这个功能要支持导入、且能自动去重、且能离线用、且一周内上线"。
5. **判断他人的预测或承诺**: 对方给了一个细节丰富、情节完整的未来剧本，需要拆出其中串联了多少个必须成立的条件。

### 语言信号 (用户的话里出现这些就应激活)

- "这个更具体，所以更可能吧"
- "感觉这个更像真的"
- "既 A 又 B 的情况，概率应该更高"
- "我们把每一步都写清楚了，应该没问题"
- "我们的目标用户是……（一长串限定条件）"
- "他说得有鼻子有眼的，应该靠谱"
- "It's more specific, so more likely." / "That sounds more plausible."

### 与相邻 skill 的区分

- 与 `mm-base-rate-fallacy` 的区别: 基础比率谬误是**忽略先验概率**（不看整体发生率只盯着个案特征）；合取谬误是**误判条件叠加的效果**（多条件必然更小）。两者常同时出现：既忽略了基础比率，又觉得加条件后更可能。
- 与 `mm-ockham-s-razor` 的区别: 剃刀是**解释选择**的元规则（解释力相同时选假设少的）；合取谬误是**概率计算**的规则（P(A∧B) ≤ P(A)）。面对同一份过长清单，剃刀问"这条有必要吗"，合取谬误问"加这条让概率降了多少"。
- 与 `mm-overfitting` 的区别: 过拟合是模型对历史数据加了过多参数导致失去泛化；合取谬误是人对单个判断加了过多条件导致概率被高估。一个是统计建模问题，一个是直觉判断问题。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把用户的各个选项写成明确的事件陈述**
   - 完成标准: 每个选项写成可判定真假的陈述，把隐含条件全部显性化（尤其把"然后""并且""同时"都拆出来）。
   - 判停条件: 若两个选项之间不存在包含关系（既不是 A ⊆ B 也不是 B ⊆ A），本 skill 不适用，停止并说明原因。
2. **判定包含关系，指出哪个是子集**
   - 完成标准: 明确指出"选项 X = 选项 Y + 附加条件 C₁, C₂…"，因此 X 是 Y 的子集。
3. **强制套用概率规则并给出方向性结论**
   - 完成标准: 明确写出 P(X) ≤ P(Y)，且每多一个附加条件，概率只会进一步下降。禁止含糊其辞。
4. **估算下降幅度（粗略即可，数量级正确优先）**
   - 完成标准: 给出每个附加条件的大致成立概率并相乘，说明叠加后概率下降到什么量级。允许数量级估算，但要标明是估算。
   - 判停条件: 若条件之间有强正相关（不是独立事件），明确指出不能用简单乘法，改用区间估计并说明相关性来源。
5. **把"叙事可信度"与"事件概率"分开提示给用户**
   - 完成标准: 明确告诉用户：细节让故事更连贯、更容易想象，但这恰恰提高了**代表性**而不是**概率**——这是该谬误的成因。
6. **（可选）给出修正后的判断**
   - 完成标准: 用基础比率或更粗颗粒度的陈述重新表达该判断，给出一个不带附加条件的概率区间。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **选项之间不是包含关系时**: 若两个选项是互斥的或交叉的，P(A∧B) ≤ P(A) 套不上，此法无效。
- **评估的是叙述的合理性/一致性而非发生概率时**: "这个解释讲得通吗"与"这件事会发生吗"是两个问题。合取谬误只管后者。
- **条件近乎必然成立时**（推导, 非书中明示）: 若附加条件几乎是同义反复（"下雨且地上有水"），概率下降的幅度可忽略，此时提醒用户没有实际意义。

### 书中警告的失败模式 / 容易误用的地方

- **书中未给明确边界，但把它与"过拟合"并列为不简化假设会落入的两个陷阱**（`boundary` 字段原文）——也就是说，作者的用意是告诫你**别给判断加太多条件**，而不是只把它当作一个冷僻的心理学名词。
- （推导, 非书中明示）**只纠正别人不纠正自己**: 知道这条规则并不能免疫它——琳达实验中被试很多是受过统计训练的人。对策是强制把选项写成集合关系再判断，而不是凭"我知道这个偏差"就放心。
- （推导, 非书中明示）**忽略条件间的相关性**: 简单相乘会严重低估高度相关的条件组合（"下雨且地湿"不是两个独立事件）。用乘法前必须先问相关性。
- （推导, 非书中明示）**反过来滥用**: 不能因为"加条件概率下降"就认为最宽泛的陈述总是最好的判断。过于宽泛的预测信息量为零。目标是找到恰当颗粒度，不是越粗越好。

### 容易混淆的邻近模型

- **代表性启发（representativeness heuristic）**: 是合取谬误的**成因**——细节提升了"像不像"的匹配度；合取谬误是它导致的**结果**。
- **条件概率（conditional-probability）**: P(A|B) 与 P(A∧B) 是不同概念。合取谬误常源于把"给定 B 时 A 很像"（高 P(A|B)）误当成" A 且 B 同时发生"（高 P(A∧B)）。
