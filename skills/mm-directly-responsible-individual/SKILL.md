# 直接负责人（directly responsible individual, DRI）

## R — 原文 (Reading)

> 每次例会后，苹果公司都会明确指定一名直接负责人，为每个行动项目负全责。“鸭鸭搜索”同样为公司的每项活动（从微不足道的小任务，到极为重要的公司目标）指定直接负责人。
>
> — 《思维模型》, 第8章 > 为谁安排什么岗位

---

## I — 方法论骨架 (Interpretation)

直接负责人（DRI, directly responsible individual）是一条极简的制度：为每一项行动明确指定**一名**负全责的个人，而不是一个团队、一个部门或"大家一起"。苹果公司每次例会后都会指定一名 DRI；鸭鸭搜索把它推广到公司的每项活动，从微不足道的小任务到极为重要的公司目标，一视同仁。

它针对的病症非常具体：**会后拖延**——每个与会者都以为别人会去做，结果谁都没做。这是"消除责任分散倾向的简便有效方法"：责任一旦被指名，就不再能被摊薄。

关键判据是**可指名性**：能不能说出一个具体的人名（而不是团队名），这个人是否知道自己是负责人，他是否清楚要交付什么、什么时候交。三条缺一，DRI 就只是名义上的。

值得注意的是适用范围——书中强调它适用于**从微不足道的小任务到极为重要的公司目标**的全部活动。这说明 DRI 的价值不随事项重要性递减，小任务反而更容易因为"不值得指派"而烂尾。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 会议/群聊里讨论并"定了"某件事，过一段时间发现没人推进。
2. 一项跨部门工作写成"由 X 组和 Y 组共同推进"，进度停滞。
3. 建立团队执行规范：想把"说了就算做了"变成可追踪的机制。
4. 布置一项没人愿意做的小事（订会议室、更新文档、清理看板），担心它烂尾。

### 语言信号

- "上次开会说好的，怎么没人动"
- "这个事到底归谁"
- "大家一起负责吧"
- "群里@了所有人，结果没人回"
- "这个小事谁来弄一下"
- "Who owns this?" / "I thought someone else was handling it"

### 与相邻 skill 的区分

- 与 `mm-diffusion-of-responsibility` 的区别: 责任分散是被解释的**现象**（人多了反而不行动），DRI 是消除它的**制度工具**。先诊断现象，再上工具。
- 与 `mm-power-vacuum` 的区别: 权力真空是**故意不指定**负责人、等想展示能力的人主动站出来，用于识别人选与激发主动性；DRI 是**明确指定**，用于保证执行。两者方向相反，分别用于"要确定性"和"要发现人"的场景。
- 与 `mm-free-rider-problem` 的区别: 搭便车是"别人做我享受成果"的理性算计，需要的是激励机制；DRI 解决的是"以为别人会做"的认知错位。

## E — 可执行步骤 (Execution)

1. **确认责任是否已唯一**
   - 完成标准: 尝试为此事指名一个人。若已有明确唯一负责人且他知情，退出本 skill，转查能力与资源问题。
2. **指定一名（不是多名）负责人**
   - 完成标准: 输出一个人名，而非团队名/角色名；不得出现"共同负责"。
3. **补齐三个要素**
   - 完成标准: 人名 + 具体交付物（可验收的结果，不是"推进一下"）+ 时间点。
4. **公开化并当场确认本人接受**
   - 完成标准: 在所有相关人可见的场合宣布，并得到该人明确回应；私下一对一指派无法消除"别人会做"的认知。
5. **覆盖小任务**
   - 完成标准: 检查本轮讨论里最不起眼的 2-3 项（更新文档、通知某人、订场地）是否也各自有了 DRI；书中明确它们同样需要。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 已经有明确唯一负责人的任务——再指定只会制造混乱和重复汇报。
- 失败原因是资源、权限或能力不足——指名负责人解决不了这些问题，反而会让人背锅。
- 需要集体共识才能推进的决策事项——此时应先把决策流程走完，再指定执行 DRI。

### 容易误用的地方

- （推导, 非书中明示）书中未提局限。由机制可推导：DRI 泛滥会失效——同一个人挂十几项 DRI，责任实际上又被稀释了，等于回到责任分散。应限制每人在办 DRI 的数量。
- （推导, 非书中明示）在缺乏问责后果的组织里，指名但无后果会以"名义 DRI"的形式复发。DRI 需要配套的验收与回顾。
- （推导, 非书中明示）DRI 只解决"谁做"，不解决"怎么做"；对高难度任务需要同时给资源与授权，否则指名等于指派失败。

### 容易混淆的邻近模型

- **责任分散（diffusion-of-responsibility）**: DRI 要消除的现象本身。
- **权力真空（power-vacuum）**: 反向操作——故意留空以观察谁主动补位。
