# 奥卡姆的剃刀（Ockham's razor）

## R — 原文 (Reading)

> "奥卡姆的剃刀"（Ockham's razor）会对你有所帮助。它指出，最简单的解释最有可能是正确的。
>
> — 《思维模型》, 第1章 少犯错 > 保持简洁，笨蛋！

---

## I — 方法论骨架 (Interpretation)

"剃刀"这个比喻是精确的：它不是一把用来切割事实的刀，而是一把用来**刮掉多余假设**的刀。当两个解释都能说明同一组观察到的数据时，优先选假设更少的那个。

为什么这个规则有用？因为每加一条假设，就多一次出错的机会。假设是"我猜是这样但还没有证据"的东西；一个由五条假设支撑的结论，其成立概率大致是这五条都成立的概率——假设越多，链条越脆。同时，多余的假设往往是**为了保住某个先入为主的结论**才被加上去的，它们不是从事实里长出来的，而是被塞进去的。

书里给的操作方法是把解释拆成一条条基本假设，然后对每一条追问两个问题：

1. 它真的有必要存在吗？（去掉它，剩下的是不是仍然能解释全部事实？）
2. 有什么证据支持保留它？

答不上第二个问题的，剃掉。

要注意的是，**它是一条指导而不是定律**。作者明确说它不是永远正确的法则，有时真正的解释确实极其复杂。奥卡姆剃刀说的是"在解释力相同的情况下优先简单的"，不是"简单的一定对"。如果某个复杂假设有实打实的证据支撑，剃刀不该碰它。

书中把它和"合取谬误""过拟合"并列：不简化假设会落入的陷阱，一边是概率上的（合取谬误），一边是建模上的（过拟合），而奥卡姆剃刀是针对**解释结构**的那一剂药。

关键判据：**去掉这条假设，解释力会下降吗？** 不会，就剃掉。

## A1 — 书中的应用 (Past Application)

### 案例: 用剃刀修剪交友清单
- **问题**: 一个人在找伴侣时列出了一长串过于具体的标准——去同一家高温瑜伽馆、爱吃山莓冰淇淋、蓝眼睛、巴西人、最喜欢的电影角色是雷神索尔。这份清单实际上是几乎不可能被满足的一组合取条件。
- **方法论的使用**: 把这些标准当成一条条假设，逐条追问"它真的有必要吗？有什么证据支持它对一段关系的质量是必需的？"——大多数答不上来，于是被剃掉。
- **结论**: 剃完之后只剩三条：能促使彼此思考、能逗你笑、有吸引力。清单的可满足性大幅提高，而核心诉求并没有损失。作者用它示范：剃刀不只是科学方法论，也是日常里削减自设约束的工具。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **为一个现象找出好几个解释，无法取舍**: 同事为什么辞职、用户为什么流失、系统为什么变慢、对方为什么那样说。每个解释都讲得通，需要削减。
2. **方案/需求/清单越加越长**: 招人标准、选型条件、需求文档、合作条款——每加一条都在降低可满足性，需要回头问每一条是否必要。
3. **怀疑自己在过度解读**: 用户从别人的一句话、一个表情、一次沉默里推出一整套动机，需要把隐含假设挖出来晒一晒。
4. **模型/规则复杂到难以解释**: 风控规则、评分模型、流程分支越来越复杂，且并没有带来可验证的效果提升。
5. **辩论中对方堆了大量解释性假设**: 需要逐条要求证据，而不是整体接受或整体拒绝。

### 语言信号 (用户的话里出现这些就应激活)

- "是不是我想太多了 / 想复杂了"
- "有几种可能，我不知道该信哪个"
- "他是不是在暗示什么？"
- "这些条件是不是太苛刻了"
- "能不能简单点，把这些砍一砍"
- "这个规则为什么要加这一条？"
- "What's the simplest explanation?" / "Are we overcomplicating this?" / "Is this assumption necessary?"

### 与相邻 skill 的区分

- 与 `mm-conjunction-fallacy` 的区别: 合取谬误处理的是**概率判断**——人们会觉得"条件更多的情形"更可能发生；奥卡姆剃刀处理的是**解释选择**——多个解释解释力相当时选假设少的。前者是概率规则，后者是解释的元规则。二者常一起出现（清单过长同时犯了这两个错），但处方不同。
- 与 `mm-overfitting` 的区别: 过拟合是**模型**对历史数据拟合得太好以致失去泛化能力；剃刀是**解释/假设集**的精简原则。过拟合是剃刀在统计建模领域的具体表现。
- 与 `mm-arguing-from-first-principles` 的区别: 第一性原理是从底部**重建**；剃刀是从现有解释里**删减**。一个做加法一个做减法，方向相反，可先后使用。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认存在多个竞争解释，且它们解释的是同一组事实**
   - 完成标准: 至少列出 2 个候选解释，并确认它们要解释的现象是同一组观察事实（不是各说各的）。
   - 判停条件: 若只有一个候选解释，本 skill 不适用——没有比较对象就无从剃，转向去风险化或直接检验该解释。
2. **把每个解释拆成基本假设列表**
   - 完成标准: 每个解释拆成 3-8 条原子假设，每条是一个独立的、可被质疑的陈述（"对方知道那件事""他有意让我难堪""系统瓶颈在磁盘 IO"）。
3. **逐条问两个问题并标注去留**
   - 完成标准: 对每条假设标注：(a) 去掉它，剩下的还能解释全部事实吗？(b) 支持它的证据是什么？标注为"必要且有证据 / 必要但无证据（标记为待验证）/ 不必要（剃掉）"。
   - 判停条件: 若一条假设被标为"必要但无证据"，不要直接剃掉——它可能是真但尚未验证的，转入去风险化设计一次检验，而不是当场判定。
4. **比较剃完之后各解释的假设数量与解释力**
   - 完成标准: 输出对比：每个解释剩下几条假设、分别覆盖了哪些事实、有没有哪条事实它解释不了。
   - 判停条件: 若简单解释**漏掉了某条已观察到的事实**，停止——解释力不同就不满足剃刀的适用前提，不能靠"更简单"取胜，应回到第 2 步修正。
5. **输出结论并声明置信度**
   - 完成标准: 选出假设最少的那个作为首选，同时明确写出：这是"最可能"而不是"确定"，以及如果要推翻它，需要找到什么证据。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **只有一个候选解释时**: 没有比较对象，剃刀无从下手。此时应该去生成对立假设（alternative-hypothesis）或做检验。
- **简单解释漏掉事实时**: 剃刀的前提是"解释力相同"。如果复杂解释能解释全部事实而简单解释不能，那么更简单没有意义。
- **需要高精度而非快速判断的场合**（推导, 非书中明示）: 科学建模、医疗诊断、金融风控等领域，简单模型的偏差代价可能远高于复杂模型，此时应以证据而非简洁为准。

### 书中警告的失败模式 / 容易误用的地方

- **作者明说它不是永远正确的法则，只是指导；有时真正的解释确实极其复杂**（`boundary` 字段原文）。把它当定律会削掉真实存在的机制。
- （推导, 非书中明示）**把它当成人身攻击的武器**: "你这个太复杂了"常被用来压过提出复杂解释的人。正确的用法是逐条追问证据，而不是整体宣布对方想多了。
- （推导, 非书中明示）**剃掉"暂时没有证据但必要"的假设**: 有些假设之所以存在，正是因为它解释了一条事实。剃之前必须先确认"去掉它事实仍然被解释"。
- （推导, 非书中明示）**简单 ≠ 更符合直觉**: 最简单的解释有时是反直觉的（比如"没有人在策划，只是随机波动"）。别让"简单"服务于"我更愿意相信"。

### 容易混淆的邻近模型

- **汉隆的剃刀（hanlon-s-razor）**: "能用愚蠢解释的，不要用恶意解释"——是奥卡姆剃刀在动机归因上的一个具体应用，只处理"恶意 vs 疏忽"这一类选择。
- **KISS 原则（keep-it-simple）**: 是关于**设计/实现**的偏好（保持简单）；奥卡姆剃刀是关于**解释/假设选择**的认识论原则。前者追求可维护性，后者追求正确性。
