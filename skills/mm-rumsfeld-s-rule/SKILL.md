# 拉姆斯菲尔德法则（Rumsfeld's Rule）

## R — 原文 (Reading)

> 美国前国防部长唐纳德·拉姆斯菲尔德也说过类似的话，也就是著名的“拉姆斯菲尔德法则”（Rumsfeld's Rule）：你是带着现有的部队参战，而不是你想要或希望拥有的部队。
>
> — 《思维模型》, 第8章 > 开篇

---

## I — 方法论骨架 (Interpretation)

这句话表面是常识，实际是在切断一条最常见的拖延路径：**"等条件齐了再开始"**。组织几乎永远处在人员不齐、能力不完美的状态；如果行动前提是"等到配齐理想的队伍"，那多数行动会永远不开始——因为招聘周期长、大牛稀缺、预算有限，而机会窗口不等人。

它成立的原因在于：**"理想队伍"是一个反事实，而反事实不能进入决策。** 你的收益矩阵里没有"拥有理想部队"这个选项，只有"用现有部队打"和"不打"两个选项。既然前者不存在，把资源花在幻想它上就是纯消耗。

它与乔伊法则（Joy's Law）互为补充，二者合起来才是完整判断：

- 乔伊法则：无论你多努力，最优秀的人大概率不在你的组织里——这是**事实判断**；
- 拉姆斯菲尔德法则：但你仍得用眼前这拨人开打——这是**行动指令**。

光有前者会滑向犬儒（"反正找不到牛人，算了"），光有后者会滑向蛮干（"别抱怨，硬上"）。合起来是：**承认人才约束是常态，然后把问题从"怎么找到完美的人"重构为"怎么让现有的人发挥出最大战力"。**

关键判据是：**这件事是否因"人手不对"而被推迟？** 若是，适用——先承认约束，再在现有队伍内重新排兵布阵。注意它不承诺结果，只承诺：等待不会让约束消失。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 项目因为"还缺两个资深工程师"一直没启动，用户在想要不要等招聘。
2. 新任管理者接手一个能力参差的团队，抱怨"这拨人做不了这件事"。
3. 小公司面对大厂竞争，觉得"我们没有他们那样的人才，没法比"。
4. 用户在反复修改组织架构图，而不是推进业务。
5. 团队士气低落，因为大家都在等一个"救世主式"的新成员。

### 语言信号 (用户的话里出现这些就应激活)

- "等招到人再说吧"
- "要是团队里有个大牛就好了"
- "这拨人做不了这个"
- "人手不够，没办法"
- "先凑合着，等有资源了再说"
- "we need better people first / you go to war with the army you have / make do with the team we have"

### 与相邻 skill 的区分

- 与 `mm-joy-s-law` 的区别: **构成一组，方向互补。** 乔伊法则说"最好的人不在你这儿"（事实判断），拉姆斯菲尔德法则说"但你仍得用眼前这拨人开打"（行动指令）。用户停在抱怨人才时用乔伊法则承接；用户因抱怨而不行动时用本 skill 推进。
- 与 `mm-10x-engineer` 的区别: 十倍工程师与十倍团队解决"如何在现有人员中**造出**十倍产出"（人岗匹配设计）；本 skill 解决"在人力约束下**还要不要行动**"。前者是提升上限的方法，后者是接受约束的纪律。
- 与 `mm-punching-above-your-weight` 的区别: 挑战重量级是竞争层面的"要不要越级参战"判断；本 skill 是执行层面的"用现有资源开打"纪律，范围更靠内。
- 与 `mm-managing-to-the-person` 的区别: 以人为本的管理是具体的管理方法（按个体差异调整管理动作）；本 skill 是接受人力约束的前提性心态。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把"理想部队"从决策里移除**
   - 完成标准: 明确写出用户心中的理想配置，然后标注它**在当前周期内不可得**的具体原因（预算、周期、市场供给）。
   - 判停条件: 若理想配置在合理周期内可得且是任务必需，则这不是"参战"问题而是招聘问题，转招聘规划。
2. **盘点现有部队的真实能力**
   - 完成标准: 逐个列出团队成员的可用能力（而非头衔），包括被低估的能力与当前未被使用的能力。
3. **重构任务而非降低目标**
   - 完成标准: 保持目标不变，给出 2-3 种**改变打法**的方案——缩小首战范围、换技术路线、外包非核心、用工具替代人力、把任务重排给最匹配的人。
4. **分配角色到"最匹配"而非"最资深"**
   - 完成标准: 为每个关键环节指定负责人，原则是能力-任务匹配，并说明为什么这样排（可结合 `mm-10x-engineer` 的人岗匹配思路）。
5. **识别真正不能绕的缺口**
   - 完成标准: 列出 1-2 个"绕不过去、必须补"的能力缺口，并给出补法（招聘、外部顾问、培训、合作）。这条清单要短——列长了说明还是在等理想部队。
6. **定下开打时点与首个可交付物**
   - 完成标准: 明确写出"用现有部队在 X 时间前交付 Y"，Y 是真实可验收的成果而非准备工作。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 正在做长期人才规划、组织架构设计或招聘决策——此时讨论"理想配置"本身就是任务内容。
- 现有资源**低于完成任务的最低门槛**（安全、合规、专业资质要求）——这不是心态问题，是硬约束，硬上会出事故。
- 用户需要的是"如何让人发挥更好"的方法，而不是"要不要行动"的决心——改用十倍工程师与十倍团队、以人为本的管理。
- 用户刚经历重大人员流失、正处于恢复期——先处理损失与情绪，再谈接受约束。

### 容易误用的地方

- 书中未提边界，仅提示"可推知的误用：把它当作不必改善人员结构的借口"。
- （推导, 非书中明示）最常见的误用是把它变成**管理层压制的工具**："别抱怨人了，手头有什么用什么。" 正确的用法是承认约束后**主动重构打法**，而不是要求团队用同样的方式更努力。
- （推导, 非书中明示）它不等于"永远不要招人"。法则是说不能**等**招到人再打，不是说招人无意义——行动与补人应当并行。
- （推导, 非书中明示）在需要长期积累的能力（研究、安全、医疗）上强行"带着现有部队上"，代价可能远大于等待。

### 容易混淆的邻近模型

- **乔伊法则（Joy's Law）**: 与本 skill 互补成对——事实判断 + 行动指令，常被一起引用。
- **十倍工程师与十倍团队（10x engineer / 10x team）**: 在承认约束之后，用于提升现有人产出的方法论。
