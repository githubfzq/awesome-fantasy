# 可逆决策与不可逆决策（reversible vs. irreversible decisions）

## R — 原文 (Reading)

> 有些决策会带来后续影响，这些影响是不可逆或近乎不可逆的，就像一扇单向门。这些决策必须运用系统的方法，经过深思熟虑和意见征询，审慎而缓慢地进行……但大多数决策不是这样的——它们是可改变、可逆转的，就像一扇扇双向门。即使你做出了次优（可逆）决策，也不需要长时间承受后果。
>
> — 《思维模型》, 第2章 > 好事过头成坏事

---

## I — 方法论骨架 (Interpretation)

这个模型给出的不是"怎么决策"，而是"该为这个决策投入多少决策成本"。判据只有一条：**错了能不能退回来**。

能退回来的是双向门（可逆决策）：即使做了次优选择，也不需要长时间承受后果，所以应该压缩决策成本、鼓励快速试验。退不回来的是单向门（不可逆决策）：必须运用系统方法，经过深思熟虑与意见征询，审慎而缓慢地进行——生孩子、卖掉一手创立的公司属于这一类。

它的价值在于纠正一个系统性的错配：贝佐斯在致股东信中指出，**大多数决策其实是可逆的**，但组织规模变大后，会把为不可逆决策设计的重量级流程套用到所有决策上。后果是行动迟缓、规避风险、缺乏试验、创新减少——用昂贵的流程去处理廉价的错误。

反过来说，把可逆决策当不可逆来对待，代价是速度与试验次数；把不可逆决策当可逆来对待，代价是灾难且无法挽回。两个方向的错误不对称，所以必须先分类再选流程。

组织层面的病尤其值得注意：流程一旦建立就会自我扩张，把所有决策都拉进自己的管辖范围，因此需要有意识地保护可逆决策的快速通道。

---

## A1 — 书中的应用 (Past Application)

### 案例: 贝佐斯的单向门与双向门

- **问题**: 组织在成长过程中普遍出现的问题：所有决策都被套用同一套重量级流程，导致行动迟缓、规避风险、缺乏试验、创新减少。
- **方法论的使用**: 贝佐斯在致股东信中提出单向门/双向门框架：不可逆或近乎不可逆的决策（单向门）必须系统性地深思熟虑并征询意见；而大多数决策是可改变、可逆转的（双向门），即使做出次优选择也不需要长时间承受后果。作者强调的判据只有一条——错了能不能退回来。
- **结论**: 贝佐斯原文强调"大多数决策"是可逆的，因此不应默认使用重量级流程。作者给的例子是生孩子、卖掉一手创立的公司这类不可逆决策。本章也提醒要"牢记不可逆决策与可逆决策之间的区别，避免陷入后者导致的分析瘫痪"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 纠结"这件事要审多久、要不要上报、要不要开三次会"。
2. 面对重大承诺：结婚生子、卖公司、签长约、不可逆的数据操作、公开承诺。
3. 组织流程过重、团队不敢做小决定，创新与试验减少。
4. 想快速试错但不确定安全边界在哪里。
5. 复盘一次决策失误：是决策本身错了，还是用错了决策流程。

### 语言信号 (用户的话里出现这些就应激活)

- "这个要不要走审批流程"
- "万一做了回不来怎么办"
- "我们是不是把简单的事搞复杂了"
- "先小范围试试行不行"
- "这件事一旦做了就改不回来了"
- "one-way door / two-way door / reversible / can we undo it"

### 与相邻 skill 的区分

- 与 `mm-analysis-paralysis` 的区别: 可逆/不可逆决策是**分类框架与流程分配规则**（决定投入多少决策成本），分析瘫痪是**卡住的状态**。前者是后者的解药之一——把可逆决策识别出来就能解除瘫痪。
- 与 `mm-de-risking` 的区别: 去风险化是"想办法把一个不可逆决策变成可逆的"（先降低不确定性再行动），可逆/不可逆是"判断它现在属于哪一类"。前者改变决策的属性，后者适配决策的流程。
- 与 `mm-precautionary-principle` 的区别: 风险预防原则主张"面对不可逆的重大危害，即使证据不充分也应先防范"，它只在**不可逆且危害巨大**时适用；可逆/不可逆框架则提醒不要把它滥用到可逆决策上。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **对决策做可逆性判定**
   - 明确问：如果做错了，能不能退回来？退回的代价是什么（时间、金钱、信誉、关系）？
   - 完成标准: 有明确归类（单向门/双向门）+ 退回代价的估计。
   - 判停条件: 若退回代价接近无限（人命、不可恢复的数据、法律不可逆），直接判定为不可逆。
2. **可逆 → 压缩决策成本，走快速通道**
   - 指定单一决策人、设时间盒、允许小步试错与灰度。
   - 完成标准: 有明确的决策人、时间上限与回滚方案。
3. **不可逆 → 投入系统性流程**
   - 安排深思熟虑与意见征询，列出必须征询的对象与关键未知项。
   - 完成标准: 有征询清单与一份"我们还没搞清楚的关键问题"列表。
4. **尝试把单向门改造成双向门**
   - 手段：先小范围试点、分阶段承诺、保留退出条款、用可撤销的方式先验证（如先合作后并购）。
   - 完成标准: 至少提出 1 种把不可逆降级为可逆（或把代价变小）的做法。
   - 判停条件: 若确实无法降级，明确说明"此项必须慢"，并停止施加加速压力。
5. **检查组织是否把重流程套在了双向上**
   - 问：这个流程是为哪类决策设计的？现在被用在了哪些决策上？
   - 完成标准: 列出被过度流程化的可逆决策，并给出豁免清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 所有决策后果都极其轻微、分类不产生任何行动差异时：直接快速决定即可，无需分类开销（推导，非书中明示）。
- 已经处于危机、需要立即响应的情形：来不及分类，先止损（推导，非书中明示）。
- 把"可逆"当成"可以草率"：可逆只是说代价可承受，不等于不需要思考（推导，非书中明示）。

### 书中警告的失败模式 / 容易误用的地方

- 贝佐斯原文强调"大多数决策"是可逆的，因此不应默认使用重量级流程——最常见的误用是把重流程套在双向门上，导致行动迟缓、规避风险、缺乏试验、创新减少（书中明示）。
- 本章要点提醒要"牢记不可逆决策与可逆决策之间的区别，避免陷入后者导致的分析瘫痪"（书中明示）——反过来，把不可逆决策当可逆处理更危险，因为无法挽回。
- 可逆性判断本身可能出错：看似可逆的决定有时因连锁承诺而变得难以撤回（如公开宣布后的信誉成本），判定时应把连带后果算进去（推导，非书中明示）。

### 容易混淆的邻近模型

- 与分析瘫痪：可逆/不可逆是解药（流程分配），分析瘫痪是病症（决策停滞）。识别出"这是双向门"通常就能解除瘫痪。
- 与去风险化：去风险化试图**改变**决策的可逆性，本 skill 是**适配**决策的可逆性；两者常串联——先尝试去风险，去不掉就按不可逆处理。
