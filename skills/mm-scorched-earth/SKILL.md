# 焦土战术（scorched earth）

## R — 原文 (Reading)

> 类似需要避免的做法是焦土（scorched earth）战术，也就是指焚烧（烧焦）地面（土地），使任何人（包括你自己）都无法使用，例如销毁记录。
>
> — 《思维模型》, 第7章 > 终局

---

## I — 方法论骨架 (Interpretation)

焦土战术源自军事：撤退时烧毁土地、庄稼、水源，让追击的敌军无法就地补给。关键是最后四个字——**包括你自己**。你烧掉的是你还可能回来的地方，你毁掉的资源对你也永久失效。

在商业与职场语境里，它的形态是销毁记录、删除数据、破坏文档、带走并废掉客户资料。动机通常是两件事之一：报复（让接手的人不好过），或掩盖（让某些记录不存在）。

它为什么被作者明确列为"需要避免的做法"？因为它的成本结构极差：

1. **自伤是确定的，伤敌是不确定的。** 你一定失去这些资源，对方未必真被卡住——他可能有备份、有替代来源，或者干脆因此更轻松地重建。
2. **不可逆。** 与过河拆桥不同，关系还有修复的可能，销毁的数据通常没有。
3. **它是可被追溯的行为。** 在数字环境里，销毁记录几乎总留下痕迹，而这个痕迹本身就是新的风险来源（法律责任、职业声誉）。

关键判据：**这项资源对我自己还有没有未来价值？** 如果有，焦土必然是净损失；如果确实没有，那销毁它的动机多半不是战术，而是情绪或掩盖——这两者都不该用"战术"来包装。

作者把它与"保留可能性"（第2章）明确对立：全书立场是保留选项，而焦土是主动且彻底地消灭选项。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 离职前想删掉自己写的代码、文档、客户名单，"反正也不给公司留"。
2. 创业失败或合伙拆伙，考虑清空服务器、销毁资料。
3. 项目被叫停/交接，想让接手方"从头开始"。
4. 被解雇后想拿走或废掉某些工作成果作为谈判筹码。
5. 用户在气头上说"我把东西全删了"——需要立即评估后果与补救。

### 语言信号 (用户的话里出现这些就应激活)

- "我把东西全删了，让他们从头做"
- "反正这些是我做的，我有权处理"
- "不想给公司留下任何东西"
- "销毁记录/清空数据库"
- "谁都别想得到"
- "scorched earth / delete everything / leave them nothing"

### 与相邻 skill 的区分

- 与 `mm-burning-bridges` 的区别: 过河拆桥毁的是**关系**（未来回不来但资源还在），焦土毁的是**资源本身**（谁都用不了，包括你自己）。焦土通常同时毁关系，是更极端的一档。
- 与 `mm-burn-the-boats` 的区别: 破釜沉舟是**主动**自绝退路以激励团队向前，动机是凝聚、方向朝前；焦土是撤退时毁资源，动机是报复或掩盖、方向朝后。二者都"毁掉退路"，但性质相反——书中特别澄清了这层混淆。
- 与 `mm-exit-strategy` 的区别: 退出策略是设计如何体面退出并保留可能性；焦土是全书立场中退出时应避免的极端做法。
- 与 `mm-nuclear-option` 的区别: 核选项是**威胁**（说出来逼对方让步），焦土是**执行**（真的毁掉）。威胁不一定要兑现，执行了就不可逆。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **立即确认是否已有不可逆动作发生**
   - 完成标准: 明确询问并确认用户是否已经删除/销毁。若是，跳到步骤 5 走止损与合规路径；未发生则继续。
2. **区分合法权利与越界行为**
   - 完成标准: 明确列出哪些资产属于用户（个人作品集、个人笔记、法律上属于自己的文件），哪些属于组织/他人（公司代码、客户数据、职务成果、他人隐私）。
   - 判停条件: 若涉及组织资产、他人数据或可能触犯法律，明确告知不要执行，并说明潜在后果（民事、刑事、职业声誉）。
3. **拆解真实动机**
   - 完成标准: 判断动机属于哪一种——报复、掩盖、谈判筹码、还是恐惧被抢功。把动机说出来，因为不同动机有不同的正当解法。
4. **给出正当替代方案**
   - 完成标准: 针对每种动机给出替代动作：报复→走正式申诉或仲裁；掩盖→合规删除与律师咨询；筹码→书面约定与离职协议；怕被抢功→留下署名与时间戳证据。至少给出一条可执行的具体动作。
5. **若已发生，做止损与补救**
   - 完成标准: 给出三步——停止进一步操作、保留现状不再覆盖（以便恢复或说明）、主动向相关方说明并寻求法律意见。明确不建议隐瞒或继续掩盖。
6. **保住自身合法权益**
   - 完成标准: 列出用户此刻**应当**带走或备份的东西（自己的劳动合同、工资与绩效记录、属于自己的作品副本、工作成果证明），把注意力从"毁掉"转向"保护"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 正常的合规数据清理、按流程删除过期文件、保护个人隐私——这些是正当行为，不是焦土。
- 用户在合法范围内主张自己的知识产权与作品归属——应支持，而不是劝退。
- 涉及违法指令（删库、销毁证据、破坏他人资产）——一律明确拒绝协助，并建议走法律途径。
- 用户处于极端情绪中且有自伤或报复倾向——先做情绪支持与风险干预，不讨论战术细节。

### 容易误用的地方

- 书中明示：全书立场是焦土与"保留可能性"（第2章）相悖，通常不应采用；作者明确把它列为"需要避免的做法"。
- 书中明示定义即含自伤——"使任何人（包括你自己）都无法使用"。把它当成纯粹的伤敌手段，是根本性的误读。
- （推导, 非书中明示）在数字环境下，销毁记录往往留下更糟的痕迹：操作日志、备份、版本历史都会让"销毁"变成"可被证明的销毁"，风险高于原问题本身。
- （推导, 非书中明示）焦土会连带伤害无辜——同事、下游客户、依赖该数据的第三方，这会把一次冲突变成长期的行业声誉问题。

### 容易混淆的邻近模型

- **过河拆桥（burning bridges）**: 毁关系，可修复；焦土毁资源，通常不可修复。
- **破釜沉舟（burn the boats）**: 主动自绝退路以向前，是策略；焦土是撤退中毁资源，是被反对的做法。
