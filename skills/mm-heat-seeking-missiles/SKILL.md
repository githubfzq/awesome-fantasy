# 热源追踪导弹（heat-seeking missiles）

## R — 原文 (Reading)

> 导弹在发射前瞄准哪里并不重要。成功的企业家总在收集数据，不断寻找更大、更好的目标，在必要的时候调整轨迹。
>
> — 《思维模型》, 第9章 > 缺少执行的愿景不过是幻想

---

## I — 方法论骨架 (Interpretation)

**热源追踪导弹（heat-seeking missiles）** 是投资家乔什·科佩尔曼用来形容成功创业者的比喻：他们像发射后持续修正轨迹、最终锁定目标的导弹。

**它描述什么**：**导弹在发射前瞄准哪里并不重要**——重要的是发射之后能否持续收集数据、不断寻找更大更好的目标，并在必要时调整轨迹。找到目标之后，还能在拥挤的市场中锁定它。

**为什么成立**：早期对"正确目标"的判断几乎必然是错的，因为在没有真实数据之前，你对用户、需求、渠道的想象都是假设。静态瞄准的导弹一旦初始判断偏差，就永远打不中；而热源追踪导弹把"修正能力"内置在系统里，让初始误差变得可容忍。换句话说：**不是先想清楚再动，而是先动起来才可能想清楚**。

**关键机制有三条**：

1. **发射优先**。待在发射架上进行无限期的瞄准，得到的不是精确，是零信息。
2. **持续收集数据**。修正需要热源——没有数据流，所谓"灵活"只是摇摆。
3. **寻找更大更好的目标**。修正的方向不是随机漂移，而是朝"更大更好"移动；否则只是在原地打转。

这个比喻指向的终点是**规避风险地实现产品/市场匹配**：不是靠一次豪赌押中，而是靠多次小修正逼近。

**关键判据**：你现在多做的一周思考，是在产生新数据，还是在重复已有的假设？前者值得，后者就是没发射。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队因为"还没想清楚"而迟迟不启动，讨论陷入循环。
2. 已上线，出现了比原计划更好的机会，纠结要不要改方向。
3. 想用"再调研一个月"来规避风险，实际是在拖延。
4. 在拥挤市场里，需要判断如何锁定目标而不是被淹没。
5. 反复改方向但说不清依据，怀疑自己只是摇摆。

### 语言信号

- "还没想清楚，要不要再等等"
- "先做个小版本试试水行不行"
- "我们发现了更大的机会，要不要转过去"
- "边做边看吧"
- "用户反馈和原计划不一样，要不要改"
- "我们是不是改方向改太频繁了"
- "heat-seeking missiles / product-market fit / let's just ship and see / should we pivot / iterate"

### 与相邻 skill 的区分

- 与 `mm-idea-maze` 的区别: 迷宫强调**发射之前**尽力画好地图（行业史、玩家、死路、技术变量）；导弹强调**发射之后**靠数据修正。两者互补而非对立——先尽力画地图降低成本，再靠数据修正残余误差。用迷宫否定发射会陷入分析瘫痪，用导弹否定地图会重复撞别人撞过的墙。
- 与 `mm-pivot` 的区别: 转型是**一次具体的方向改变动作**（含时机判断、代价评估）；本 skill 是**整体的运作姿态**——把修正变成常态而不是一次大手术。
- 与 `mm-experimental-mindset` 的区别: 实验思维提供**获取数据的方法**（如何设计实验、如何判定结果）；本 skill 提供**对初始方向的姿态**——不必瞄准，但要能锁定。实验是导弹的导引头。
- 与 `mm-product` 的区别: 产品/市场匹配是**要到达的终点状态**；本 skill 是**到达它的方式**——通过持续修正而非一次押中，且强调这种方式本身就是在规避风险。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判断用户是卡在"没发射"还是"乱转向"**
   - 完成标准: 明确当前状态。若卡在没发射 → 进步骤 2；若已在跑但反复改 → 进步骤 4。
2. **把"再想想"换算成信息收益**
   - 完成标准: 问出并回答"再等一周能产生什么新数据"。若答案是"没有新数据，只是再讨论一遍"——明确指出这是拖延，应尽快发射最小版本。
   - 判停条件: 若等待确实能等到关键外部信息（法规、大客户决策、技术发布），则等待成立，给出明确的等待截止日。
3. **定义最小发射物与热源**
   - 完成标准: 明确这一轮发射的最小单元是什么（功能范围/客群/渠道），以及要采集的 2-3 个关键数据是什么。没有热源的发射不是导弹，是烟花。
4. **为"更大更好的目标"设定判据**
   - 完成标准: 写出可比较的量化标准（市场规模、留存、付费意愿、增长斜率），能明确回答"这个新目标是否比现在的更大更好"，而不是凭感觉。
5. **设定转向的代价上限与检查节奏**
   - 完成标准: 给出单次转向允许消耗的资源上限，以及固定的数据复盘节奏——既避免"已经投了只能继续"的承诺升级，也避免"每周一个新方向"的随机漂移。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 决策不可逆或转向代价极高（重资产投入、一次性合约、安全相关）——此时必须先在发射架上瞄准，本 skill 的"瞄准不重要"不适用。
- 已处于执行期、路径明确——持续修正会变成无谓扰动。
- 需要先建立行业认知的全新领域——先画迷宫，盲目发射只是快速撞墙。
- 用户缺乏收集数据的能力或渠道——没有热源的导弹无法制导，此时应先解决数据获取问题。

### 容易误用的地方

- （推导, 非书中明示）把"瞄准不重要"当成"不需要任何方向"。书里说的是初始瞄准的**精度**不重要，不是不需要目标——没有目标就无法判断什么算"更大更好"。
- （推导, 非书中明示）无节制转向。修正必须朝"更大更好的目标"移动，且要有第 4 步的判据与第 5 步的代价上限；否则只是在随机漂移，还美其名曰灵活。
- （推导, 非书中明示）把数据收集变成新的拖延。"持续收集数据"是发射之后的行为，不是发射之前的替代方案。
- （推导, 非书中明示）忽略"在拥挤市场中锁定目标"这后半句。修正的终点是锁定，不是永远在路上。
