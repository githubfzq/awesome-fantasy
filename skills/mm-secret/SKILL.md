# 秘密（secret）

## R — 原文 (Reading)

> 伟大的企业建立在公开但尚未被察觉的秘密之上，这些秘密关乎世界的运作方式。
>
> — 《思维模型》, 第9章 > 秘密武器

---

## I — 方法论骨架 (Interpretation)

这里说的"秘密"不是商业机密——不需要保密。恰恰相反，它是**公开的**：任何人查都能查到，但它没有被普遍察觉，所以绝大多数人没意识到它重要。

为什么这能撑起一家伟大企业？因为竞争的本质是把利润压到零。如果一个人人都知道的真相，就会有无数人去抢，回报被瓜分干净。而一个"大家路过一万次却没注意到"的真相，在它被注意到之前，是没人跟你抢的。所以作者把它叫做**秘密武器**：它是超额回报的来源，和顺势-逆势矩阵里的第四格是同一件事的两种说法。

书里把秘密分成三种形态，这个分类很有用：

1. **别人没想到的点子**——纯粹的认知盲区。
2. **别人觉得风险太大但其实可行的做法**——不是看不见，是看见了却不敢做。这类最常被误判为"不可能"。
3. **把别人的"优秀"点子变成"卓越"的路径**——idea 不新鲜，但你知道怎么把它做到别人做不到的完成度。

那秘密去哪儿找？作者给的方向是：**去各个领域的"自制计算机俱乐部"式前沿社群里，成为知情者**。意思是，真正的边缘信息不在新闻里，而在那些正在动手的人聚集的地方。

还有一个更普适的生成机制：**跨领域迁移**。一个领域里的常识，对另一个领域的人来说往往就是秘密。你不需要比别人聪明，你只需要带着 A 领域的常识走进 B 领域。

最后一个必须同时知道的约束：**光有秘密不够，时机必须恰当**。作者的证据是 1993 年的苹果牛顿平板——方向是对的，但早了十几年，白白浪费了时间和金钱。

关键判据一句话：**这个判断是公开的还是只有我知道？它是真的没被察觉，还是只是我不常提起？**

## A1 — 书中的应用 (Past Application)

### 案例: 爱彼迎、优步与来福车看到的闲置资源
- **问题**: 一边是大量闲置的资产，另一边是大量没被满足的需求，但两边从来没被连起来。
- **方法论的使用**: 爱彼迎看到的是**闲置房间可以被放心地出租给陌生人**——房间的供给一直存在，"能不能放心"这件事随着评价体系和支付体系的成熟已经可以解决，但没人把它当成一门生意。优步和来福车看到的是**闲置车辆可以被实时调度**——同样，车在那儿，司机在那儿，缺的只是把它组织起来的方式。这些都不是发明出来的新技术，而是被长期忽视的**闲置生产力**。
- **结论**: 这些公司建立在一个"公开但尚未被察觉"的真相之上——闲置资源可以被安全地组织起来。作者用它们说明伟大企业的地基长什么样：不是某个专利，而是对一个被集体忽视的事实的率先察觉。这类秘密一旦被说出来，所有人都恍然大悟，这正是它的特征。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **用户有一个强烈直觉但不确定价值**: "我觉得这里有问题/有机会，但好像没人讨论"——需要判断它是不是秘密，还是只是自己信息不足产生的错觉。
2. **寻找创业方向或新业务切入点**: 用户不知道从哪儿找机会，需要知道秘密的三种形态和它的产地（前沿社群、跨领域迁移）。
3. **评估一个创意是不是"太明显了"**: 用户担心自己的想法没有壁垒，需要区分"点子被所有人想到"和"点子公开可见但未被察觉"。
4. **把别的领域的做法搬过来用**: 用户说"我在 X 行业见过这么做，能不能用到 Y 行业"，这正是书里点出的秘密生成机制，值得认真展开而不是当作随口一提。

### 语言信号 (用户的话里出现这些就应激活)

- "我发现了一个好像没人注意到的现象"
- "这个大家都忽略了，但我觉得很值钱"
- "为什么从来没有人这么做？"
- "这不就是明摆着的事吗，怎么没人做"
- "我在上一个行业里这套玩法很普遍，这边居然没人用"
- "大家都说这事做不成，但我算下来其实可行"
- "There's something nobody has noticed." / "It's hiding in plain sight." / "Why hasn't anyone done this?"

### 与相邻 skill 的区分

- 与 `mm-why-now` 的区别: 秘密回答"这件事**为什么成立**（有什么被忽视的真相）"，为什么是现在回答"**为什么是此刻**（时机成熟了吗）"。书里明确指出光有秘密不够、过早会浪费资源（苹果牛顿），所以这两个必须配套使用：先用秘密验证地基，再用为什么是现在验证时机。
- 与 `mm-asymmetric-information` 的区别: 信息不对称是你**掌握别人拿不到的信息**（通常靠位置或研究获得，如内幕、专有数据）；秘密是**所有人都可获得但没被察觉的真相**。前者靠封锁，后者靠先觉，二者的持续性来源完全不同。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把用户的直觉写成一句关于世界如何运作的陈述**
   - 完成标准: 得到一句形如"事实上 X 是真的，因此 Y 可以做"的话。若用户只能说出"我想做个 App"，说明还没有秘密，只有愿望，需明确告知。
   - 判停条件: 若陈述依赖"只有我能做到"（而非"这是真的"），跳到第 4 步——那可能是能力而非秘密。
2. **验证它是公开的还是私有的**
   - 完成标准: 检查这条陈述能否通过公开信息得到支持（公开数据、可复现实验、行业公开报道）。若是,标记为候选秘密；若依赖只有用户有的私有数据，转由信息不对称处理。
3. **测量它到底有没有被察觉**
   - 完成标准: 给出"已被察觉"的证据：是否已有人在实践、有没有相关社群讨论、搜索热度、从业者是否随口就能说出这句话。若发现已经有人在规模化地做，判定为**不是秘密**，明确告诉用户。
4. **归入三种形态之一**
   - 完成标准: 明确标注属于"别人没想到 / 别人觉得风险太大但其实可行 / 把别人的优秀点子做到卓越"中的哪一种。不同形态决定下一步该做的事不同——第二种需要重新核算风险，第三种需要问清楚"我凭什么做得比别人好得多"。
5. **追问去哪里找更多、以及时机是否成熟**
   - 完成标准: 指出 1-2 个具体的"前沿社群"（该领域正在动手的人聚集的地方）供用户去成为知情者；然后交接给 `mm-why-now` 检查时机——苹果牛顿的教训是不能跳过这一步。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **谈保密协议、技术机密、防泄密**: 这里的"秘密"是认知概念，不是保密管理，两者几乎相反。
- **点子已经满街都知道**: 此时应该讨论的是执行力和产品/市场匹配，而不是继续寻找秘密。
- **用户需要的是渐进改良的日常运营建议**: 秘密是关于战略地基的，套在小优化上会让人忽略眼前的确定性收益。

### 书中警告的失败模式 / 容易误用的地方

- **书中明示**: **仅有秘密不够，时机必须恰当**。作者用 1993 年的苹果牛顿平板说明，过早会浪费时间和金钱——它比 iPad 早了十几年，最终停产。必须用 `mm-why-now` 配套检查。
- （推导, 非书中明示）**把"我很少听见"当成"没人知道"**: 这是最常见误用。个人的信息圈很小，在一个圈子里没人提，不等于在动手的人群里没人知道。第 3 步就是为拦住这个误用设计的。
- （推导, 非书中明示）**把个人独有能力误判为秘密**: 秘密是"世界运作方式的真相"，可以被别人承认；如果你的优势只是"我比别人能熬夜"，那不是秘密，也撑不起壁垒。
- （推导, 非书中明示）**害怕说出来**: 秘密的价值在于它尚未被察觉，说出来会启动竞争倒计时。但完全不说又会失去验证的机会。建议在小范围、可信任的前沿社群里验证，而不是公开宣讲。

### 容易混淆的邻近模型

- **同步发明（simultaneous-invention）**: 当条件成熟时往往不止一个人在围绕同一个秘密行动。如果你真的找到了一个秘密，很可能别人也快发现了——这两件事是同一个现象的两面。
- **信息不对称（asymmetric-information）**: 信息不对称是你握着别人拿不到的信息；秘密是公开的但没人察觉。前者靠封锁维持，后者靠先觉抢时间，因此前者的护城河通常比后者可靠。
