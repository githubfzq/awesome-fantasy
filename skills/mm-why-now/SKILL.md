# 为什么是现在（why now）

## R — 原文 (Reading)

> 为了更有条理地解决“时机”的问题，不妨问问自己“为什么是现在”（why now）。这个简单而强大的思维模型来自风险投资公司红杉资本
>
> — 《思维模型》, 第9章 > 秘密武器

---

## I — 方法论骨架 (Interpretation)

"先给它加个 AI"和"现在给它加 AI"，中间隔着几年，而这个差别决定了生死。

为什么是现在，问的是一件很具体的事：**凭什么是这一刻，而不是更早？** 一个创意如果三年前也能做，那它大概率不是你的机会——因为早该有人做了；而且你做的时候，别人也在做。反过来，如果它必须依赖某个刚刚发生的变化才成立，那么这个变化本身就是你的时间窗口：它在昨天还不存在，今天刚刚出现，你正站在窗口打开的一瞬间。

书里说，好答案通常基于两类东西：**最新的科技进步**，或者**底层技术采纳程度的变化**所揭开的秘密。优步就是典型例子：叫车这件事的想法不新，但只有在智能手机普及——人人随身带着一个联网、知道自己在哪儿、能完成支付的设备——之后，实时调度闲置车辆才真正成立。**不是想法变好了，是基础设施终于铺好了。**

这个模型还解释了一个让人困惑的现象：**同步发明**。历史上经常出现好几个人几乎同时搞出同一个东西。为什么会这样？因为当必需的若干条件同时成熟（而此前一直缺一两个），所有走在边上的人会同时看到那个秘密。所以同步发明的存在本身就是证据——它反过来说明时机确实由客观条件决定，而不是由某个人的天才决定。

书里还提供了一个反向用法：**用逆向思维反过来问"现在该做什么"**，从你周围正在发生的变化里找机会——先看条件，再看能长出什么。

判据一句话：**如果这个项目去年就该成功、用不着什么新变化，那么你的答案很可能不成立。**

## A1 — 书中的应用 (Past Application)

### 案例: 苹果牛顿与 iPad 的时机落差
- **问题**: 同一个产品构想——手持的平板计算设备——为什么一次彻底失败，一次大获成功？构想本身没有变，变的是它落地的年份。
- **方法论的使用**: 苹果牛顿在 1993 年推出，1998 年停产。用"为什么是现在"去检验：1993 年的互联网基本还不存在，联网应用、内容生态、移动数据这些配套条件全都没到位——设备能做的远远少于它承诺的。而十多年后推出的 iPad，创下了苹果产品中最高的初始采纳率，因为此时互联网已经成熟，围绕它的一切基础设施都已铺好：应用商店、内容、无线连接、用户对触屏的预期。**同一个秘密，在不同的基础设施成熟度下，结果截然相反。**
- **结论**: 作者用它给这个模型定下最硬的教训——**仅有秘密不够，时机必须恰当**。过早会浪费时间和金钱（这是在 `mm-secret` 里明确给过的警告），过晚则会撞上同步发明者。所以每个创意都必须单独回答"为什么是现在"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **评估一个创业/产品构想的可行性**: 用户兴奋地讲完 idea，需要立刻追问"凭什么是现在"，这是筛掉空想最快的一问。
2. **考虑进入一个已经有人在做的新兴领域**: 用户担心自己太晚，需要判断窗口是已经关闭、还是刚打开。
3. **重推一个过去失败过的项目**: 用户想复活老项目，需要检查当时缺失的条件是否已经补齐——牛顿/iPad 式的复盘。
4. **寻找下一步该做什么**: 用户不知道做什么，可以用模型的逆用法——先看身边发生了哪些变化，再倒推机会。

### 语言信号 (用户的话里出现这些就应激活)

- "我想做 X，是不是太早了？"
- "这个领域已经有人做了，我是不是晚了？"
- "为什么以前没人做成，是因为当时条件不够吗？"
- "我们三年前试过失败了，现在条件变了没？"
- "凭什么是现在？"
- "最近 AI/某个技术出来了，是不是有新机会？"
- "Why now?" / "Is it too early for this?" / "Have we missed the window?" / "What changed that makes this possible?"

### 与相邻 skill 的区分

- 与 `mm-secret` 的区别: 秘密回答"这里有什么被忽视的真相"，为什么是现在回答"为什么这个真相此刻才能兑现"。书中把两者明确绑在一起——牛顿的例子就是"秘密早就对了、时机错了"。必须连问两个问题，只问一个会出事。
- 与 `mm-tipping-point` 的区别: 临界点问的是"某个变化多久会失控式扩散"，重点在于过程中的扩散动力学；为什么是现在问的是"此刻有没有某个新条件出现，使某件事第一次成为可能"，重点在于把 "the trigger event" 定位到过去两年里。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先问反向问题：去年为什么做不成？**
   - 完成标准: 用户说出 1-3 条具体的、在 12-24 个月前还不存在的条件。若答不出来，判定"没有为什么是现在"，直接告知：这很可能是个已经存在的机会而非新窗口，需要重新审视，并停止后续步骤。
2. **把促成条件逐条列出来并核对时间**
   - 完成标准: 得到一个清单，每条标明"它是什么时候发生变化的"。优先检查四类：技术突破、底层基础设施的采纳率、法规政策变化、用户行为转变。至少要有 1 条发生在最近 12-24 个月内且可信。
3. **给每条找客观数据锚点**
   - 完成标准: 每条促成条件都附上一个可查证的指标（渗透率、价格下降曲线、出货量、法规生效日期、活跃用户数）。用不上数字的条目标记为"待验证"，不能当成立的前提。
   - 判停条件: 若最有分量的一条只有传闻或媒体热度支持，判定为炒作驱动，见"边界"部分中关于过度宣传的警告。
4. **检查同步发明风险**
   - 完成标准: 明确回答"这些条件是否同样对别人可见"。若是，则几乎必然存在并行者，需要给出应对——拼执行速度、拼细分定位、或转向一个别人看不上的切入角。
5. **反向用法：如果不确定做什么**
   - 完成标准: 列出用户所在的领域最近正在发生的 3-5 个变化，对每个回答"因为这个变化，什么事情第一次变得可能"。从这里倒推候选方向。
6. **给出"太早 / 刚好 / 太晚"判定与下一步**
   - 完成标准: 基于以上证据给一个明确的时机判定：太早 → 指出该等哪个指标到位，并设复检时间；刚好 → 指出窗口大概有多长；太晚 → 给出换切入口或放弃的建议。注意书中提醒：不要因为"接纳程度一开始通常不高"就误判创意本身没价值。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **问题本质是执行力而不是时机**: 用户明明缺的是客户开发或团队能力，用时机分析会转移注意力，把执行问题包装成"我生不逢时"。
- **成熟稳定的行业中的常规经营决策**: 没有新的促成条件正在出现，模型无从落脚。
- **个人生活里的时机选择**（什么时候跳槽、什么时候表白）: 模型依赖技术/基础设施采纳这类客观条件，套到主观时机会产生伪精确。

### 书中警告的失败模式 / 容易误用的地方

- **书中明示**: **过早会浪费时间和金钱**。牛顿平板的例子是这句话的实证：想法正确但早了十几年，最终 1998 年停产。
- **书中明示**: 作者指出**对过度宣传提出质疑是合理的**——媒体热度不等于时机成熟。
- **书中明示**: 斯滕伯格提醒"**至少在一开始，创意的接纳程度通常都不高**"。这条很重要：不能因为初期没人接受就判定时机不到。初期冷遇与"条件未成熟"是两回事，前者甚至可能是新事物的常态。
- （推导, 非书中明示）**把自家产品的发布时间当成"为什么是现在"**: "我们下周上线"不是时机，那是日程。时机必须是发生在你之外的客观变化。
- （推导, 非书中明示）**窗口刚开时过度扩张，会被融资周期反噬**: 在热度最高时按峰值预期扩团队、囤库存，一旦热度回落而收入未跟上，会立刻陷入现金危机。时机判断正确不等于扩张节奏可以激进。

### 容易混淆的邻近模型

- **同步发明（simultaneous-invention）**: 它既是"为什么是现在"的解释证据（条件成熟导致多人同时想到），也是使用它时必须评估的风险（你不会是唯一一个）。
- **技术采纳生命周期（technology-adoption-life-cycle）**: 它刻画一项技术如何被不同人群依次接纳的过程，可用来为"基础设施到位没有"提供量化依据；为什么是现在是拿这些证据去给某个具体创意下时机结论。
