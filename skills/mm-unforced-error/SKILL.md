# 主动失误（unforced error）

## R — 原文 (Reading)

> 在网球比赛中，"主动失误"（unforced error）是指一名球员因为自己判断出错或执行力差而失误，而不是因为对方球员打出了好球。
>
> — 《思维模型》, 第1章 少犯错 > 章首

---

## I — 方法论骨架 (Interpretation)

网球记分时会把丢分分成两类：对手打出了一记你接不到的好球（forced error，受迫性失误），和你自己把球打下网、打出界（unforced error，主动失误）。两类丢分在记分牌上完全一样，但改进手段完全不同：前者只能靠提升绝对实力，后者靠注意力和基本功就能大幅削减。

把这套分类搬到决策上，就是把失败拆成"外部环境真的强/运气真的差"和"我们本可以避免"两部分。书里关心的几乎全是后者——它认为大多数人的大部分损失，来自那些**事前稍加注意就能避免**的错：决策时没有考虑自己所有的选项、用了错误的单位（把大汤匙当小茶匙）、留给别人糟糕的第一印象、提交前没检查清单。

这个模型的价值在于它把"我失败了"这个笼统的自我否定，切成了一个可操作的比例问题：**这次失败里，有多大一块是我自己送出去的？** 那一块是可控的，因此削减它不需要更强的能力，只需要流程和注意力。

关键判据是**事前可避免性**（不是事后严重程度）：把时间倒回决策那一刻，在当时的信息条件下，一个稍微细心一点的人会不会犯这个错？会，就是主动失误。这个判据同时也是它的护栏——不确定性下的最优决策事后仍可能出错，那不是失误，那是概率的正常实现。

---

## A1 — 书中的应用 (Past Application)

### 案例: 三类典型主动失误
- **问题**: 作者要说明"主动失误"在网球之外长什么样，以及它离日常生活有多近。
- **方法论的使用**: 把三个看起来毫不相干的场景并列，指出它们的共同结构是"事前注意一下就能避免"：烘焙时用大汤匙代替小茶匙（单位错误）、约会时留给对方糟糕的第一印象（未注意自身呈现）、做决策时没有考虑自己所有的选项（选项集不完整）。
- **结论**: 主动失误不是能力问题，而是注意力与流程问题。因此它可以靠清单、靠单位复核、靠强制枚举选项来系统性地削减——这正是全书"少犯错"这一章的立足点：不必变得更聪明，只要少送分。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **失败复盘，需要划分责任性质**：项目没中标、产品上线数据差、面试没过、谈判崩了。用户第一反应是"对手太强/运气不好"或"我太菜了"，需要一个客观标准把两者分开。
2. **决策定稿前的最后一扫**：合同要签了、方案要发了、代码要上线了、邮件要群发了。需要一份"低级错误检查"而不是再来一轮战略分析。
3. **重复性失误反复出现**：同一个类型的错（数字算错、单位搞混、忘了回邮件、开会迟到）一直在发生，用户需要意识到这不是运气，是系统里缺一道防线。
4. **把"我果然不行"的自我否定拆开**：用户因为一次失败全盘否定自己能力，需要看到其中有多少是流程可修的部分。

### 语言信号 (用户的话里出现这些就应激活)

- "这次是我们自己搞砸的，还是对手确实太强？"
- "这种低级错误我们怎么会犯"
- "当时要是注意一下就好了"
- "这明明是可以避免的啊"
- "他又来了，同样的错犯了第三次"
- "帮我检查一下这份方案/合同/邮件有没有明显问题"
- "Was this avoidable?" / "unforced error" / "we shot ourselves in the foot"

### 与相邻 skill 的区分

- 与 `mm-inversion` 的区别: 逆向思维是**事前**主动构造"怎样一定会失败"的清单来预防；主动失误是**事后**对已发生的失败做性质归因。一个生成防线，一个判定责任。
- 与 `mm-root-cause` 的区别: 根本原因要挖到**深层结构性原因**（组织失效、缺乏制衡、能力缺口）；主动失误只判定"这一分是不是自己送的"，是归因的第一层，往往作为挖根本原因的起点。
- 与 `mm-hindsight-bias` 的区别: 后见之明偏差是**误用**主动失误时最常见的病——知道结果之后觉得"当时明明看得出来"。判主动失误时必须靠后见之明偏差来校正自己。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把这次失败拆成一张"丢分清单"**
   - 完成标准: 列出具体是哪些环节没有达成预期（不是笼统的"没做好"），每个环节一条。
2. **对每一条判定性质：受迫 / 主动 / 无法判定**
   - 完成标准: 用事前可避免性判据——"回到决策那一刻，在当时的信息下，一个稍微细心的人会不会也这么做？"会 = 受迫；不会 = 主动；信息不足 = 无法判定，如实标注而非归类。
   - 判停条件: 若某条明显带"我早就知道会这样"的味道，先停下来用后见之明偏差校正，再判。
3. **对判定为主动失误的条目，定位它属于哪一类缺口**
   - 完成标准: 归入四类之一——(a) 选项集不完整（没考虑全部选项）；(b) 单位/量纲/数字错误；(c) 注意力与呈现（第一印象、措辞、格式）；(d) 流程缺失（没有清单、没有复核人）。写出归类理由。
4. **给每类缺口设计一道具体防线**
   - 完成标准: 防线是可执行的机制（强制枚举至少三个备选、数字双人复核、发出前 10 分钟冷却检查、关键动作设第二人签字），不是"下次注意点"。
   - 判停条件: 若防线的成本高于它预防的损失，改为明确接受该风险并告知用户。
5. **输出"可削减比例"**
   - 完成标准: 明确告诉用户：这次失败中约有多大比重是主动失误（因而可控可削减），多大比重是外部强度或运气（因而只能靠提升实力或增加样本）。禁止得出"全是自己的错"或"全是运气"这种无信息量的结论。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **不确定性下的决策结果不好时**：书中明示——依据当时信息做出的最佳决策，事后仍可能出错，那不是主动失误。此模型只覆盖"本可避免"的部分。投资亏了、创业失败了、赌注没押中，都可能只是概率的正常实现。
- **信息本身不可得时**：如果当时根本拿不到那个信息（对方隐瞒、黑天鹅、系统未暴露的缺陷），不能事后追认为失误。
- **需要追责到人的纪律场景**：本模型的目的是改进流程，不是分配惩罚。用来算账会让人开始隐瞒失误，反而摧毁它赖以工作的数据来源。

### 书中警告的失败模式 / 容易误用的地方

- **不要把受迫性失误硬算成主动失误**（书中明示）：不确定性下的最优决策出错不是失误。误判的代价是让组织变得保守，或让人为不可控的结果背锅。
- （推导, 非书中明示）反过来也要小心：把主动失误解释成"运气不好/对手太强"是最常见的自我保护，会让人重复送分。判定时要求给出"当时信息下细心的做法是什么"作为对照。
- （推导, 非书中明示）"第一印象""单位错误"这类清单会随领域变化，不要拿书中的三条当通用清单，应按第 3 步在当前领域重新枚举。

### 容易混淆的邻近模型

- **根本原因（root cause）**: 主动失误是"这一分是不是自己送的"（性质判定），根本原因是"为什么会反复送分"（结构归因）。主动失误通常是挖根本原因的输入。
- **沉没成本谬误（sunk-cost-fallacy）**: 关注已投入的成本，与本模型无关；但复盘时容易一起出现，注意别把"已经投了这么多"当成继续的理由。
