# 深度工作（deep work）

## R — 原文 (Reading)

> 作家卡尔·纽波特（Cal Newport）将这种引出突破性解决方案的思维方式称为“深度工作”（deep work）。他主张人们利用一段不会被外界干扰的时间来思考最重要的问题，以便取得进展。
>
> — 《思维模型》, 第3章 > 你能做好任意一件事

---

## I — 方法论骨架 (Interpretation)

最好的表现几乎都来自创造性的解决方案，而创造性方案通常不是灵光一现，而是长时间专心盯住一个问题熬出来的。深度工作就是给这种"长时间专心"创造条件：一段预先划出来、不会被打断的时间，专门用来思考最重要的那个问题。

它的前提是多任务处理的反面——一次只做一件事。但作者补了一个容易被忽略的条件：**一次只做一件事还不够，你脑海里的首要念头必须是重要的念头**。如果整块时间被拿来想琐事，深度工作只是把浪费变得更彻底。

为什么需要刻意安排？因为不深度投入时，人会本能地转向自己会解的问题。作者引用彼得·蒂尔式的观察：手上没有真正投入的 A+ 级问题时，你会跑去解决一堆 B+ 级问题，把那个最难的、真正重要的问题无限期搁置。

判据很简单：这件事是否需要"想出来"而不是"做出来"。需要想出来的，就得给它整块时间。

---

## A1 — 书中的应用 (Past Application)

### 案例: 彼得·蒂尔的"每个人只能做一件事"

- **问题**: 组织里的人同时挂着许多任务，看上去很忙，但真正重要的难题没人深入，大家都在处理自己擅长处理的那类问题。
- **方法论的使用**: 贝宝 CEO 彼得·蒂尔坚持一条规则——每个人只能做一件事。开会时，除了分配给你的那件事，其他一概不谈。这是把"一次只做一件事"制度化，把人的注意力强行锁死在单一重要问题上。
- **结论**: 深度工作不只靠个人意志，也可以靠组织规则来保障；当干扰被结构性移除，人才有机会在真正重要的问题上取得突破。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户要写一个方案、设计一个架构、想清楚一个战略问题，但发现自己一直被会议和消息切碎，迟迟没有进展。
2. 用户想建立长期习惯（每周固定时间做某件重要但不紧急的事），需要把时间先"占住"再说的具体做法。
3. 用户承认自己"一直在忙，但忙的都是小事"，怀疑自己在回避那个最重要的问题。

### 语言信号 (用户的话里出现这些就应激活)

- "我根本找不到一整段不被打扰的时间"
- "这个方案我想了好几天，但一直沉不下去"
- "怎么才能进入那种专注的状态"
- "重要的事一直被往后排，天天在救火"
- "I need a big block of time to think this through"

### 与相邻 skill 的区分

- 与 `mm-multitasking` 的区别: 多任务处理说明"并行为什么不行"，深度工作给出正面替代方案——用整块时间单任务推进，两者是一个诊断一个处方。
- 与 `mm-eisenhower-decision-matrix` 的区别: 矩阵把"重要不紧急"的事挑出来，深度工作解决挑出来之后怎么真正推进它。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认那件"最重要的问题"到底是什么，并写成一个具体待解问题**
   - 完成标准: 输出一句可验证的问句（如"如何在 Q4 前把注册转化率从 2% 提到 4%"），而不是一个模糊主题。
   - 判停条件: 若用户说不出哪个问题最重要，先用优先级模型收敛，本 skill 暂不推进。
2. **检查它的确需要"想出来"，值得用整块时间**
   - 完成标准: 明确回答"这是创造性/突破性问题还是例行性执行"，例行性执行应转流程优化而非深度工作。
3. **在日程上划出不被干扰的整块时间，并把它设为默认**
   - 完成标准: 给出具体的时段长度、频率、以及它被写进日程的方式（重复时段），而不是"建议找时间专注"。
4. **列出并切断干扰源**
   - 完成标准: 至少给出 3 条具体措施（通知、消息、会议、协作方式各覆盖一项），并说明由谁/什么机制来执行。
5. **设定这一段的产出物与自检问题**
   - 完成标准: 明确"这段结束时应该有什么"（一版草稿/一个决策/一组假设），并附一个自检：这段时间里我脑海中的首要念头，是不是那个最重要的问题。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 工作性质本身就是高频协作与响应（值班支持、销售跟进、一线管理），强行要求大块独处时间不现实，应转向日程结构（匠人日程/管理者日程）而非本模型。
- 用户只是要"更专注一点"的小技巧，而问题其实出在任务太多，此时应先做减法。

### 书中警告的失败模式 / 容易误用的地方

- 书中明示的前提：一次只做一件事时，你脑海中的首要念头必须是重要的念头。把深度工作时间用来处理琐事，等于什么都没做。
- （推导, 非书中明示）把"深度工作"当成逃避协作的挡箭牌，会在团队中制造信息孤岛——作者主张的是有意识地安排，不是永久性地关闭通道。

### 容易混淆的邻近模型

- 与心流（flow）混淆：心流描述专注时的主观体验状态，深度工作是一套可安排的、有产出物的工作方式。
- 与刻意练习（deliberate-practice）混淆：刻意练习针对技能提升的重复训练，深度工作针对一次性难题的突破。
