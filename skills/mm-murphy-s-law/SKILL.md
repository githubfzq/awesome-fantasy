# 墨菲定律（Murphy's law）

## R — 原文 (Reading)

> 总的来说，就是要留意墨菲定律（Murphy's law）——凡可能出错之事必出错。这个定律得名于航空工程师爱德华·墨菲（Edward Murphy），他是在测量设备未能发挥预期效果后发表这一评论的。这句话提醒你有备无患，建议你未雨绸缪，提前为出错的情况准备预案。
>
> — 《思维模型》, 第2章 > 章末小结（章名即此定律）

---

## I — 方法论骨架 (Interpretation)

这句话常被当成一句俏皮的宿命论，但书里给它的定位是**风险预备原则**，不是悲观哲学。它的实际含义是：

> 只要一个失败路径在物理上或逻辑上存在，且被足够多次地触发，它就迟早会被触发。

这不是玄学，是概率的必然：单次发生概率为 p 的事件，在 n 次机会中至少发生一次的概率是 1-(1-p)ⁿ，随着 n 增大趋近于 1。所以问题从来不是"会不会出错"，而是**"出错之后我有没有兜底"**。

由此产生一个明确的注意力转移：从**预测成功**转向**设计容错**。预测成功是在赌一个特定的未来；设计容错是承认未来不确定，因此让每一种失败都留有余地。

书中把这一章其余所有模型的定位讲得很清楚：**它们本质上都是在具体情境下回答"到底哪里会出错"**。也就是说，墨菲定律是那一整章的总纲——给出态度与方向，而具体位置要靠其他模型（连锁故障、公地悲剧、外部性……）去定位。

关键判据（一问）：**如果这件事失败了，我有预案吗？** 答不上来，就是墨菲定律该起作用的地方。

边界同样重要（书中明示）：**"这无法解释所有可能的意外结果"**——它是提醒性口号，不能替代结构化归因。

## A1 — 书中的应用 (Past Application)

### 案例: 航空工程师爱德华·墨菲
- **问题**: 作者要说明这条定律的来源，以及它本来的工程师含义。
- **方法论的使用**: 该定律得名于航空工程师爱德华·墨菲，他在测量设备未能发挥预期效果后发表这一评论。作者把它放在第 2 章的章末小结，作为整章的收束性原则。
- **结论**: 它的用途不是解释事故，而是**提前为出错的情况准备预案**。书中用它把整章的各个模型串成一个统一的问题意识——"到底哪里会出错"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **规划一件有失败可能的事**: 上线、发布、活动、迁移、出差、签约——需要提前问一遍"哪里会出错"。
2. **方案里没有任何容错设计**: 用户描述的计划是一条直线，从头到尾都假设一切顺利。
3. **需要设计兜底与回滚**: 数据库迁移、支付流程、关键依赖第三方服务。
4. **被问到"万一……怎么办"**: 用户自己已经隐约感到不安，需要一个系统的兜底检查。
5. **复盘时找不到"为什么会这样"**: 此时应提醒：墨菲定律只负责让你提前准备，不负责解释——解释要靠结构化归因。

### 语言信号 (用户的话里出现这些就应激活)

- "万一失败了怎么办"
- "有没有兜底方案 / 备份 / 回滚"
- "这个计划是不是太顺利了，感觉不真实"
- "要不要提前准备一下"
- "反正可能出错的都会出错"
- "我们从来没演练过故障恢复"
- "Anything that can go wrong will go wrong." / "What's our fallback?" / "Do we have a rollback plan?"

### 与相邻 skill 的区分

- 与 `mm-inversion` 的区别: 逆向思维是**生成策略的操作**——反转问题、穷举失败路径、逐条排除，产出新选项；墨菲定律只给出**态度与方向**——凡可能出错必出错，要有预案。逆向思维的具体得多，墨菲定律是它背后的动机之一。
- 与 `mm-scenario-analysis` 的区别: 情景分析是**系统地枚举多种可能的未来**（含好中坏）并为每种做准备，是一套方法；墨菲定律是它的一句总纲。情景分析包含"出错"以外的情景，墨菲定律只关注出错。
- 与 `mm-unknown-unknowns` 的区别: 未知的未知数处理的是"我连自己不知道什么都不知道"的那类风险，对策是提高探索与弹性；墨菲定律处理的是"我知道可能出错、但没准备"的那一类，对策是预案与冗余。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认当前是在规划阶段（而非事故解释阶段）**
   - 完成标准: 确认用户是要规划/准备，而不是在追问已发生事故的原因。
   - 判停条件: 若是在解释已发生的事故，明确提醒——书中指出墨菲定律"无法解释所有可能的意外结果"，应转向五问法/根本原因做结构化归因。
2. **枚举这条计划上的失败路径**
   - 完成标准: 按环节列出 5-10 条"哪里会出错"，每条写成"如果 X 发生，那么会怎样"。覆盖：关键人物缺席、依赖方失败、数据/环境问题、时限被压缩、外部条件变化。
   - 判停条件: 若用户对该领域完全陌生、列不出具体失败路径，先做信息收集，不要凭空想象。
3. **对每条问"出错后我有兜底吗"**
   - 完成标准: 每条给出三种处理之一：**预防**（降低发生概率）、**检测**（发生后能立刻知道）、**兜底**（发生后有替代路径/可回滚）。三者都没有的，标记为"裸奔"。
4. **优先处理"裸奔"项与高损失项**
   - 完成标准: 按"发生概率 × 损失大小"排序，先给裸奔项加上至少一层（优先加检测与兜底，因为预防通常最贵）。
   - 判停条件: 若某项的兜底成本高于其损失，明确写为"接受该风险"，并让用户知情——不要为所有风险都做预案。
5. **指出墨菲定律不覆盖的部分**
   - 完成标准: 明确告诉用户：这套枚举只覆盖**能想到的**失败路径，不覆盖未知的未知数；因此除预案外，还需要保留弹性（缓冲时间、可逆性、保留可能性）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **解释已发生的事故时**: 书中明确指出"这无法解释所有可能的意外结果"。拿它当解释（"因为可能出错的都会出错嘛"）等于放弃归因，应改用五问法/根本原因。
- **当宿命论使用**: "反正会出错，那就别规划了"——这完全违背本意。它的用途是**有备无患**，不是放弃。
- **低风险、可逆的日常事务**: 为每一件小事都准备兜底是过度设计，成本高于收益。

### 书中警告的失败模式 / 容易误用的地方

- **书中明确指出："这无法解释所有可能的意外结果"，它只是提醒性口号，不能替代本章其他模型做结构化归因**（`boundary` 字段原文）。这是最需要守住的一条：墨菲定律负责"提前怕"，不负责"事后懂"。
- （推导, 非书中明示）**列了一堆预案但没有检测**: 预案只有在你知道事故已经发生时才会被启用。缺了监控与告警，预案等于不存在。
- （推导, 非书中明示）**预案从未演练**: 没演练过的回滚和备份，在真正需要时常常失效。
- （推导, 非书中明示）**只做预防不做兜底**: 预防降低概率但不能归零；对高损失项，兜底（可逆性、冗余）往往比预防更值。

### 容易混淆的邻近模型

- **逆向思维（inversion）**: 是穷举失败路径的具体操作；墨菲定律是它的动机与口号。
- **预防原则（precautionary-principle）**: 是"在科学不确定时采取预防措施"的规范性原则，多用于公共政策；墨菲定律是工程/规划层面的经验提醒。
