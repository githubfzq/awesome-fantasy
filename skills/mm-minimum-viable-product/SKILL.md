# 最简可行产品（minimum viable product, MVP）

## R — 原文 (Reading)

> "最简可行产品"有助于你避免长时间独自一人闭门造车。职业社交网站领英（LinkedIn）的联合创始人雷德·霍夫曼（Reid Hoffman）就说过："如果你不为产品的第一个版本脸红，它就发布得太晚了。"
>
> — 《思维模型》, 第1章 少犯错 > 保持简洁，笨蛋！

---

## I — 方法论骨架 (Interpretation)

MVP 是只保留够用功能、体量最小、可供真实用户测试的产品版本。

它的作用不是省事，而是**把假设尽快推到真实反馈面前**，避免长时间闭门造车。霍夫曼那句"如果你不为产品的第一个版本脸红，它就发布得太晚了"其实是这个模型的判据：不脸红 = 你做了太多 = 你等了太久。

书里把它推广成"最简可行 X"——最简可行组织、最简可行沟通、最简可行策略、最简可行实验，甚至"最简可行解释"。所以 MVP 不只属于创业，任何需要拿反馈的东西都能用。

判据：**砍掉这个功能，还能不能拿到真实反馈？** 能，就该砍。

隐含前提是——必须有能给出真实反馈的对象。没有用户、没有读者、没有评审时，MVP 推不出去，模型失效，此时该先去找人而不是先做东西。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户准备做一个产品/功能/文档，在纠结第一版要做多少功能。
2. 用户一个人闷头做了很久，还没给任何人看过。
3. 用户要写方案、汇报、邮件，纠结篇幅和完备度。
4. 用户要搭组织、流程或活动，想先小规模试一下。
5. 用户说"拿出去丢人"，需要判断"脸红"是否恰恰是正确的信号。

### 语言信号

- "第一版到底要做多少功能？"
- "我还没准备好，不敢给别人看"
- "这个方案是不是该写得更完整一点再发"
- "先做个小范围试点吧"
- "What's the MVP here?"
- "ship something embarrassing / if you're not embarrassed, you shipped too late"

### 与相邻 skill 的区分

- 与 `mm-premature-optimization` 的区别: MVP 是正面的"先做什么"，过早优化是负面的"别先做什么"。两者共用同一判据（假设验证了吗），是一个硬币的两面，经常成对出现。
- 与 `mm-customer-development` 的区别: 客户开发在 MVP **之前**——先确认问题真实存在、找到愿意给反馈的人；MVP 是拿一个最小实物去验证解法。找不到人时应先做客户开发，而不是先做 MVP。
- 与 `mm-pivot` 的区别: 转型是 MVP 拿到反馈之后的一种可能结果；MVP 是转型的输入，不是输出。先有 MVP 的反馈，才谈得上要不要 pivot。

## E — 可执行步骤 (Execution)

1. **写出这次要验证的核心假设**
   - 完成标准: 一句可证伪的话（"用户会为 X 付 Y 元""读者看完能自己操作"），而不是"我想做个产品"。
2. **列出候选功能，逐项用判据过筛**
   - 完成标准: 每个功能都回答"砍掉它还能拿到真实反馈吗"，砍掉所有答案为"能"的。
3. **确认反馈对象**
   - 完成标准: 指定至少 3 个真实的反馈者（用户/读者/评审），并预约好时间。
   - 判停条件: 若找不到任何真实反馈对象，停止做 MVP，先转 `mm-customer-development` 去找人。
4. **事前定义"什么算验证通过"**
   - 完成标准: 写下量化门槛（如"5 人里 3 人主动要求续用"），避免事后用主观感受解释任何结果。
5. **发布并设复盘时间点**
   - 完成标准: 有明确的发布日期 + 复盘日期，且第一版确实让你"有点脸红"——若不脸红，回到步骤 2 再砍。

---

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 不可逆、错了会伤人的领域（医疗剂量、金融合规、安全关键系统）——不能拿"最小版本"去撞真实反馈。
- 没有真实反馈对象的场合（没人用的内部 demo、没人读的内部文档）——MVP 的前提不成立。
- 用户要的其实是"完整方案"而不是"验证假设"（如提交董事会的最终决策材料）——砍功能只会通不过。

### 容易误用的地方

- 书中未提局限；隐含前提是要有能拿到真实反馈的对象。
- （推导，非书中明示）把 MVP 当成"做得烂"的借口：最小 ≠ 粗糙到产生不了信号，它必须能给出可判定的反馈。
- （推导，非书中明示）MVP 之后不设验收门槛，任何结果都被解释成"验证成功"，等于没验证，反而给错误方向提供了正当性。
