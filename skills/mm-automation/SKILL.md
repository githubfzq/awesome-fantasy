# 自动化（automation）

## R — 原文 (Reading)

> 只有当通过更高效的处理方式能最终节省时间和金钱，取得的成果超出设置它的成本时，这样的自动化（Automation）才有意义。
>
> — 《思维模型》, 第3章 > 通往成功的捷径

---

## I — 方法论骨架 (Interpretation)

自动化是用更高效的处理方式替代人工重复劳动，从而持续节省时间与金钱。

它成立的条件被作者说得非常干脆：**节省下来的时间与金钱必须超过设置自动化的成本**，否则没有意义。这是一个纯算术判据，不是"先进不先进"的判断题。

第二个收益在规模上：规模上去之后，自动化是实现**规模经济**的好方法——因为自动化的边际成本趋近于零，而人工的边际成本是线性的。所以规模越大，同一套自动化的账越划算。

作者也给出了反面提醒：采用前应**分析各选项的利弊**，选错工具会浪费时间金钱甚至更糟；必要时可以请专业人士来分析和操作。书中用个人预算举例：从纸笔加计算器，到电子表格，再到能自动导入数据的软件，每月节省的时间逐级增加——但每一级迁移都有学习成本，账要算过来才值得升。

关键判据有两问：这件事会重复多少次？设置成本能否在合理周期内被省回来？

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户在手工重复做一件事（导数据、发报告、核对名单），想知道值不值得自动化。
2. 用户在多个自动化方案/工具之间选择，需要比较而非凭印象。
3. 用户在"自己做 vs. 买现成工具 vs. 雇人"之间权衡。
4. 用户已经自动化了却没感觉到省时——需要复盘是不是选错了工具或流程没跑通。

### 语言信号
- "这个每月都要做一遍，能不能自动跑？"
- "我在想要不要写个脚本／买个工具。"
- "自动化到底值不值？设置起来挺麻烦的。"
- "我们上了系统，但好像也没省多少时间。"
- "Is it worth automating this?"
- "Can we just run this automatically?"

### 与相邻 skill 的区分
- 与 `mm-brute-force` 的区别: 暴力是**一次性**用人力完成任务；自动化是**持续性**用系统替代人力。判据是会不会重复发生——只做一次看规模，会重复做才谈自动化。
- 与 `mm-economies-of-scale` 的区别: 规模经济描述"规模扩大导致单位成本下降"这一**结构性现象**；自动化是**实现它的手段之一**。规模经济还能靠集中采购、摊薄固定成本获得。

## E — 可执行步骤 (Execution)

1. **量化现状成本**
   - 统计：这件事多久做一次？每次花多少人力时间？换算成成本（时间 × 时薪）。
   - 完成标准: 得出"每年消耗 X 人时／Y 元"这个数字。
2. **量化设置成本**
   - 包括选型、开发/配置、调试、培训、以及后续维护成本（这块最常被漏算）。
   - 完成标准: 得出一次性投入 + 年维护成本两个数字。
3. **算回收周期并决策**
   - 比较两者，算出多久回本。
   - 完成标准: 给出明确结论：做 / 不做 / 换更轻的方案。若回收周期超过合理阈值（如 12 个月），倾向不做。
4. **先把流程跑顺，再自动化**
   - 确认手工流程已稳定、无歧义后再动手；否则自动化只会固化混乱。
   - 完成标准: 流程已被手工执行至少 3 次且每次一致。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 设置成本高于收益时——书明示"这样的自动化才有意义"的前提是成果超出成本。
- 流程还在变动、尚未跑通——先把流程稳定下来，否则把混乱固化后改动成本更高。
- 只做一两次的事——见 `mm-brute-force`。

### 容易误用的地方
- 书中明示的失败模式：设置成本高于收益时不应自动化；选错工具反而带来麻烦（浪费时间金钱甚至更糟）。
- 只算开发成本不算维护成本——自动化不是一次性的，它会持续要求有人照顾。
- 把"省下的人力"当成真金白银：如果那个人没有更高价值的事可做，账面上的节省不会兑现。

### 容易混淆的邻近模型
- 与**暴力解决方案（brute force）**：一次性 vs. 持续性的分野。
- 与**规模经济（economies of scale）**：手段与结果的关系。
