# 彼得原理（Peter principle）

## R — 原文 (Reading)

> 人们会根据过往的工作表现晋升到新岗位，但新岗位所需的能力或许截然不同，而且并不适合他们。最终，人们会被提升到不适合自己的岗位（也就是“其无法胜任的层级”），并在那个岗位上备受煎熬。
>
> — 《思维模型》, 第8章 > 为谁安排什么岗位

---

## I — 方法论骨架 (Interpretation)

彼得原理描述的不是"人不行"，而是**晋升机制的系统性缺陷**：晋升的依据是过去岗位的表现，但新岗位需要的能力往往与旧岗位截然不同——最典型的是从个人贡献转向人事管理。于是每个表现好的人都会被持续晋升，直到抵达一个他不胜任的层级，然后停在那里，备受煎熬。

为什么这个缺陷难以自纠？因为组织默认"把人往上放"既是奖励也是肯定的唯一方式，而新岗位的能力要求在晋升前无法被检验。

书中给出三条应对路径：

1. **避开错配岗**——为不擅策略但擅战术的人避开战略岗。不是每个人都该往上走，有些人留在擅长的层级价值更高。
2. **开辟多条晋升通道**——建立不需要人事管理的技术领导路径，让深度专业贡献也能获得与管理者对等的回报与地位。
3. **判断能否成长**——对"想升但暂不胜任"的人，判断他能否成长：能，就扶上马并给支持；不能，就提升他对现岗的满意度，或另设合适岗位。

关键判据：**晋升后的岗位与旧岗位之间，能力要求是否有实质差异？** 如果是同类型的更大范围，风险较低；如果是换了能力类型（做→管、战术→战略），就要走第三条路径的判断。

## A1 — 书中的应用 (Past Application)

### 案例: 组织层面的对策——技术领导通道

- **问题**: 书中未给具体人物案例，给出的是组织对策。
- **方法论的使用**: 面对"优秀个人贡献者被晋升到管理岗后失能"的普遍现象，作者提出的组织级解法是：开辟不需要人事管理的技术领导之路，让晋升不再是唯一的向上通道。
- **结论**: 把"向上"从单一通道变成多通道，是削弱彼得原理负面后果最有效的结构性手段。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 准备提拔一个业绩顶尖的个人贡献者去做管理，或他自己提出要转管理。
2. 某人晋升后明显状态下滑、团队抱怨，用户在想"是不是提错了"。
3. 组织在设计职级体系，讨论要不要设专家线/技术领导线。
4. 用户本人刚被提升到一个不熟悉的岗位，感到煎熬，怀疑自己不行。

### 语言信号 (用户的话里出现这些就应激活)

- "他业务能力最强，要不让他带团队吧"
- "升上去之后反而不行了"
- "我特别怕管人，但好像不往上走就没前途"
- "我们是不是该设个专家岗"
- "技术转管理到底适不适合我"
- "promoted into management and now struggling"

### 与相邻 skill 的区分

- 与 `mm-commandos` 的区别: 突击队员/警察模型讲的是**项目阶段与人格**的匹配（同一个人换个阶段就不合适）；彼得原理讲的是**晋升机制**把人系统性推到能力类型不同的岗位。
- 与 `mm-joy-s-law` 的区别: 乔伊法则是"不能靠挖明星"，指向岗位与项目设计；彼得原理是"内部晋升也会失效"，指向通道设计。
- 与 `mm-diffusion-of-responsibility` 的区别: 责任分散讲的是岗位责任归属不清导致没人动手；彼得原理讲的是人被放到了能力不匹配的岗位上。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **对比新旧岗位的能力类型**
   - 完成标准: 列出旧岗位的 2-3 项核心能力，与新岗位的 2-3 项核心能力，明确指出哪些是**类型差异**（做→管、战术→战略）而非程度差异。
   - 判停条件: 若只是范围扩大、能力类型相同，则彼得原理风险低，退出本 skill。
2. **判断是否为"战术强、策略弱"型错配**
   - 完成标准: 明确回答该人选是否属于"不擅策略但擅战术"，若是，直接给出避开战略岗的建议。
3. **检查是否存在替代通道**
   - 完成标准: 若组织没有技术领导/专家通道，明确提出建立该通道的建议，并说明它要具备哪些与管理者对等的回报（薪酬、话语权、资源）。
4. **对"想升但暂不胜任"做成长性判断**
   - 完成标准: 给出"能成长 / 不能成长"的判断及依据；能成长则配套支持措施（带教、缩小范围、定期复盘），不能成长则给出提升现岗满意度或另设岗位的替代方案。
5. **给出时间限定的结论**
   - 完成标准: 输出带复查节点的安排（例：三个月后按哪些信号决定去留），避免无限期煎熬。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 确实是绩效/态度问题（不是类型错配）——用彼得原理包装会掩盖真问题。
- 组织只有几人、没有晋升阶梯可言时，通道设计无从谈起。
- 用户需要的只是管理技能培训的具体资源——本模型不做培训方案。

### 书中警告的失败模式 / 容易误用的地方

- 书中明确：**某人最初不适合某岗位，不意味着永远不适合**——随时间与实践可能变得胜任，且往往优于从外部招聘新人。这是对本模型最容易被误用之处（拿它当永久判决）的直接纠正。
- （推导, 非书中明示）把"不胜任"归因于个人而不检查岗位设计，是组织层面的推责；很多时候是岗位被塞了过多异质职责。
- （推导, 非书中明示）多通道设计若只给头衔不给资源与话语权，会变成安慰奖，不起作用。

### 容易混淆的邻近模型

- **突击队员、步兵与警察（commandos）**: 阶段与人格匹配，不是晋升机制问题。
- **责任分散（diffusion of responsibility）**: 责任归属不清，不是能力错配。
