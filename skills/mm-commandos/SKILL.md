# 突击队员、步兵与警察（commandos, infantry, and police）

## R — 原文 (Reading)

> 如果你让一名“突击队员”扮演“警察”的角色（例如项目经理、监察主任等），他们通常会心生叛逆，把事情弄得一团糟。如果你让一名“警察”充当“突击队员”（例如涉及快速制作原型、创意交付的岗位），他们则会待在原地，陷入僵局。
>
> — 《思维模型》, 第8章 > 齐心协力

---

## I — 方法论骨架 (Interpretation)

这个模型借自军事：入侵一个国家需要三类部队，而且是在**不同阶段**依次投入。

- **突击队员（commandos）**: 工作努力、行动快速、工资低廉、专业水平稍差但可接受。他们靠出其不意和团队合作建立滩头堡。他们讨厌规则与程序。
- **步兵（infantry）**: 人数多、职责多，负责规模化推进。他们需要规则与程序——恰恰是突击队员讨厌的东西。
- **警察（police）**: 讨厌改变，靠增加人口、建立经济体系和规模化来促进发展，任务是守住并发展已经拿下的成果。

机制的关键在于**错配是双向伤害**：让突击队员去当项目经理，他会心生叛逆、把事情弄糟；让警察去快速做原型，他会原地僵住。所以这不是能力高低问题，而是人格—阶段匹配问题。

判据因此可以落到人格上：**反权威型人格适合当突击队员，喜欢循规蹈矩的人适合当警察。** 判断一个人该放哪儿，不是看他多优秀，而是看他对规则的态度。

对项目的实际含义是：同一个项目在从 0 到 1、从 1 到 100、从 100 到守成的三个阶段，需要不同的人主导。识别当前处在哪个阶段，是调用这个模型的第一步。

## A1 — 书中的应用 (Past Application)

### 案例: 克林利《意外帝国》的部队类比 & 阿特伍德的提醒

- **问题**: 企业在不同生命周期需要不同类型的人，但常被当成同一种"优秀员工"标准来招人用人。
- **方法论的使用**: 克林利在《意外帝国》中用入侵国家的三类部队来类比企业生命周期——先突击队抢滩，再步兵推进，最后警察治理。杰夫·阿特伍德在"编程恐怖"博客中补充了一个反面提醒：在需要保住成果的时候用突击队员会弊大于利。
- **结论**: 阶段与人格匹配决定成败；突击队员听起来令人兴奋，但在错误时机担任突击队员事实上会对项目有害。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 项目从探索期转入规模落地期，团队在讨论"要不要换负责人/加流程"。
2. 某个很能打的人被放到管理/治理岗位上之后明显不适应、团队开始出问题。
3. 一个成熟业务需要重新做创新，正在考虑"要不要让原来那批人来做"。
4. 招人时在纠结"要能折腾的还是要稳的"。

### 语言信号 (用户的话里出现这些就应激活)

- "他是打天下的，守不住"
- "项目已经跑通了，接下来谁来接"
- "他做流程特别难受，老是想打破规则"
- "我们能不能让他同时负责创新项目和日常运维"
- "这个人太稳了，推不动新东西"
- "We need someone to scale this / who should run it after the prototype"

### 与相邻 skill 的区分

- 与 `mm-generalists-versus-specialists` 的区别: 那个模型按**知识宽度**配置人（通才/专家），解决"要不要设专职岗"；本模型按**阶段与人格**配置人，解决"这个阶段该派谁"。
- 与 `mm-beachhead` 的区别: 滩头堡是一个目标/策略概念（找到可立足的小市场），本模型中的突击队员是执行这一策略的人的类型。
- 与 `mm-peter-principle` 的区别: 彼得原理解释"为什么好人被晋升到不胜任的位置"（晋升机制问题）；本模型解释"为什么同一岗位在不同阶段对不同人格的适配度不同"（匹配问题）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判定项目当前阶段**
   - 完成标准: 在"抢滩（未验证、求速度）/ 推进（已验证、求规模）/ 守成（求稳定与深化）"三选一，并写出支持该判断的证据。
2. **识别该阶段需要的人格**
   - 完成标准: 明确该阶段主导者应对规则持什么态度（打破 / 遵守 / 维持），以及应被什么激励（奇袭成果 / 规模效率 / 稳定与秩序）。
3. **盘点现有人员并做匹配**
   - 完成标准: 对每位关键成员给出"突击队员 / 步兵 / 警察"的判断与依据（看他对规则、流程、改变的实际行为）。
4. **找出错配并给出调整方案**
   - 完成标准: 至少指出一处错配，并给出具体调整（换岗、搭档、引入外部、明确边界）。
   - 判停条件: 若全员匹配当前阶段，跳到步骤 5。
5. **预判下一阶段并提前安排**
   - 完成标准: 写出下一阶段何时到来（触发信号）、届时主导者应换成谁、过渡怎么安排。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 任务本身不涉及阶段变化（如一次性的稳定执行工作），三类划分没有意义。
- 用它给同事贴固定标签并据此永久排除在某类工作之外——这是人格倾向，不是能力上限。
- 需要严格公平的晋升与人事决策场合，标签化表述容易造成伤害，应回到可观察行为。

### 书中警告的失败模式 / 容易误用的地方

- 阿特伍德提醒：虽然当突击队员听起来令人兴奋，但在错误时机担任突击队员事实上会对项目有害——"突击队员"不是荣誉头衔。
- （推导, 非书中明示）阶段切换时的交接最易出问题：突击队员建立的滩头堡往往没有文档与流程，步兵接手时会重新踩一遍坑，需要预留交接成本。
- （推导, 非书中明示）一个人可能在不同阶段之间迁移（有些突击队员能学会守成），不应把分类当成永久定型。

### 容易混淆的邻近模型

- **通才与专家（generalists versus specialists）**: 知识宽度维度，不是阶段/人格维度。
- **彼得原理（Peter principle）**: 晋升机制造成的错配，与本模型的阶段性匹配互补。
