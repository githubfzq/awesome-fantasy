# 重新定义问题（reframe the problem）

## R — 原文 (Reading)

> 另一种在遇到困境时迅速找到解决方案的策略是重新定义问题（reframe the problem）。……如果游乐设施本身空间有限，这种方法甚至无法实现。
>
> — 《思维模型》, 第3章 > 通往成功的捷径

---

## I — 方法论骨架 (Interpretation)

当一个问题怎么解都太贵、太慢或者根本不可行时，最快的出路往往不是更努力地解它，而是**换一种方式把它表述出来**。

为什么有效？因为问题的表述方式决定了它的"解答空间"——你能在哪些方向上找解。原表述把解空间锁死在一个昂贵或不可行的区域里；重新表述之后，原本看不见的解法会浮现出来。

这在数学和科学里是最常规的操作：把一道难题转换成另一道"已经有可行解法"的问题，于是现成的算法和设计模式都能用上。

判据是：**当原问题的最优解成本过高或不可行时，先停下来问一句"我真正要解决的到底是什么"**。注意，重新定义不是放弃目标——目标没变，是被锁死的路径变了。

需要警惕的是，这个工具本身是中性的：重新定义问题也能导向坏的解法。

## A1 — 书中的应用 (Past Application)

### 案例: 迪士尼的排队问题

- **问题**: 主题乐园排队时间太长，游客怨声载道。原问题是"怎么减少排队时间"，但游乐设施的空间和吞吐能力有限，靠加容量根本做不到（原文提到"如果游乐设施本身空间有限，这种方法甚至无法实现"）。
- **方法论的使用**: 迪士尼把问题重新定义为"怎么让人们在排队时更开心"——目标从"缩短客观等待时间"转成"改善主观等待体验"。
- **结论**: 重定义后解答空间被打开，于是有了快速通行证（FastPass）、预计等候时间公告牌、排队区里的游戏与动画等一系列低成本、切实可行的解法。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户在一个问题上卡了很久，所有想到的方案都被"太贵/太慢/不可能"否掉。
2. 用户描述的需求明显是某个解决方案，而不是真正想达成的目标（"我要一个更快的马车"）。
3. 用户面临资源硬约束（空间、预算、时间、人力），但目标必须达成。

### 语言信号 (用户的话里出现这些就应激活)

- "这个根本做不到吧"
- "所有方案都太贵了"
- "卡住了，想不到别的办法"
- "有没有完全不一样的思路"
- "there has to be a different way to look at this"

### 与相邻 skill 的区分

- 与 `mm-first-principles` 的区别: 第一性原理是把问题拆到不可再拆的基本事实再重建；重新定义是换一个等价（或更高层）的问题表述，不必拆到基本事实。
- 与 `mm-jobs-to-be-done` 的区别: 待办任务专门用于识别用户"雇用"产品要完成什么，是重定义在产品领域的一个具体应用。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写下用户当前的原始问题表述，并确认它为什么无解**
   - 完成标准: 明确写出"原表述是什么"和"卡在哪"（太贵/不可行/资源硬约束）。
2. **追问真正的目标：抛开当前做法，用户最终想要的状态是什么**
   - 完成标准: 得到一句不含手段描述的目标陈述。
   - 判停条件: 若原表述已经就是目标本身（无法再往上抽象），本模型不适用，退出。
3. **产出至少 3 种不同的重定义表述**
   - 完成标准: 每个表述都改变了求解方向（换主体、换时点、换度量指标、换约束条件），并说明各自打开了什么新的解答空间。
4. **评估每种重定义下的解法，选成本最低且仍达成原目标的**
   - 完成标准: 每种重定义至少给出 1 个具体解法，并标注成本与可行性。
5. **检查重定义有没有偷换目标或引入负面解法**
   - 完成标准: 明确验证新解法是否真的服务于原目标；同时排除那些"达成指标但损害真实目标"甚至是伦理上有问题的解法。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 问题已经定义清楚、只是执行不到位时，重定义只会拖延执行。
- 需要找到故障根因（系统出错、事故复盘）时，那是根本原因分析，把问题换个说法会掩盖真实缺陷。

### 书中警告的失败模式 / 容易误用的地方

- 书中明示：重定义也可能导向负面解法——黑客把"怎么猜出密码"重定义为"怎么获取密码"，于是选择了社会工程。
- （推导, 非书中明示）重定义容易退化成"改指标"：把难做的指标换成好做的代理指标，看似解决了问题，真实目标并未改善。

### 容易混淆的邻近模型

- 与横向思维（lateral-thinking）混淆：横向思维是一大类跳出常规的思考技巧，重定义问题是其中非常具体的一招——改问题本身的表述。
- 与解答空间（solution-space）混淆：解答空间是被问题表述决定的可选解集合，是重定义要打开的"那个东西"，不是方法本身。
