# 去风险化（de-risking）

## R — 原文 (Reading)

> 为了少犯错，你还需要在现实世界中测试自己的假设。这个过程被称为"去风险化"（de-risking）。
>
> — 《思维模型》, 第1章 少犯错 > 保持简洁，笨蛋！

---

## I — 方法论骨架 (Interpretation)

任何一个计划，表面是一个方案，实际是一叠假设。创业方案里锁着"能造得出来""有人想要""能盈利""扛得住竞争""市场够大"这五条；度假计划里锁着"那家酒店还开着""亲戚那周有空"。方案失败时，几乎总是其中某一条假设不成立，而不是整体逻辑错了。

去风险化就是把这叠假设**显式化**，然后有次序地、用尽可能低的成本把它们一条条拿回现实里检验。

为什么这样能少犯错？因为假设的**致命性**和**不确定性**分布是极不均匀的：通常少数两三条假设决定成败，而多数假设即使错了也无所谓。如果按假设在文档里出现的顺序、或按"最容易检验的那条"去验证，就会把最贵的资源花在最不要紧的地方。正确的排序是两个维度的乘积：

> **优先级 = 这个假设若错，结论是否随之崩塌（致命性） × 我有多不确定它（不确定性）**

只有致命且高度不确定的假设才值得优先花成本检验。致命但已经很确定的、不确定但无关紧要的，都可以往后放甚至直接接受。

关键操作是**先检验、后投入**：书中强调必须在"做太多事之前"检验，否则就变成了过早优化——把资源投进一个建立在未验证假设上的方案，投得越多沉没成本越大，越难回头。

关键判据（针对每一条假设问两个问题）：
1. 如果这个假设是错的，我的结论会不会随之崩塌？
2. 我对它有多不确定？有没有任何现实证据，还是纯粹是我以为？

## A1 — 书中的应用 (Past Application)

### 案例: 创业的五条原则性假设 vs. 度假安排
- **问题**: 作者要示范"去风险化"在不同量级的事情上怎么用，以及它不必昂贵。
- **方法论的使用**: 把一个创业计划拆成五条原则性假设——能造出来、有人想要、能盈利、能抵御竞争、市场够大——然后逐条拆细，按上述两个维度排序，优先在现实中检验最致命且最不确定的那条（通常不是"能造出来"，而是"有人想要"）。对照之下，一次度假安排的去风险化只需两个动作：网上搜一下酒店评价、发邮件问亲戚那周有没有空。
- **结论**: 去风险化的成本与事情的量级成比例，但**流程是一样的**。它的价值不在于做得多隆重，而在于把"我以为"变成"我查过了"，并且是在投入之前而不是之后。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **要投入大资源前的最后一道关**: 要辞职创业、要立项、要批量生产、要签长约、要买设备。用户已经被自己的方案说服，需要有人把假设拆出来。
2. **方案讨论陷入"我觉得会有人买 / 我觉得不会"**: 双方各执一词但都没有证据。需要把分歧转化成一条可检验的假设和一次低成本实验。
3. **推演完第一性原理后**: 从基本事实推导出新结论（比如成本能压到三分之一），但那只是假设，需要回到现实检验。
4. **项目已经投入很多但前景不明**: 需要判断现在该继续、转型还是停下——回头列出当初未验证的假设，看哪条现在能补验。
5. **规划一件多方参与的事**（活动、旅行、搬迁）: 需要一份"哪些前提必须确认"的清单，避免临门一脚才发现不成立。

### 语言信号 (用户的话里出现这些就应激活)

- "我们先小范围试一下吧"
- "万一没人要怎么办"
- "我们凭什么认为用户会买单？"
- "能不能先做个最简版本看看反应"
- "这件事最大的不确定性在哪？"
- "投这么多钱之前，有没有更便宜的验证方式"
- "Let's de-risk this." / "What's the riskiest assumption?" / "How can we test this cheaply?"

### 与相邻 skill 的区分

- 与 `mm-arguing-from-first-principles` 的区别: 第一性原理是**在脑子里**从基本事实推导出结论，产出的是假设；去风险化是**在现实世界里**检验假设。书中明确把二者接在一起：推导出来的东西必须去检验。
- 与 `mm-minimum-viable-product` 的区别: MVP 是一种具体的去风险化**手段**（做一个最小版本去验证需求）；去风险化是更上层的**流程**（排序并检验所有关键假设，其中只有一部分适合用 MVP 验证）。
- 与 `mm-premature-optimization` 的区别: 过早优化是在假设未验证时就打磨细节；去风险化正是它的解药——把打磨的动作推迟到关键假设被验证之后。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把方案拆成显式假设清单**
   - 完成标准: 列出 5-10 条假设，每条写成一句可被证伪的陈述（"目标用户愿意为 X 付 Y 元"，而不是"市场有需求"）。书里给的创业五条可作为起始模板：能造出来 / 有人想要 / 能盈利 / 能抵御竞争 / 市场够大。
   - 判停条件: 若某条假设无法被证伪，重写它；重写不了就删除，它不参与排序。
2. **给每条假设打两个分数：致命性 × 不确定性**
   - 完成标准: 致命性 = "它若错，整个结论是否崩塌"（高/中/低）；不确定性 = "我有现实证据吗，还是只是我以为"（高/中/低）。两个维度都写理由。
3. **排序，取前 1-3 条**
   - 完成标准: 输出排序表，前 3 条是"高致命 × 高不确定"的假设。明确写出为什么"容易检验但不致命"的假设不在前面。
   - 判停条件: 若存在某条致命假设**完全无法低成本检验**，单独标出并告知用户这是项目的结构性风险，不要假装它可以被验证。
4. **为每条关键假设设计最低成本检验**
   - 完成标准: 每条给出具体动作 + 成本 + 时间 + 明确的判定阈值（例如"24 小时内找到 10 个愿意预付定金的人"）。判定阈值必须**先于**实验写下，否则事后总能解释成成功。
   - 判停条件: 若检验成本高于"假设错了会造成的损失"，跳过检验直接做，并在输出中说明这个取舍。
5. **执行检验并据结果调整策略**
   - 完成标准: 按阈值判成"通过/不通过"。不通过，则**立刻停下并改变方案**——书中强调：若关键假设不成立就停下改变，否则整个流程无法推进。
   - 判停条件: 若结果落在阈值附近（模糊区），不要据此下结论，重新设计一次更锐利的检验。
6. **更新假设清单，进入下一轮**
   - 完成标准: 把已验证的假设从清单移出，把检验中冒出来的新假设加入，重新排序。输出下一轮该检验的那一条。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **假设已被充分验证时**: 若这条假设已有扎实的历史数据或直接经验支撑，再验证一遍是浪费。
- **检验成本高于失败损失时**: 直接做比验证快。别为了严谨而严谨。
- **纯粹的执行类任务**: 没有假设需要检验，只需要做。

### 书中警告的失败模式 / 容易误用的地方

- **书中未提明确局限，但强调必须在"做太多事之前"检验，否则触发过早优化**（`boundary` 字段原文）。这是本模型最重要的时间约束：检验太晚，沉没成本会绑架判断。
- （推导, 非书中明示）**事后设定判定阈值**: 实验做完了才决定"多少算成功"，等于没有阈值。阈值必须在实验开始前写死。
- （推导, 非书中明示）**只检验容易检验的**: 团队倾向于先做能做实验的那条假设，而不是该做的那条。必须强制按"致命性 × 不确定性"排序，而不是按可行性排序。
- （推导, 非书中明示）**把"验证通过"当成"验证充分"**: 找到 10 个愿意预付的人，不等于市场够大。每条假设验证的只是它自己，不要把结论外推。

### 容易混淆的邻近模型

- **过早优化（premature-optimization）**: 是在假设未验证时打磨细节，去风险化是它的解药；但去风险化本身也可能被滥用成"无限期验证而不动手"，此时它自己就成了另一种过早优化。
- **敏感性分析（sensitivity-analysis）**: 是在模型内部看哪个输入变量对输出影响最大；去风险化是回到现实世界去获取那个变量的真实值。前者是计算，后者是实验。
