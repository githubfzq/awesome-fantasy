# 坦诚相待（2×2 反馈矩阵）（Radical Candor）

## R — 原文 (Reading)

> 这个矩阵的横轴和纵轴分别是“直接挑战”和“个人关怀”。……“坦诚相待”（矩阵中的右上象限）是结合“直接挑战”和“个人关怀”这两种方式提出的反馈。你的反馈完全坦率，从根本出发，直指问题的根源。
>
> — 《思维模型》, 第8章 > 熟能生巧

---

## I — 方法论骨架 (Interpretation)

金·斯科特提出的反馈矩阵有两条轴：

- **直接挑战（direct challenge）**: 给出可付诸实践的具体建议，而不是抽象模糊的评价。
- **个人关怀（personal care）**: 反馈之前已有的关系基础——对方是否相信你是为他好。

右上象限（两轴都高）是**坦诚相待**：完全坦率，从根本出发，直指问题根源。

为什么两轴缺一不可？

- 只有关怀没有挑战 = **有害的同情（ruinous empathy）**（左上）：说了等于没说，问题留着，对方还以为自己没问题。含糊其辞比直截了当容易，但只有具体说明才能让反馈起作用。
- 只有挑战没有关怀 = **可憎的侵犯（obnoxious aggression）**（右下）：反馈再直白也会被抛在脑后，甚至破坏关系。
- 两者皆无 = **操纵式的伪善（manipulative insincerity）**（左下）：难以付诸实践的含糊批评，既不说清也不关心。

书中给出的措辞对照最说明问题：「我认为你在沟通这方面可以做得更好」是模糊的；「你说的那句话叫人摸不着头脑。我认为你应该这么说……」才是直接挑战。

它与刻意练习紧密相连——**这正是刻意练习例会中应提供的反馈**，因为刻意练习要求的"实时反馈"，只有坦诚相待的质量才够用。

关键判据：这条反馈里有没有一个对方明天就能改的具体动作？没有，就落在非右上象限。

## A1 — 书中的应用 (Past Application)

### 案例: 反馈措辞对比

- **问题**: 书中未给独立案例，给出的是反馈措辞的对比。
- **方法论的使用**: 「我认为你在沟通这方面可以做得更好」——模糊、抽象、无法付诸实践，属于有害的同情或操纵式的伪善；「你说的那句话叫人摸不着头脑。我认为你应该这么说……」——具体、可操作，是直接挑战。
- **结论**: 同一件事，措辞的差别决定了反馈落在这个矩阵的哪个象限；只有具体说明才能让反馈起作用。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要给下属/同事/合作者提一条可能让人不适的反馈，不确定怎么说。
2. 用户收到一条模糊的负面评价，不知道对方到底要他改什么。
3. 团队在做复盘或一对一，需要把反馈制度化。
4. 用户发现自己"说了但对方没改"，怀疑反馈方式有问题。

### 语言信号 (用户的话里出现这些就应激活)

- "我怕说了伤感情，就一直没说"
- "我说过了，但他根本没当回事"
- "领导说我沟通可以做得更好，具体是啥意思"
- "怎么提意见才不会把关系搞僵"
- "他这做得太差了，我能直说吗"
- "How do I give feedback without being harsh / radical candor"

### 与相邻 skill 的区分

- 与 `mm-deliberate-practice` 的区别: 刻意练习要求"实时反馈"这个要素，坦诚相待规定这个反馈应该是什么质量——前者提需求，后者给供给。
- 与 `mm-most-respectful-interpretation` 的区别: 最善意的解释是**接收**反馈/信息时的态度（先把对方的话往最好处解释）；坦诚相待是**给出**反馈时的结构。
- 与 `mm-high-context-versus-low-context-communication` 的区别: 高/低语境解释不同文化对"说多少"的默认期望；坦诚相待主张无论语境都要具体——但落地时要考虑语境差异。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认目标：你要改变的是哪个具体行为**
   - 完成标准: 用一句话写出希望对方"明天开始做/停止做"的具体动作，而不是一个品质标签。
2. **检查关怀轴：关系基础是否足够**
   - 完成标准: 明确回答"对方是否相信我在为他好"；若否，先补关系（先做一次非评价性的交流）。
   - 判停条件: 若关系基础明显不足且无法短期补上，先降低挑战强度并另寻合适的反馈人。
3. **把反馈改写为直接挑战**
   - 完成标准: 输出改写后的原话，要求满足：指出具体哪一句话/哪一个行为（不是"沟通"这类抽象词）+ 给出应该怎么说/怎么做。
4. **自检落在哪个象限**
   - 完成标准: 明确标出改写后的反馈落在右上象限，并说明改写前的版本落哪个象限。
5. **约定后续**
   - 完成标准: 给出下一次观察/复盘的时间点，让反馈成为循环而非一次性事件。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 对方此刻需要的是安慰、支持或哀伤陪伴，不是改进建议——这时给反馈就是"可憎的侵犯"。
- 纯事实性纠正（数据写错了、链接失效了）——不需要动用关怀轴，直接说更快。
- 权力极度不对等且缺乏信任的环境（如刚认识、或对方有报复倾向）——关怀轴无法凭一次对话建立。

### 书中警告的失败模式 / 容易误用的地方

- 书中未提边界。以下是基于机制推导的警告，标明「(推导, 非书中明示)」：
  - 把"直接挑战"当成直率伤人的许可证：没有关怀轴，直白只会被抛在脑后。
  - 把"个人关怀"当成先夸两句再批评的话术模板：关怀是反馈**之前已有的关系基础**，不是当场补的缓冲句。
  - 在公开场合给出本应私下的直接挑战，会让关怀轴瞬间归零。
- 含糊其辞比直截了当容易，但只有具体说明才能让反馈起作用——这是书中明确给出的判断。

### 容易混淆的邻近模型

- **最善意的解释（most respectful interpretation）**: 接收端的态度模型，与本模型的给出端互补。
- **刻意练习（deliberate practice）**: 消耗高质量反馈的训练模型。
