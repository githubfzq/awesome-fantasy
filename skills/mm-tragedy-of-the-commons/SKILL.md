# 公地悲剧（tragedy of the commons）

## R — 原文 (Reading)

> 牧民每增加一头牛，自己家就能从中受益。但如果所有牧民都不断增加奶牛，公地上的牧草就会消耗殆尽，所有人都会体会到过度放牧对牧群和土地造成的负面影响。
>
> — 《思维模型》, 第2章 > 无意伤邻

---

## I — 方法论骨架 (Interpretation)

结构是**收益私有化、成本社会化**：

> 每多攫取一单位，收益归自己（全部），损耗由全体分摊（我只承担 1/n）。

于是对每一个个体而言，再多一单位永远是划算的——我拿 100% 的好处，只付 1/n 的代价。而当所有人都这样算账时，资源被耗尽，所有人受损。这不是因为牧民贪婪或愚蠢，而是因为**激励结构本身指向耗尽**。每个人都是理性的，集体结果是灾难性的。

关键判据不是"这是不是自然环境"，而是：**是否存在一个无排他性的共享资源池**。只要满足这一条，不管资源是什么，悲剧结构就成立。书中明确点出的非环境例子：垃圾邮件（共享的是收件人的注意力与邮件系统的信誉）、抗生素抗药性（共享的是抗生素的有效性）、维基百科词条的可靠性（共享的是词条的可信度）。

破解办法的方向是明确的：**由能纵观全局的一方限制个体的决策**。这个角色可以是自己（内部约束）、第三方（社群规范）、或管制者（法规、配额、产权）。波士顿公地在 1646 年被迫颁布限养 70 头牛的法令，就是管制者介入的例子。

关键判据（判断是不是公地悲剧）：
1. 是否存在一个**无排他性**的共享资源池（谁都能取用、很难把谁排除在外）？
2. 个体的边际收益是否**归自己**，而边际损耗是否**由全体分摊**？
3. 是否已经出现"每个人都觉得只用了一点，但总量已经过载"的现象？

## A1 — 书中的应用 (Past Application)

### 案例: 波士顿公地的过度放牧
- **问题**: 作者要说明公地悲剧是一个长期存在、且需要外部管制才能解决的结构性问题。
- **方法论的使用**: 17 世纪的波士顿公地（即今天的波士顿公园）上，富裕家庭不断增加自己的奶牛数量，每家都只多要一点，最终牧草被消耗殆尽。1646 年，当地被迫颁布法令，限制总共只能养 70 头牛——由管制者出面限制个体决策。直到 1833 年，威廉·劳埃德才把这种现象正式写成"公地悲剧"。
- **结论**: 悲剧不是靠牧民自觉解决的（自觉无法改变激励结构），而是靠一个能纵观全局者的外部限制。作者特别强调它的影响"远远超出环境问题"——判据是无排他性的共享资源池，而不是资源是不是草地。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **共享资源被用爆**: 团队共享的测试环境、公司的云资源预算、部门共用的设计系统、共享带宽。
2. **质量型公地的退化**: 代码库质量、文档准确性、wiki/知识库可信度、代码 review 的认真程度——每个人偷一点懒，整体崩坏。
3. **信誉型公地**: 群发的营销邮件、对外承诺的交付标准、品牌的社媒发言——个人多发一封收益归自己，信誉损耗由全体承担。
4. **注意力 / 时间公地**: 会议时间、群消息、共享日历——每个人多占一点，所有人都被消耗。
5. **需要设计配额/限流/产权/规范**: 用户要解决"没人爱惜"的问题，需要知道该从哪个方向入手。

### 语言信号 (用户的话里出现这些就应激活)

- "谁都不爱惜，反正不是自己的"
- "大家都这么干，我一个人省着也没用"
- "资源又快被用爆了"
- "没人愿意做维护，但人人都在用"
- "要不要搞个配额/限流"
- "这事该谁管？"
- "tragedy of the commons" / "nobody takes care of it" / "everyone overuses it" / "free rider"

### 与相邻 skill 的区分

- 与 `mm-free-rider-problem` 的区别: 搭便车关注的是**不为公共品做贡献**（享受好处但不付出）；公地悲剧关注的是**过度取用共享资源**（付出很少但拿走很多）。一个是贡献不足，一个是消耗过度。二者常同时出现，但处方不同。
- 与 `mm-externalities` 的区别: 外部性是更上层的概念——个体行为对第三方产生了未定价的影响（可正可负）；公地悲剧是**负外部性在特定结构下的集体性爆发**（无排他性 + 收益私有 + 成本共担）。
- 与 `mm-prisoner-s-dilemma` 的区别: 囚徒困境是**两人一次性/重复博弈**中的背叛结构；公地悲剧是**多人在共享资源池上**的持续取用问题。数学结构相关（都是个体理性导致集体次优），但场景与解法不同。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别共享资源池，并确认它无排他性**
   - 完成标准: 明确指出那个被共享的东西是什么（带宽、信誉、注意力、代码质量、预算），并说明为什么很难把任何人排除在外。
   - 判停条件: 若产权明确或已有有效排他机制，本 skill 不适用——书中明示反例：产权明确或存在有效管制时不成立。转向普通的资源管理。
2. **验证激励结构：收益私有、成本共担**
   - 完成标准: 写出"个体多做一单位，得到什么（全部归自己）"与"造成什么损耗（由几方分摊、每人摊多少）"。
   - 判停条件: 若个体的损耗也主要由自己承担（不是共担），那就不是公地悲剧，只是普通的成本收益问题。
3. **确认是否已经出现过载迹象**
   - 完成标准: 给出可观察的过载证据（配额告警下降、质量指标恶化、维护时间占比上升、投诉增多），而不是凭感觉。
4. **确定由谁来限制个体决策**
   - 完成标准: 三选一并说明理由——**自己**（自我约束、内部约定）、**第三方**（社群规范、同行压力、透明化）、**管制者**（配额、限流、收费、产权界定、规则与处罚）。书中波士顿的例子是管制者。
   - 判停条件: 若无人有全局视角或执行权，明确指出这是治理缺口，需要先解决"谁有权限制"的问题，否则任何方案都落不了地。
5. **设计具体限制机制并给出量化阈值**
   - 完成标准: 给出可执行机制（配额上限、按使用计费、限流、轮值维护责任、命名可见的取用记录、违约处罚），并写明阈值与检查频率。
6. **（可选）考虑把公地变成私地**
   - 完成标准: 评估能否通过界定产权或划分责任（明确归属、专属配额、责任到人）来消除无排他性——这是最彻底的解法，但并非总能做到。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产权明确或已有有效管制时**（书中明示反例）: 若资源已经有清晰归属或有效的排他机制，悲剧结构不成立，这只是普通的资源管理问题。
- **个体损耗也主要自担时**: 公地悲剧需要"成本社会化"。如果我多用一个单位，代价主要落在我自己头上，那不存在悲剧结构。
- **资源可无限再生、取用不影响总量时**: 信息、知识这类非竞争性资源被多人使用不会耗尽，不适用。

### 书中警告的失败模式 / 容易误用的地方

- **作者强调它「影响远远超出环境问题」，不能只用于环保场景**（`boundary` 字段原文）。最常见的误用是只在谈环保时才想起它，而忽略了垃圾邮件、抗生素抗药性、知识库可靠性这些同样是公地的领域。
- （推导, 非书中明示）**指望自觉与道德教育**: 悲剧的驱动力是激励结构，不是品德。不改变"收益私有、成本共担"的结构，呼吁珍惜无效。
- （推导, 非书中明示）**限制机制无人执行**: 定了配额但没人测量、没人处罚，等于没有配额。必须明确执行者与检查频率。
- （推导, 非书中明示）**限制过度导致公地闲置**: 管制的目的是可持续，不是把资源锁死。阈值应参考资源的再生速率或承载上限，并定期复核。

### 容易混淆的邻近模型

- **搭便车（free-rider-problem）**: 贡献不足 vs 取用过度，二者常共现但处方不同。
- **科斯定理（coase-theorem）**: 指出在交易成本低、产权明确时，各方可以协商解决外部性——这正对应"把公地变成私地"这条解法路径。
