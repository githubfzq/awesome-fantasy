# 舍基原则（Shirky Principle）

## R — 原文 (Reading)

> 舍基原则指出，如果组织能提供某个问题的解决方案，它们就会努力让问题保留下来。

> — 《思维模型》, 第4章 > 别跟自然对着干

---

## I — 方法论骨架 (Interpretation)

舍基原则揭示的是一种**结构性的利益绑定**：一个组织如果靠解决某个问题而存在，那么这个问题的消失就等于它的消亡。于是它会——通常不是出于恶意，而是出于生存本能——努力让这个问题保留下来。

机制很直白：**组织的收入、预算、话语权与存在感，全都与"问题仍在"绑定**。所以当一个更简单、更便宜、甚至能根除问题的方案出现时，最强烈的反对声音往往不是来自被服务的人，而是来自现在的服务提供者。

书中的例证是特波税务软件（TurboTax）：它让报税变轻松，却游说反对政府推行"无须返回申报"（return-free filing）的预填表制度——因为一旦政府预填好税表，报税软件这门生意就没了。

在个人层面，它表现为那句"**我们这儿一直是这么做的**"。作者提醒：办公室或学校里那些总说这句话的老古板正是此原则的体现，你绝不会想变成那样的人。这一句把模型从"分析别人"翻转为"照镜子"——**你的价值是否也绑定在某个本可以消失的问题上？**

关键判据是：**看反对者的收益是否随问题的消失而消失**。如果是，那么他对方案的技术性批评就需要打折看待；如果不是，他的反对可能确实基于合理性。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 推动流程简化/自动化时，遭到某个中间部门或供应商的强烈反对，理由听起来合理但总觉得不对。
2. 看到一个明显更优的方案（自助化、预填、开源、直连）被行业既得利益者联手阻挠。
3. 分析某个政策或行业现象为什么长期低效却不改变。
4. 团队内部有人以"一直是这么做的"反对变革，需要判断这是经验还是利益。
5. 自我审视：我现在的岗位价值是否建立在某个本可以消失的问题上。

### 语言信号

- "为什么这么简单的改进他们就是不同意"
- "我们这儿一直是这么做的"
- "这个流程存在的意义到底是什么"
- "供应商强烈反对我们自己做"
- "明明有更省事的办法，就是推不动"
- "Shirky Principle / they profit from the problem / incumbent resistance"

### 与相邻 skill 的区分

- 与 `mm-perverse-incentives` 的区别: 不当诱因泛指**激励设计导致行为扭曲**（指标导致造假），舍基原则特指**存在性威胁导致的护问题行为**。前者是"怎么做会被扭曲"，后者是"为什么它不许问题消失"。
- 与 `mm-regulatory-capture` 的区别: 管制俘获是**被监管者控制了监管机构**（通过政治渠道），舍基原则是**解决方案提供者维护问题本身**（通过市场与话语）。前者靠权力，后者靠业务模式。
- 与 `mm-inertia` 的区别: 惯性是**无动机的维持现状**（懒得改、改不动），舍基原则是有**明确利益动机**的维持现状。区分方法是：如果问题消失，谁会受损？

## E — 可执行步骤 (Execution)

1. **画出"谁从这个问题的持续存在中获益"**
   - 列出所有与该问题相关的组织/部门/角色，以及他们从中获得的收入、预算、权力、存在感。
   - 完成标准: 得到一张"利益相关方—收益来源"表。
2. **检验：如果问题消失，谁受损？**
   - 对每一方问：这个问题被彻底解决后，他们损失什么？
   - 完成标准: 明确指出至少一方会因问题消失而失去主要收益来源。
   - 判停条件: 若无人受损，本 skill 不适用，转向 `mm-inertia`。
3. **把反对意见分成"技术性"与"存在性"两类**
   - 逐条检查反对理由：是"这个方案有缺陷"还是"这个方案会让我们没用"。
   - 完成标准: 每条反对意见被归类，并标注哪些需要认真对待、哪些是存在性防御。
4. **设计让对方也能赢的过渡方案**
   - 既然硬碰硬会被持续阻挠，考虑让对方的收益与"问题被解决"而非"问题存在"绑定（转岗、改收费模式、承接新环节）。
   - 完成标准: 至少提出一个能保住对方部分收益的替代路径。
5. **自我检查：我是不是那个老古板？**
   - 用作者的提醒照镜子：我的价值是否绑定在某个本可以消失的问题上？
   - 完成标准: 明确回答自己的岗位/收益是否依赖某个可被消除的问题，若是，列出转向计划。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 把所有变革阻力都解释成利益阴谋。先排除合理性：很多"一直是这么做的"背后是真经验（安全、合规、历史教训）。（推导，非书中明示）
- 对方是可以被说服的个体、而非依赖该问题的组织：此时是沟通问题，不是结构性问题。（推导，非书中明示）
- 用户只是想抱怨同事保守：本 skill 首先是一个分析工具，其次才是自我审视的镜子；只用来评判别人属于误用。（书中明示：作者提醒"你绝不会想变成那样的人"）

### 容易误用的地方

- 把正当的专业意见当成存在性防御。反对一个方案不等于在护自己的饭碗，需要按步骤 3 逐条甄别。（推导，非书中明示）
- 只用它分析对手，不用它照镜子。作者明确把这条原则引向自我警惕——你也可能正靠某个本可消失的问题吃饭。（书中明示）
- 认为对方是恶意的。机制是生存本能，不是阴谋；按恶意处理会破坏合作可能。（推导，非书中明示）

### 容易混淆的邻近模型

- 与不当诱因：一个说"指标会扭曲行为"，一个说"存在会绑定立场"。
- 与管制俘获：一个靠业务模式维护问题，一个靠政治影响力控制规则制定者；两者常同时发生（如报税软件既护问题又游说政府）。
