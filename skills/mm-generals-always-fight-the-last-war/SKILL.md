# 将军总在打上一场仗（generals always fight the last war）

## R — 原文 (Reading)

> 将军总在打上一场仗（generals always fight the last war）。这意味着，军队会默认使用在过去或上一场战争中奏效的策略、战术和技巧。
>
> — 《思维模型》, 第7章 > 改变战局

---

## I — 方法论骨架 (Interpretation)

任何一套战术都不是凭空成立的，它成立在一组隐含前提上：当时的技术条件、对手的形态、信息传播速度、成本结构。当这些前提变了而战术没变，战术就悄悄从"最优解"退化成"惯性"。

这个模型描述的就是这种退化：组织和个人会默认沿用上一场战争中奏效的策略、战术与技巧，而它未必适合下一场战争。为什么普遍发生？因为上一场胜利会被写进晋升标准、培训材料、预算分配和组织记忆里——越成功，惯性越强，越难被质疑。

它的另一面是机会：**战术优势随技术环境变化**。当环境迁移时，用更现代有效的战术对抗过时的战术，兵力较少也能胜出。本质上这是靠改变游戏规则取胜，而对手还没意识到游戏规则已变。

关键判据有两个：

1. **前提核查**——这套打法当年成立的前提，今天还成立吗？如果不成立，它就是"上一场仗的战术"。
2. **对手觉察度**——赢的窗口来自于对手尚未意识到规则已变；一旦对手也换装备，你的优势立刻消失，所以这是一个有时限的窗口，不是长期护城河。

作者也提醒不要过度推广：政治家、金融专家、教育界都在"打上一场仗"，但反过来，也不要假定一切旧战术都失效。

## A1 — 书中的应用 (Past Application)

### 案例: 对马海战、IBM 与大型主机、微软与智能手机

- **问题**: 沙俄舰队带着上一场海战的装备与战法投入 1905 年对马海战；IBM 把 PC 操作系统让给微软，因为战略重心押在大型主机上；微软困守 Windows，把智能手机市场让给苹果。
- **方法论的使用**: 三个案例的共同结构都是——环境的技术前提已经改变（航速与射程、无线电；计算中心从主机转向个人终端；终端从 PC 转向手机），而 incumbents 仍然按旧前提配置资源，把新战场当成边缘业务。
- **结论**: 日军凭借航速、射程优势与无线电大败沙俄舰队；IBM 与微软各自在换代节点上把新战场让给了后来者。谁先察觉规则已变，谁获得窗口期优势。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 行业出现了新技术/新渠道/新监管，用户仍在用旧的投入结构分配资源（例：还在把主要预算投在正在失效的渠道上）。
2. 用户用"我们当年就是靠这个做起来的"来否决新做法，或说"这个我们十年前试过，不行"。
3. 用户所在的组织明显被更灵活的后来者蚕食，但不理解为什么。
4. 用户在评估一个"看起来很小"的新事物，需要判断它是否代表规则迁移。

### 语言信号 (用户的话里出现这些就应激活)

- "我们以前一直这么做，效果挺好的"
- "当年就是靠这个起来的"
- "这个渠道/玩法已经不行了吗"
- "十年前我们试过这个，没成"
- "新的技术会不会把我们颠覆掉"
- "We've always done it this way / fighting the last war"

### 与相邻 skill 的区分

- 与 `mm-path-dependence` 的区别: 路径依赖描述"历史选择约束了今天的选项"，偏结构性、中性；将军总在打上一场仗专指"战术与环境错配"，带有明确的对错判断和竞争后果。
- 与 `mm-disruptive-innovations` 的区别: 颠覆性创新讲的是新进入者从低端/边缘切入的市场机制；本模型讲的是 incumbent 的心理与组织惯性，可以解释为什么被颠覆。
- 与 `mm-inertia` 的区别: 惯性是"维持现状"的泛化倾向；本模型特指"维持的是上一场战争中形成的战术"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别正在被沿用的"上一场战术"**
   - 完成标准: 明确指出用户当前依赖的具体做法（不是笼统的"传统方法"），以及它上一次取得成功的场景。
2. **还原它当年成立的前提**
   - 完成标准: 列出 2-4 条隐含前提（技术条件 / 成本结构 / 对手形态 / 信息速度），每条都要可验证。
3. **逐条核查前提今天是否仍成立**
   - 完成标准: 每条前提给出"仍成立 / 已失效 / 不确定"的判断和依据。
   - 判停条件: 若所有前提仍成立，说明不是"打上一场仗"，应立即退出本 skill 并告知用户不要强行套用。
4. **找出已经改变的规则维度**
   - 完成标准: 明确写出"现在的胜负取决于 X，而不是过去的 Y"。
5. **评估窗口期与行动**
   - 完成标准: 给出对手是否已察觉规则变化的判断，以及据此的时间窗口建议（窗口内该抢什么、窗口关闭后靠什么活）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 环境本身稳定、历史经验仍然有效的例行决策——强行"创新"只是制造成本。
- 用户只是在引用经验作为参考之一，并没有拒绝新信息——此时直接给新信息即可，不需要上升到组织惯性批判。
- 纯粹的个人偏好或审美问题，不存在"环境变了"的客观事实。

### 书中警告的失败模式 / 容易误用的地方

- 作者提醒并非所有领域都适用，同时明确说："反过来，也不要假定一切旧战术都失效。"这是双向的警告。
- （推导, 非书中明示）过度使用会造成"凡是旧的都错"的新偏见：判断必须回到前提核查，而不是"新旧"标签。
- （推导, 非书中明示）识别出规则变化不等于必须立刻全力投入——新规则也可能不成立，需要区分"已验证的规则迁移"与"尚未验证的趋势叙事"。

### 容易混淆的邻近模型

- **路径依赖（path dependence）**: 结构性约束，中性描述；本模型带有战术错配的判断。
- **颠覆性创新（disruptive innovations）**: 描述市场机制；本模型描述在位者的认知惯性。
