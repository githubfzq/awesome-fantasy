# 助推（nudging）

## R — 原文 (Reading)

> 某个精心选择的字眼或其他环境提示都可能形成对你的"助推"。餐馆会通过突出显示菜单上的某些菜肴、让服务员口头描述特色菜或用线条把某些菜品框起来，来"助推"你选择这些菜品。
>
> — 《思维模型》, 第1章 少犯错 > 各持己见

---

## I — 方法论骨架 (Interpretation)

助推指的是：在不禁止任何选项、不显著改变经济激励的前提下，通过改变**选项的呈现方式**来影响人的选择。菜单上被加框的那道菜没有被强制推销，你依然可以点任何东西——但被框起来的那道，点单率会明显上升。

它为什么有效？因为人的判断高度依赖**当下最容易提取的线索**：一个动词的轻重、一个默认值、一个陈列位置，都会被大脑当作"这个选项大概更好/更常见"的暗示。书里引用的经典实验很能说明力度：让被试看同一段交通事故影片，只把提问的动词从"接触"换成"撞碎"，估计的车速就从 31 英里一路升到 41 英里——事实没变，措辞变了，记忆和判断就跟着变了。

需要区分的是，助推不都是坏的：把健康食品放在视线齐平处、把退休金默认设为"加入"，都是助推。判断它是否有问题，看的不是"有没有影响"，而是**影响的方向是否服务于被推者的利益，以及他能否低成本地退出**。

判据：**我的这个选择，是出于自己的判断，还是被某个措辞/陈列/默认值轻轻推了一下？**

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. **感到自己"莫名其妙选了某个选项"**：订阅自动续费、接受了默认配置、买了原本没计划买的东西。
2. **设计产品/表单/页面的默认项与排序**：注册流程、隐私设置、套餐推荐位。
3. **撰写会影响他人判断的文案或问卷**：调研问题措辞、汇报材料的表述、合同条款的强调方式。
4. **评估别人给你的方案**：报价单的排序、议程里被放在第一位的议题、被"特别推荐"的选项。
5. **线下陈列与话术设计**：门店货架、菜单、服务员的口头推荐（推导, 非书中明示）。

### 语言信号
- "我也不知道为什么就点了那个"
- "默认就是这个，我就没改"
- "他们把这个放在最显眼的位置"
- "换个说法，你会怎么回答？"
- "怎么让用户更多地选择××"
- "Why did I end up picking that option?" / "Does the wording change the answer?"

### 与相邻 skill 的区分
- 与 `mm-default-effect` 的区别: 默认效应特指**预先勾选的那一项**具有强大惯性，是助推的一种具体手段；助推是更大的范畴，包含措辞、排序、陈列、社会提示等全部"轻推"手法。
- 与 `mm-framing` 的区别: 框架效应改变的是**同一选项的描述方式**（90% 成功 vs 10% 失败），影响对它的评价；助推改变的是**选项环境本身**（放哪里、勾哪个、说不说）。二者常叠加使用。
- 与 `mm-dark-patterns` 的区别: 黑暗模式是**用欺骗或阻碍退出来操纵用户**（隐藏取消入口、假紧迫感），已经越过了助推"不限制自由"的界线。判断标准：被推者能否低成本退出。

## E — 可执行步骤 (Execution)

1. **还原这个决定发生时的"选项环境"**
   - 完成标准: 写出做决定时实际呈现的全部元素——有哪些选项、默认是谁、怎么排序、用了什么措辞、谁在旁边说了什么。
2. **逐条摘出其中的提示元素并做"去除测试"**
   - 完成标准: 对每个元素问"去掉/改掉它，我的选择会变吗？"，标注出真正产生推力 1-3 个元素。
   - 判停条件: 若去掉全部提示后选择不变，说明这是真实偏好，退出本 skill，不要硬套。
3. **判断助推的方向与可退出性**
   - 完成标准: 对每个有力元素给出两个判定：(a) 它服务的利益方是谁——被推者还是设计者；(b) 被推者退出的成本有多高（点一下 / 找客服 / 几乎不可能）。
   - 判停条件: 若退出成本被判定为"高"且服务的是设计者利益，转 `mm-dark-patterns`，不再按助推中性处理。
4. **给出应对或设计建议**
   - 完成标准: 若用户在**防守**，给出"重置为默认前先逐项确认""换个表述重问自己一遍"的具体动作；若用户在**设计**，给出保留退出自由、方向对被推者有利的具体改法。

---

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- **存在强迫或实质限制时**：不给退路、不给选项的设计不是助推，是操控，应按黑暗模式或强制处理。
- **选择结果来自真实偏好**：不是所有"被影响"都是助推，别把用户自己的决定都归因于设计。

### 容易误用的地方
- **书中未给边界**。以下基于机制推导：
- （推导, 非书中明示）**把助推当作万能解释**："我买这个是商家助推的"有时会变成不为自己决定负责的借口。
- （推导, 非书中明示）**忽视助推的伦理方向**：同样的方法可以用来帮用户做长期有利的选择，也可以用来掏空他们的钱包；技术中立，用途不中立。
- （推导, 非书中明示）**在调研/汇报中无意使用带推力的措辞**：问"您有多满意"和"您有什么不满意"，得到的分布会完全不同，这是最常见的无意识误用。
