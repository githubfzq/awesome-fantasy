# 离群值（outliers）

## R — 原文 (Reading)

> 在得出区间之前，你应该先寻找离群值（outliers），也就是看起来与其他数值格格不入的数据点

> — 《思维模型》, 第5章 > 钟形曲线

---

## I — 方法论骨架 (Interpretation)

离群值是"看起来与其他数值格格不入的数据点"。这句话的重点在"看起来"——它是一个**需要你做出判断的信号**，不是一个可以自动执行的删除指令。

为什么必须先处理它？因为它对汇总统计量的破坏力极大：一个极端值会大幅拉伸区间、拉走均值、撑大标准差。你辛辛苦苦算出来的"正常范围是 96.3–100.0"，可能只是被那一个点撑开的假象。所以书里给的顺序是硬的：**先找离群值，再得区间**。

关键判断是二分：**它是错误，还是真实现象？**

- 是错误：书里的例子是体温数据集里 100.8 华氏度那个点——"也许是某个病人（的数据）偷偷溜进了这个数据集"。病人混进健康人样本，这是采样错误，剔除它才能还原健康人群的真实区间（剔除后为 96.3–100.0）。
- 是真实现象：那它就是数据里最重要的信息，剔除等于自废武功。

判据：追问**这个点是怎么来的**。如果能找到明确的机制解释（录入错了一个零、传感器掉线、非目标群体混入），它就是错误；如果找不到，默认按真实现象处理，因为删掉无法解释的东西等于删掉你还没理解的部分。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户准备算"正常范围/参考区间/置信区间"，数据里存在一个或几个明显偏离的值。
2. 用户的报表或模型被个别极端订单、极端用户、极端请求严重扭曲。
3. 用户发现监控曲线上有个毛刺，在判断要不要把它算进 SLA 统计。
4. 用户在清洗数据集，纠结"去掉最大值和最小值"这个常见做法是否合理。

### 语言信号

- "这个值明显不对劲，能删吗？"
- "去掉最大最小再算平均行不行？"
- "我们的正常区间应该定在哪？"
- "会不会是病人混进健康人样本了？"
- "这个订单金额比别的大 100 倍。"
- "outliers" / "should I remove this data point?" / "anomaly"

### 与相邻 skill 的区分

- 与 `mm-mean` 的区别: 均值是**被离群值影响的对象**；离群值是**原因**。处理顺序是先识别离群值，再决定均值能不能用。
- 与 `mm-selection-bias` 的区别: 选择性偏差讲的是"进入样本的方式有偏"（谁被选进来了）；离群值讲的是"进来的这批里有个点格格不入"。一个是入口问题，一个是内部问题。
- 与 `mm-standard-deviation` 的区别: 标准差会被离群值撑大，正如均值被拉走；离群值处理是这两者的前置步骤，不是与之并列的统计量。

## E — 可执行步骤 (Execution)

1. **先可视化再下判断** — 完成标准: 把数据画出来（散点/直方图），肉眼确认哪些点格格不入，而不是只看最大最小值。
2. **追问这个点的来源** — 完成标准: 对每一个候选离群值，能说出它的产生机制（录入、单位错误、混入样本、真实事件）；说不出机制的，标记为"来源不明"。
3. **按机制分类处置** — 完成标准: 明确归为三类之一——(a) 确认错误 → 剔除或修正；(b) 来源不明 → 保留并标注；(c) 真实现象 → 保留且在结论中单独说明。
4. **重算区间并对比影响** — 完成标准: 给出剔除前/后两套区间（书中剔除后为 96.3–100.0 华氏度），量化这一个点的影响幅度。
5. **把规则写进流程** — 完成标准: 形成一条可复用的判定规则（如"超过均值 ±3σ 且能在日志中找到错误来源的才剔除"），避免每次凭感觉删。

---

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- **只是为了得到一个更好看的数字**: 如果动机是"去掉它我的指标就达标了"，那这个 skill 正在被当成美化工具，而不是清洗工具。
- **样本量极小（如 n<10）时**: 每个点都至关重要，此时"格格不入"往往是样本量不足的表现，不是数据质量问题。

### 容易误用的地方

- **默认剔除**: 书中只给出了剔除的例子（体温数据集 100.8 度那个点），并**未讨论何时应当保留离群值**；因此"来源不明就保留"这一条是蒸馏时补全的推论，不是书中主张。（部分推导, 非书中明示）
- **反复剔除直到数据好看**: 每剔除一次，剩下的"最极端值"又会成为新的离群值，循环下去会把分布削成自己想要的样子。（推导, 非书中明示）
