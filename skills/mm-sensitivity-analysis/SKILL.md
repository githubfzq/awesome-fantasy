# 敏感性分析（sensitivity analysis）

## R — 原文 (Reading)

> 这是一种非常实用的方法，用于分析模型对输入参数的敏感程度。
>
> — 《思维模型》, 第6章 > 权衡成本与收益

---

## I — 方法论骨架 (Interpretation)

任何量化结论都建立在若干输入数字上,而这些数字多半是估的。敏感性分析把问题从"我猜的数字准不准"换成了更有用的"**这个数字错了会不会改变结论**"——前者无解,后者可算。

做法:固定其他一切,只改动一个输入参数,看结果怎么变。三个用途:一是给出净收益的合理区间,而不是一个假装精确的孤零零数字;二是给难以定价的无形因素测权重(比如"不用跟房东打交道"到底值多少钱,可以反推它要多大才能让结论翻转);三是快速找出关键驱动因素,从而知道该把有限的精力花在核实哪个假设上——大多数模型里,真正左右结论的只有一两个参数。

书中的债券例子最直观:只改折现率这一个参数,6% 时净收益 5839 美元,4% 时大幅上升,8% 时变成负数。泳池例子则改概率:3000 美元账单的概率从 5% 改成 50%,最优选项直接翻转。作者还把蒙特卡洛模拟称为"动态的敏感性分析"——一次性让所有参数同时随机波动。

关键判据:**找出那个让结论翻转的临界值**,然后判断这个临界值是否落在合理区间内。落在区间内,说明决策本身很脆弱,需要先去核实;落在区间外很远,说明你可以放心行动。

---

## A1 — 书中的应用 (Past Application)

### 案例: 债券的折现率与泳池维修的概率

- **问题**: 债券案例里净收益 5839 美元这个结论可靠吗?泳池案例里"选新承包商"这个结论可靠吗?两者的输入都是估的。
- **方法论的使用**: 作者在债券案例里只改动折现率一个参数——6% 时净收益 5839 美元,4% 时大幅上升,8% 时变负数;在泳池案例里只改动概率——3000 美元账单出现的概率从 5% 提高到 50%,最优选择立刻翻转。
- **结论**: 结论的稳健性由个别参数决定。必须逐个参数施压,才能知道这个决策到底是"算清楚了"还是"被某个猜测撑着"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户刚做完成本收益分析或决策树,算出净收益 5839 美元这类精确数字,准备据此行动——此时必须先问"这个数字有多脆"。
2. 用户面临两个选项,算出来的差距很小(比如 2200 vs 2500),想知道这点差距值不值得纠结。
3. 用户不知道该优先核实哪个假设:时间有限,只能去查一件事。
4. 用户要给别人汇报一个估算,需要给出区间而不是单点,否则一旦偏差就被全盘否定。

### 语言信号 (用户的话里出现这些就应激活)

- "这个数字是我估的,不知道准不准"
- "如果实际情况比这差一倍,结论还成立吗"
- "最坏能坏到哪 / 最好能好到哪"
- "两个方案差得不多,选哪个都行吧"
- "我该先去核实哪个数据"
- "how sensitive is this to..." / "what if the estimate is off?"

### 与相邻 skill 的区分

- 与 `mm-cost-benefit-analysis` 的区别: 成本收益分析负责**算出**净收益,敏感性分析负责**检验**这个净收益有多可靠;两者是同一流程的先后两步,本章要点明确要求对所有输入做敏感性分析。
- 与 `mm-monte-carlo-simulation` 的区别: 蒙特卡洛是让所有参数同时随机波动的"动态敏感性分析",适合参数多且互相作用;本 skill 是单参数逐个施压,适合快速定位关键驱动因素。
- 与 `mm-confidence-interval` 的区别: 置信区间描述**统计抽样**带来的不确定性,敏感性分析描述**你对输入的主观猜测**带来的不确定性;前者可算,后者只能靠改数字试。

## E — 可执行步骤 (Execution)

1. **列出模型的全部输入参数并标记可信度**
   - 完成标准: 每个输入都标注是"已知的"(报价、税率)还是"猜的"(概率、折现率、无形因素估值)。
   - 判停条件: 若一个量化模型都还没有,先回到成本收益分析或决策树,本 skill 无法凭空运行。
2. **逐个施压并记录结果**
   - 完成标准: 每次只改一个参数(其余固定),在合理区间内取低/中/高三档,记录每个档位下结果是多少、结论是否翻转。
3. **定位临界值与关键驱动因素**
   - 完成标准: 对每个关键参数给出"结论翻转的临界值";按影响力排序,明确指出哪 1-2 个参数真正左右结论。
   - 判停条件: 若排序后没有哪个参数能翻转结论,直接跳到步骤 5 并说明"这个决策很稳健,可以行动"。
4. **把精力投向关键参数**
   - 完成标准: 给出一条具体动作——去核实那个排名第一的参数(问谁、查什么、做个小实验),并说明核实后重算的流程。
5. **输出区间而非单点**
   - 完成标准: 最终结论以"净收益大约在 X 到 Y 之间,在 Z 条件下会翻转"的形式给出,并写明哪些输入尚未核实。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 还没有任何量化模型、仍处于定性权衡阶段——先把框架搭起来。
- 输入参数全部是确凿事实(如税率、合同价、已发生的历史成本)——施压没有意义。
- 用它替代对输入的核实:敏感性分析告诉你"该查哪个",不能代替真的去查。(推导,非书中明示)

### 书中警告的失败模式 / 容易误用的地方

- 书中未给出边界,但明确强调它是成本收益分析不可或缺的一步——本章要点直接要求"对所有输入的数据进行敏感性分析"。(书中明示)
- 只改一个参数会掩盖参数之间的联动;参数多且相关时,单参数分析会低估风险,应升级为蒙特卡洛模拟。(推导,非书中明示)
- 常见误用是只对"看起来不确定"的参数施压,却漏掉那个看起来确定、其实只是大家都默认的参数(如折现率)。(推导,非书中明示)

### 容易混淆的邻近模型

- 与情景分析(scenario-analysis): 情景分析是构造几套自洽的未来图景,敏感性分析是机械地拨动单个数字;前者改的是世界观,后者改的是参数。
- 与误差范围(margin-of-error): 误差范围是数据本身的统计属性,敏感性分析是你主动施加的压力测试。
