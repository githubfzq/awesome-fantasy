# 熵（entropy）

## R — 原文 (Reading)

> 这个概念用于衡量一个系统的无序程度。
>
> — 《思维模型》, 第4章 > 从混沌到有序

---

## I — 方法论骨架 (Interpretation)

熵衡量一个系统的无序程度。这句话听起来抽象，但书里给了一个极其好用的操作化方式：**看"每样东西能放的位置"有多少种选择**。

一个干净的房间有严格规定——每样东西该放哪里——可选的摆放方式很少，熵的最大值就小；一旦你允许衣服摊在地上，可选的摆放方式骤增，系统的最大熵显著上升。所以熵的上限不由当前状态决定，而由**规则有多松**决定。

这个视角带来两个重要推论。

第一，**秩序需要持续投入能量维持，混乱则自然入侵**。维持有序是逆熵过程，一旦停止投入，系统会自发滑向无序。这解释了为什么整理过的房间、代码库、文档、流程都会自动变乱——不是因为谁不负责任，而是因为没有持续投入。

第二，也是书中最反直觉的一点：**有限度的无序是好事**。严格的规定把熵压得很低，但也把可能性压缩掉了；松一点，系统可能处于的状态更多，撞上有利状态的概率就更大——这正是熵与幸运表面积的连接：增加你可能遇到的情况数量，就是提高熵的最大值。

所以判据不是"越有序越好"，而是"这个系统的最大熵应该被设在哪里"。熵太多只会酿成混乱；熵太少则失去机遇与韧性。作者的建议是置身于秩序与混乱之间，有意识地提升个人熵值以接触机遇，同时保有足够韧性与灵活性。

## A1 — 书中的应用 (Past Application)

### 案例: 两个"熵的制造者"

- **问题**: 作者家里为什么总是乱？
- **方法论的使用**: 作者戏称两个孩子是"熵的制造者"——他们不按规矩放东西，屋里每件物品的可选位置极多，熵的最大值极高。
- **结论**: 最终衣服玩具随处可见、接近完全随机分布。这不是孩子"懒"，而是规则松 → 最大熵高 → 系统自然滑向高熵状态的必然结果。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户困惑于"为什么刚整理好又乱了"（代码库、文档、桌面、流程）——需要指出这是自然趋势，解法是降低最大熵（收紧规则）而非一次性整理。
2. 用户的组织/日程/流程过于僵化，失去了创新与应变空间——需要有意提高最大熵，给系统留出状态空间。
3. 用户在权衡"要不要立规矩"（团队规范、文件命名、代码风格）——需要判断这条规矩会把最大熵压到多少、代价是什么。
4. 用户想理解"为什么留白和随机接触有价值"——需要用熵与可能性数量的关系来解释。

### 语言信号 (用户的话里出现这些就应激活)

- "刚整理完没两天又乱了。"
- "规矩是不是定得太死了？"
- "要不要给这个流程加一条硬性规定？"
- "我的日程排得太满，一点弹性都没有。"
- "Everything falls apart as soon as I stop maintaining it."
- "Are our rules too rigid?"

### 与相邻 skill 的区分

- 与 `mm-luck-surface-area` 的区别: 熵是**底层物理量**（系统可能状态数的度量）；幸运表面积是熵在"撞上机遇"这个具体场景下的应用。提高最大熵可以同时提高机遇概率和混乱程度，是一体两面。
- 与 `mm-second-law-of-thermodynamics` 的区别: 热力学第二定律讲的是"孤立系统的熵必然增加"这一**方向性规律**；熵本身是**状态量**（衡量无序程度）。前者解释"为什么必然变乱"，后者用于"现在有多乱、上限能有多高"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定义系统边界与"东西"**
   - 问：这个系统里的元素是什么（文件、任务、物品、人）？它们的"位置"或"状态"由什么规则决定？
   - 完成标准: 明确列出系统边界与元素类型。
2. **估算当前最大熵**
   - 问：现有规则下，元素一共有多少种合法摆放/状态？规则越松，这个数字越大。
   - 完成标准: 给出定性判断（低/中/高）及依据（哪条规则最松或最紧）。
3. **判断该升还是该降**
   - 若系统已经混乱到无法工作 → 该降；若系统僵化、缺乏机遇与弹性 → 该升；若两者兼有 → 分区处理（核心区严格、探索区宽松）。
   - 完成标准: 给出明确方向，若是分区处理则划出核心区与探索区。
4. **调整规则而非一次性整理**
   - 降熵：收紧规则（固定位置、强制命名、自动化检查）。升熵：放宽规则、刻意留白、引入随机接触。
   - 完成标准: 给出 1-3 条规则层面的改动，并说明它如何改变最大熵。
   - 判停条件: 若用户只是要一次性的整理方法（不涉及规则设计），明确告知一次整理不改最大熵、必然复发，再进入步骤 4。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 真正的热力学工程计算——这里是类比用法，不是精确的统计量。
- 把它当可测量的 KPI（"我们的熵是 3.7"）——书中给的是定性框架。
- 安全关键或合规强约束的场景——那里必须压低熵，不能"留白"。

### 书中警告的失败模式 / 容易误用的地方

- 熵太多只会酿成混乱。（书中明示）
- 秩序需要持续投入能量维持，否则混乱自然入侵——不要指望"整理一次永久有效"。（书中明示）
- 作者建议置身于秩序与混乱之间，有意识地提升个人熵值以接触机遇，同时保有足够韧性与灵活性。（书中明示）

### 容易混淆的邻近模型

- 与**热力学第二定律**: 见 A2 区分——状态量 vs. 方向性规律。
- 与**幸运表面积**: 底层量 vs. 具体应用。
