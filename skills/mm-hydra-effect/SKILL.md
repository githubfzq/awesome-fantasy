# 九头蛇效应（hydra effect）

## R — 原文 (Reading)

> 另一个需要注意的相关模型是九头蛇效应（hydra effect）。这个模型得名于勒拿九头蛇（Lernaean Hydra），希腊神话中的一种怪兽，每砍掉一个脑袋就会长出两个。
>
> — 《思维模型》, 第2章 > 许愿须谨慎

---

## I — 方法论骨架 (Interpretation)

九头蛇效应描述的是：每移除一个问题源头，就会冒出更多替代者，问题不但没解决，反而扩散了。

它的成因是**只打击供给侧而需求侧未变**。需求还在，被清除的位置就成了一个空缺的生态位，必然会被新进入者填补；而且由于前一位被清除留下的"教训"，新进入者往往更隐蔽、更分散、数量也更多。书中给的例子是：每逮捕一名毒贩，为满足毒品需求，很快就会有另一名毒贩取而代之。

判据非常清楚：**你打击的是"角色"，还是"产生这个角色的需求"？** 打掉某个毒贩，是在打角色；毒品需求不变，下一个毒贩必然出现。同理，封掉一批违规账号，只要违规能带来的收益和进入成本的结构没变，新账号就会持续注册。

它和眼镜蛇效应容易混：眼镜蛇效应的放大来自**激励扭曲**（有人开始主动生产问题），九头蛇效应的再生来自**系统补偿**（空缺被填补）。前者要改激励结构，后者要么消除需求、要么把进入成本抬到高于收益。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 黑产/刷单/作弊账号治理：封了一批又来一批。
2. 渠道或商家整顿：清退之后冒出更多小散玩家，更难管。
3. 组织内反复出现的岗位或流程问题：换人/砍团队后问题照旧。
4. 竞品围堵：打掉一个对手，市场上出现更多对手。
5. 评估"加大打击力度"是否能终结问题，还是只是加速换血。

### 语言信号
- "封了一批，又冒出来一批"
- "打不完，怎么都打不完"
- "换个马甲又来了"
- "越打越多，是不是我们力度不够"
- "清退之后反而更分散了"
- "hydra effect / whack-a-mole / they keep coming back"

### 与相邻 skill 的区分
- 与 `mm-cobra-effect` 的区别: 眼镜蛇效应是**激励扭曲**导致有人主动生产问题（养蛇领赏金），九头蛇效应是**系统补偿**——需求不变导致空缺生态位被填补；前者要改激励，后者要改需求或进入成本。
- 与 `mm-perverse-incentives` 的区别: 不当诱因聚焦被诱导出的有害行为，本 skill 的再生不是激励诱导的，而是需求侧的拉力造成的。
- 与 `mm-streisand-effect` 的区别: 史翠珊效应放大的是**关注度**（遮盖使更多人看见），本 skill 放大的是**实际数量**（源头真的变多了）。
- 与 `mm-war-of-attrition` 的区别: 消耗战是一种策略选择（比谁耗得起），本 skill 是判断这种消耗是否会有终点的模型——需求不变时消耗战没有终点。

## E — 可执行步骤 (Execution)

1. **确认问题是"再生型"还是"一次性"**
   - 看三条：源头数量是否随打击次数上升？新源头的出现间隔是否在缩短？形态是否更分散更隐蔽？
   - 完成标准: 三条中至少 2 条成立判定为再生型。
   - 判停条件: 若是一次性事件或彼此独立，退出本 skill。
2. **定位持续存在的需求侧**
   - 问：谁在为此付费/获利？这个收益有多大？
   - 完成标准: 写出"需求方 + 单位收益"，且收益必须是具体数字或量级。
3. **测算进入成本与收益的对比**
   - 计算：新进入者要付出的成本（注册、设备、被抓风险折现）vs 预期收益。
   - 完成标准: 得到一个明确的比值；只要收益高于成本，再生就不会停止。
4. **决定主攻方向：抬成本还是削需求**
   - 抬成本：提高注册与验证门槛、设备指纹与连坐、延长收益兑现周期、提高处罚确定性（比提高处罚力度更有效）。
   - 削需求：让需求方无法获益（如刷单的流量不再计入推荐、假评不影响排序）。
   - 完成标准: 选定一条主线，并说明为什么另一条不可行；优先选削需求。
5. **设计"不依赖持续打击"的收口机制**
   - 完成标准: 写清当打击停止后，靠什么机制让问题不反弹。
6. **设定终止判据**
   - 完成标准: 明确"到什么指标就算赢"（如新源头出现率低于某阈值并持续 N 周），以及"到什么程度就承认此路不通并换策略"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 需求可以被一次性消除的问题（如一个错误的默认值、一个已修复的漏洞）：修掉就结束了，不存在再生。
- 多起事件彼此独立、没有共同的需求侧：那是巧合或统计波动，不是九头蛇（推导，非书中明示）。
- 打击是法律与合规义务时：即使知道会再生也必须执行，本 skill 只用于补充设计配套机制（推导，非书中明示）。

### 容易误用的地方
- 最常见的误用是把再生当成"力度不够"，于是加大打击——书中案例（逮捕毒贩）表明，只要需求不变，加大力度只是加速换血，还可能让新进入者更分散更难管（推导，非书中明示）。
- 提高处罚**力度**不如提高处罚**确定性**：被抓概率低时，再重的惩罚也压不住再生（推导，非书中明示）。
- 只看到打掉的那一侧：判据始终是"需求方还在不在、还在不在赚钱"，没算清这一侧就谈治理方案是本末倒置（推导，非书中明示）。
