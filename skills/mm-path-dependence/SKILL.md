# 路径依赖（path dependence）

## R — 原文 (Reading)

> 来自经济学的模型"路径依赖"（path dependence）探讨了这种影响。所谓的"路径依赖"是指，你现在可用的决策或路径取决于你过去的决策。
>
> — 《思维模型》, 第2章 > 越来越热

---

## I — 方法论骨架 (Interpretation)

路径依赖说的是：你此刻的选项清单，是被过去的选择塑造过的。不是所有可能性都还在桌上，有些门在很久以前就被无声地关上了。

它的机制是**积累物造成切换成本**。一个当初随手选的项目管理软件，随着公司成长被越来越多的人使用、数据全部存在里面，此时"换成更好的"就不再是一个软件问题，而是一个包含数据迁移、流程重造、全员重学的巨大工程。切换成本（迁移数据、重学技能、搬迁）越高，路径越接近不可逆。

它会与债务模型叠加放大：欠的债越多，灵活性就越差，可选路径就越少。技术负债、地理定居、职业方向，都会把未来的选项一点点收窄。

最危险的地方在于，作者提醒最初的决定"乍看起来似乎没有害处"。正因为早期选择看起来成本低、不值得花精力，人们才随手决定；而恰恰是这些低关注度的选择，会随着规模与数据的积累变成最难更改的部分。

判据很简单：**是否存在"越用越难换"的积累物**——数据、技能、地理、关系、流程。只要有，这个选择就带有路径依赖。

---

## A1 — 书中的应用 (Past Application)

### 案例: 随手选的项目管理软件、毕业留下的城市、扎堆的珠宝店

- **问题**: 公司刚起步时"随手选"的项目管理软件，随着公司成长被大量人使用、数据全存在里面，此时换软件极其麻烦。类似的，许多人毕业后留在上学的城市，这个看似自然的决定长远影响了职业道路与家庭选择。
- **方法论的使用**: 作者指出这些例子的共同结构：最初的决定"乍看起来似乎没有害处"，但随着使用规模与积累物（数据、关系、地理、技能）的增长，切换成本不断上升，最终把后续选项锁定。作者还举了商业地理的例子：珠宝店、家具店、汽车经销店倾向于扎堆聚集，先开的店为后开的店创造了可以依赖的路径。
- **结论**: 要特别警惕低成本、低关注度的早期选择——正是因为它们看起来不重要，才最容易在不经意间关上未来的门。判断标准是看有没有"越用越难换"的积累物。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 做一个看起来不起眼的选型：工具、云服务、数据格式、编码规范、供应商、框架。
2. 纠结要不要换：明知现有方案不如另一个，但迁移成本让人犹豫。
3. 决定长期承诺前：定居城市、加入早期公司、选定职业方向、签署长约。
4. 解释组织僵化：为什么"谁都知道该改，但就是改不动"。
5. 评估一个早期决策的长期影响：这件事三年后会不会把我锁死。

### 语言信号 (用户的话里出现这些就应激活)

- "当初随手选的，现在全公司都在用"
- "数据都在里面，换不动了"
- "其实有更好的，但迁移太贵"
- "先定下来吧，以后再说"
- "大家都在这行干了十年了，转不了"
- "path dependence / lock-in / switching cost / migration is too expensive"

### 与相邻 skill 的区分

- 与 `mm-preserving-optionality` 的区别: 路径依赖描述"选项被过去锁定"这一**约束**，保留可能性是应对它的**策略**（刻意保留未来选择权）。前者是诊断，后者是对策；两者要平衡使用，不能只讲一边。
- 与 `mm-switching-costs` 的区别: 转换成本是路径依赖的**成因量化**（换一次要花多少），路径依赖是结果状态（可选路径变窄）。评估"能不能换"用转换成本，理解"为什么选项越来越少"用路径依赖。
- 与 `mm-sunk-cost-fallacy` 的区别: 沉没成本谬误是**认知错误**（因为已经投入所以不愿放弃，即使放弃更好），路径依赖是**客观约束**（放弃确实要付出真实的迁移代价）。前者的正确做法是忽略已投入，后者的正确做法是认真计算迁移成本。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别积累物**
   - 列出这个选择会随时间积累什么：数据、技能、关系、地理、流程、品牌。
   - 完成标准: 至少 2 项积累物，并说明它们如何随时间增长。
   - 判停条件: 若没有积累物（如一次性的、不留痕迹的选择），停止本 skill。
2. **估算三年后的切换成本**
   - 对每项积累物估算迁移代价：迁移数据、重学技能、重建关系、搬迁。
   - 完成标准: 得到一个量级估计（人天/金额/月数）与主要成本来源。
3. **判断这是客观锁定还是心理锁定**
   - 关键区分：迁移成本是真实存在的，还是"已经投入了舍不得"（沉没成本）？
   - 完成标准: 明确归类；若是沉没成本谬误，转 `mm-sunk-cost-fallacy`。
4. **检查是否叠加了债务**
   - 问：这条路径上还欠着什么债（技术债、管理债、承诺）？债务会进一步压缩选项。
   - 完成标准: 列出叠加的债务项。
5. **给出"提前保留出口"的具体安排**
   - 手段：选择开放标准/可导出格式、抽象层隔离供应商、保持技能可迁移、设定期限性承诺、明确记录"若 X 发生则切换"。
   - 完成标准: 至少 2 条出口设计，每条写明它降低了哪一项切换成本。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 切换成本极低、可随时反悔的选择（如选哪家咖啡店）：不构成路径依赖。
- 只是"舍不得已投入"而没有真实迁移成本：那是沉没成本谬误，用错模型会让人误以为锁定是客观的。
- 选择本身已经做完且不可逆、用户在寻求心理安慰时：此时应转向如何在既有路径上优化（推导，非书中明示）。

### 书中警告的失败模式 / 容易误用的地方

- 作者提醒最初的决定"乍看起来似乎没有害处"，所以要特别警惕低成本、低关注度的早期选择——这是书中明示的核心警告。最大的风险恰恰来自"不值得花时间挑"的那类决定。
- 容易把路径依赖当成沉没成本，从而强行切换或强行坚持：必须先分清客观迁移成本与心理不舍（推导，非书中明示）。
- 它与债务叠加后会显著压缩灵活性，因此欠债时更要留意是否同时锁死了出口（推导，非书中明示）。

### 容易混淆的邻近模型

- 与沉没成本谬误：最常被混淆。判据是"放弃是否真的要付出代价"——真要付 → 路径依赖；不用付只是舍不得 → 沉没成本谬误。
- 与保留可能性：一枚硬币的两面。保留可能性是对冲路径依赖的手段，但过度保留本身有成本（见该 skill 的边界）。
