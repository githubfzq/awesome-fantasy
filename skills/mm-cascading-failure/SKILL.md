# 连锁故障（cascading failure）

## R — 原文 (Reading)

> 这个概念是指，系统中某一部分的故障会引发波及整个系统的连锁反应。
>
> — 《思维模型》, 第4章 > 利用链式反应

---

## I — 方法论骨架 (Interpretation)

连锁故障的核心机制是**过载的转移**：系统中某一部分失效后，它原本承担的责任并没有消失，而是被转移给相邻部分；相邻部分因此超出自身容量而过载，再把负担传给更远的邻居。如此逐级放大，一个局部事件最终波及整个系统。

这个机制解释了为什么"每个部件都单独测过没问题"的系统仍然会整体崩溃——问题不在部件强度，而在**耦合结构**：部件之间承担了彼此的溢出负荷，却没有预留余量。

判据是三条，满足越多越危险：一，部件之间存在负载转移路径（一个挂了别的要顶上）；二，被转移方没有足够冗余；三，失效会改变系统结构本身（而不只是减少容量）。

在生物系统中，这个模型表现为食物链上的连带灭绝——一个物种消失，依赖它的物种随之消失。书中特别提到单食性依赖（熊猫与竹子、考拉与桉树叶）是极端脆弱的结构。

值得注意的是，作者指出这不完全是坏事：这些都是自然法则，就看你用在什么地方。核临界量既可用于相对安全的核能，也可能导致灾难性的核冬天——同一个机制，方向取决于设计。

## A1 — 书中的应用 (Past Application)

### 案例: 电网大型断电

- **问题**: 为什么一个区域的电力故障会演变成大面积停电？
- **方法论的使用**: 一个区域过载后，其负荷自动转移到相邻区域线路，触发相邻区域过载，依此类推逐级放大。
- **结论**: 故障不是"扩散"而是"转移"——每一级的负荷都集中到幸存部分，直到它们也崩溃。

### 案例: 2007—2008 年金融危机

- **问题**: 次级抵押贷款这一相对局部的市场，如何演变成全球危机？
- **方法论的使用**: 次级抵押贷款崩溃 → 持有相关资产的机构受损 → 通过衍生品与同业敞口传导 → 最终拖垮重要金融机构。
- **结论**: 金融机构之间的高度耦合，把一个细分市场的坏账放大成系统性崩溃。

### 案例: 珊瑚礁消失

- **问题**: 珊瑚礁消失后为什么大量物种一起消失？
- **方法论的使用**: 依赖珊瑚礁生存的物种失去了唯一栖息与觅食结构，形成食物链上的连带灭绝。
- **结论**: 单向、高依赖的结构（类似熊猫与竹子、考拉与桉树叶）没有替代路径，是连锁故障最脆弱的形态。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户刚经历或正在复盘一次事故（服务雪崩、线上故障、项目崩盘），想理解"为什么一个小问题闹这么大"——需要还原过载转移链路。
2. 用户在做架构/流程/供应链设计，想知道"哪里该加熔断、哪里该加冗余"——需要识别负载转移路径。
3. 用户在评估组织的单点依赖（只有一个懂某系统的人、只有一个大客户、只有一个供应商）——需要用连带灭绝的视角看单向依赖。
4. 用户在做风险预案，想知道"最坏会波及到哪一步"——需要划定爆炸半径。

### 语言信号 (用户的话里出现这些就应激活)

- "一个服务挂了，结果全站都不可用了。"
- "为什么一个小故障会闹成这么大的事故？"
- "我们是不是过度依赖某一个供应商/客户/人？"
- "该在哪里加熔断和隔离？"
- "One service went down and took everything with it."
- "What's the blast radius if this fails?"

### 与相邻 skill 的区分

- 与 `mm-domino-effect` 的区别: 多米诺效应强调**顺序触发**（A 倒下直接推倒 B），连锁故障强调**负荷转移与过载**（A 的责任压到 B 上，B 因此超出容量）。前者是"推倒"，后者是"压垮"。
- 与 `mm-chain-reaction` 的区别: 链式反应是中性甚至可资利用的自持过程（核能、信息扩散）；连锁故障特指**破坏性**的传导，关注的是如何阻止而非如何引发。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **画出负载转移图**
   - 列出：如果 X 失效，它的负载/责任会转移到谁身上？
   - 完成标准: 对每个关键部件写出至少 1 个承接方。若某部件失效后无人承接且无影响，标记为"安全孤岛"。
2. **标注冗余余量**
   - 对每条转移路径问：承接方能不能扛住 X 的全部负载？余量有多大？
   - 完成标准: 每条路径标注"够/不够/临界"，标出所有余量不足的承接点。
3. **定位单食性依赖**
   - 找出没有任何替代路径的节点（唯一供应商、唯一专家、唯一收入来源、唯一栖息地）。
   - 完成标准: 列出全部单食性依赖节点。
4. **设计阻断措施**
   - 对每个高风险转移路径给出具体阻断：熔断、限流、降级、冗余、解耦、隔离舱。
   - 完成标准: 每个高风险点至少 1 个可落地的阻断措施，并标明代价。
   - 判停条件: 若事故正在进行中，先执行 `mm-stop-the-bleeding`（止血），回溯分析放到事后。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 孤立的单点故障（一个不联网的工具坏了）——没有转移路径，不会级联。
- 事故正在发生、需要立即处置时——先止血，模型分析放到复盘。
- 高度冗余、已充分解耦的系统——过度分析会把资源浪费在不会发生的级联上。

### 书中警告的失败模式 / 容易误用的地方

- 作者指出这不完全是坏事——这些都是自然法则，就看你用在什么地方：核临界量既可用于相对安全的核能，也可能导致灾难性的核冬天。（书中明示）
- 最常见的误用是只加固部件而不解耦：把每个服务都做得更结实，但负荷仍会转移，级联照样发生。（推导，非书中明示）

### 容易混淆的邻近模型

- 与**多米诺效应**: 见 A2 区分——顺序推倒 vs. 过载压垮。
- 与**链式反应**: 中性/可利用于方向 vs. 破坏性/需阻断。
