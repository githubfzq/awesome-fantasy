# 五问法（5 Whys）

## R — 原文 (Reading)

> 事后分析中常用的一种技巧被称为"五问法"（5 Whys）。你需要反复提问："为什么会发生这种事？"直到找出根本原因。
>
> — 《思维模型》, 第1章 少犯错 > 别相信直觉

---

## I — 方法论骨架 (Interpretation)

操作极简：对每一层答案再问一次"为什么会发生"，把上一层的答案当作下一层的问题起点。

> 现象 → 为什么？→ 答案₁ → 为什么？→ 答案₂ → …… → 根本原因

它的作用是**对抗停留在表层的本能**。人对"为什么"的默认回答，总是取时序上最近、最具体、最容易看见的那个动作（"他点错了""密封接缝破了"）。这个答案通常没错，但它只是链条的第一环。每追问一次，就把解释从"谁做了什么"推向"什么样的条件让他做得出来"。

为什么有效？因为**每一层答案同时是一个新问题的起点**，而人的直觉只会给第一层。强制追问把注意力从"人"逐步转移到"流程、条件、结构"上。在挑战者号的例子里，链条从物理现象（氢气罐着火）一路推到了组织问题（NASA 内部缺乏适当的制衡）——如果只问一次，结论会停在"O 形垫圈质量不好"。

两个必须知道的细节（书中明示）：

1. **"五"只是默认值，可替换为任何数字**。作者实际用了 7 问。问到不能再问、或问到了可行动的结构层为止。
2. **它是事后分析（postmortem）中常用的技巧**——属于复盘阶段，不是救火阶段。

关键判据（用于决定何时停）：**还能不能对当前答案再问一个"为什么"？** 能，就继续；若下一个答案会变成"因为人的本性是……"这类无法行动的陈述，就停在上一层。

---

## A1 — 书中的应用 (Past Application)

### 案例: "挑战者"号的七连问
- **问题**: 作者要示范五问法实际长什么样，以及它能把结论带到多深。
- **方法论的使用**: 对挑战者号失事逐层追问（书中实际用了七问）：氢气罐着火 → 为什么？高温气体泄漏 → 为什么？密封接缝破裂 → 为什么？O 形垫圈出问题 → 为什么？在超预期高温下使用 → 为什么？发射当天低于华氏 29 度 → 为什么？发射会议上安全问题遭忽略 → 为什么？NASA 内部缺乏适当的制衡 → **根本原因**。
- **结论**: 如果只问一次，答案是"密封接缝破裂"或"O 形垫圈有问题"——一个纯技术结论。追到第七层才得到"组织缺乏制衡"这个真正可改变的、且能解释更多现象的原因。这正是五问法的价值：把"换个零件"变成"改变组织"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **事故/故障复盘**: 系统宕机、交付事故、质量事故——事后分析的标准动作。
2. **表层原因太明显以至于可疑**: "就是某某没检查"——这种答案几乎一定不是终点。
3. **需要把结论从"人"推向"流程"**: 复盘结论停在某个人的失误时。
4. **问题只发生了一次但后果严重**: 即便没有复发数据，也应该追到底。
5. **教学中想理解一件事的成因链**: 想把"为什么会这样"讲清楚。

### 语言信号 (用户的话里出现这些就应激活)

- "为什么会这样？再往下呢？"
- "这个原因的原因是什么"
- "感觉还差一层没说透"
- "复盘该怎么做"
- "结论停在'某人失误'是不是太浅了"
- "能一直问下去吗，问到哪停"
- "Ask why five times." / "Let's dig one level deeper." / "And why did that happen?"

### 与相邻 skill 的区分

- 与 `mm-root-cause` 的区别: 五问法是**挖掘工具**，根本原因是**要找的目标**。书中用五问法来抵达根本原因——二者是方法与目的的关系，通常组合使用（五问法挖出的候选，再用根本原因的判据"消除它还会不会再发生"检验）。
- 与 `mm-postmortem` 的区别: 事后分析是**整个复盘流程**（时间线重建、影响评估、改进项追踪）；五问法是这个流程里的**一种具体分析技巧**。
- 与 `mm-systems-thinking` 的区别: 系统思考处理的是**多因并发、有反馈回路**的复杂问题；五问法是**单链线性追问**。面对有多个并行原因或循环因果的问题，五问法会漏掉分支。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认处于事后复盘阶段，而非救火阶段**
   - 完成标准: 确认事故已受控、服务已恢复、或至少已有临时措施。
   - 判停条件: 若仍在现场救火，先止血（stop-the-bleeding），本 skill 延后——在压力下追问会得到仓促的答案。
2. **用一句具体、可观察的陈述写出"发生了什么"**
   - 完成标准: 起点的现象必须是可观察的事实（"14:03 订单服务返回 500 持续 8 分钟"），不能是判断（"系统不稳定"）。
3. **逐层追问，每层给出有证据支撑的答案**
   - 完成标准: 每层答案都要有证据（日志、记录、当事人陈述），禁止推测；推测必须显式标注为"待验证"。
   - 判停条件: 若某层出现多个并列原因，立即停止单链追问——这是多因并发问题，改用鱼骨图或系统思考，否则会漏掉分支。
4. **判断何时停：问到"可行动的结构层"**
   - 完成标准: 停在能给出具体可改动动作、且属于流程/结构层面的那一层（如"缺少变更评审机制"）。书里示范的终点是"NASA 内部缺乏适当的制衡"。
   - 判停条件: 若下一层答案会变成无法行动的陈述（人性、行业规律、运气），停在上一层，不要继续。
5. **允许数字不是 5**
   - 完成标准: 明确记录实际问了几层（书中用了 7 层），不为了凑数停在 5，也不为了显示深刻而硬问下去。
6. **验证：用根本原因判据检验终点**
   - 完成标准: 对最终答案问"消除它之后，同类事故还会不会发生？"——若会，说明停早了，回到第 3 步。
   - 判停条件: 若已问到可行动层且通过判据，输出改进项，明确标注它是治本还是治标。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **事故现场、正在救火时**: 先止血。书中明示这是"事后分析中常用的技巧"。
- **多因并发的复杂问题**: 五问法是单链追问，遇到多个并列原因会强行把它们排成一条链，从而漏掉真正的分支。此时用鱼骨图、故障树或系统思考。
- **存在反馈回路的系统性问题**: 循环因果无法用线性"为什么"链表达，会追成一个圈。
- **纯探索性问题**: 没有已发生的事故，只有待设计的方案，不适用。

### 书中警告的失败模式 / 容易误用的地方

- **书中对本模型未给边界**（`boundary` 字段为"书中未提"），以下为基于机制推导的警告（推导, 非书中明示）：
- **为了凑够五次而停**: 作者的示范用了 7 问，明确说"五"可替换为任何数字。停在 5 是教条，停在实际的可行动层才是目的。
- **每层答案缺少证据**: 五问法最脆弱的环节是中间层——一旦某层是猜的，整条链就塌了，而且看起来仍然很完整。每层的证据必须可回溯。
- **单链掩盖多因**: 一个"为什么"常常有多个答案，只挑一个继续问会得出看似严密实则片面的结论。每层都应问"还有别的原因吗"。
- **追到无法行动的地方**: 停在"人就是会犯错"这类层面，等于什么也没说。终点必须对应一个具体的可改动动作。

### 容易混淆的邻近模型

- **根本原因（root-cause）**: 是五问法要抵达的目标，也是检验其终点的判据来源。
- **鱼骨图 / 故障树分析**: 是多因并发场景下的替代工具，弥补五问法单链的不足。
