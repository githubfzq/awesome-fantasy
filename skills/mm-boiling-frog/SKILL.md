# 温水煮青蛙（boiling frog）

## R — 原文 (Reading)

> 用来打比方的"温水煮青蛙"一直是个相当实用的思维模型，用来形容渐进式的变化通常难以应对，甚至是难以感知的。
>
> — 《思维模型》, 第2章 > 越来越热

---

## I — 方法论骨架 (Interpretation)

这个模型讲的是感知机制的一个缺陷：人对变化的察觉依赖**变化率**，而不是绝对水平。只要每一刻的增量都低于警觉阈值，人就永远处于"还好吧"的状态，直到累积的总量已经致命。

它成立的原因不是人蠢，而是比较基线在漂移。你今天的判断基准是"昨天"，而不是"一年前"——每次只跟上一刻比，任何缓慢上升的信号都显得平稳。这就是为什么全球变暖、家庭暴力、大规模监控这些事在早期几乎无人反应：没有哪一天是"出事的那一天"。

判据是：**单次增量低于可察觉阈值，但总量巨大**。这两条同时成立时，靠感觉一定失灵。作者列举的典型情境就是全球变暖、家庭暴力、大规模监控。

因此对策不是"提高警觉"——这是在同一个失灵的系统里打补丁——而是**外置指标并定期检查"我现在处在什么温度"**：找一个不受基线漂移影响的客观参照（历史数据、同行对比、绝对阈值），并设定强制复查的时间点。

需要诚实说明的是，作者明确指出真正的青蛙通常会从热水里蹦出来，这是一个比喻而非动物行为事实，但作为思维模型依然实用。

---

## A1 — 书中的应用 (Past Application)

### 案例: 全球变暖、家庭暴力与大规模监控

- **问题**: 作者把这三类情境并列为"温水煮青蛙"式警世寓言的典型：全球变暖逐年小幅升温，家庭暴力在关系中逐步升级，大规模监控的能力一点点扩张。它们的共同点是没有任何一个单独的时刻足以触发警觉与行动。
- **方法论的使用**: 作者不把问题归结为"人们不够关心"，而是指出感知机制本身对变化率不敏感——单次增量低于警觉阈值，累积总量却巨大。因此关键不是提高关注度，而是引入外部参照与定期检查。
- **结论**: 作者同时澄清了这个比喻的边界：真正的青蛙通常会从热水里蹦出来，所以它是个比喻而非动物行为事实；但作为提醒"渐进式变化难以感知和应对"的思维模型，它依然实用。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 指标持续小幅走坏：留存、利润率、响应时间、代码质量逐季变差，但每次幅度都不大。
2. 一段关系、团队氛围或健康状态"慢慢就这样了"，说不清转折点。
3. 长期未复查的前提假设：定价、架构选型、客户结构、安全边际，三年前定的现在还在用。
4. 权限、范围、承诺的渐进扩张：为了省事一次次放宽，至今没人算过总账。
5. 需要说服他人"现在就该动"：因为看起来一切都还正常。

### 语言信号 (用户的话里出现这些就应激活)

- "也说不上哪不对，就是一年不如一年"
- "每年都差一点点，没什么大不了的"
- "跟去年比好像也差不多"
- "说不清从什么时候开始的"
- "现在还行吧，没到非要改的地步"
- "boiling frog / gradual decline / slowly getting worse / creeping"

### 与相邻 skill 的区分

- 与 `mm-tyranny-of-small-decisions` 的区别: 小决定泛滥强调"同类决定的**数量**在增长且无人核算"，温水煮青蛙强调"变化的**速率**太低导致感知不到"。前者是你每次都知道自己在做什么却觉得无所谓，后者是你根本没察觉变化。
- 与 `mm-technical-debt` 的区别: 技术负债是温水煮青蛙在软件工程中的具体形态——打补丁累积成未来必须偿还的债；温水煮青蛙是通用感知机制，不限于技术场景。
- 与 `mm-path-dependence` 的区别: 路径依赖讲"过去的选择锁死了未来的可选路径"（可逆性下降），温水煮青蛙讲"渐变无法被察觉"（可感知性下降）。前者是选项在减少，后者是警报在失灵。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把"感觉还好"翻译成具体指标**
   - 选 2-3 个不受基线漂移影响的客观量（绝对值、同行分位、历史最值）。
   - 完成标准: 每个指标有明确定义与数据来源。
   - 判停条件: 若确实无法量化，改用"最坏情况描述法"：如果这种趋势再持续 3 年，会是什么样？
2. **拉长比较窗口，重设基线**
   - 强制与 12-36 个月前对比，而不是与上月对比；把曲线画出来。
   - 完成标准: 得到一条跨年度曲线和累计变化幅度。
3. **计算单次增量与总量的对比**
   - 明确写出：每次变化 X%，累计已变化 Y%。
   - 完成标准: 用一句话呈现"单次无感 vs 总量惊人"的落差。
   - 判停条件: 若累计幅度仍在可接受范围内，明确告知用户这不是温水煮青蛙，停止本 skill。
4. **设定外部警报线与强制复查节奏**
   - 因为感知必然失灵，必须外置：一条绝对阈值（越过就行动）+ 一个固定复查周期。
   - 完成标准: 阈值是具体数字，复查有具体日期/周期。
5. **找出"如果一次到位我会不会接受"的测试**
   - 问用户：如果这些变化是一夜之间发生的，你会接受吗？
   - 完成标准: 用户给出明确回答；若"不接受"，说明感知确实失灵，应与 `mm-tyranny-of-small-decisions` 区分后采取结构性措施。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 突发性、一次性的变化：那不需要"察觉渐变"的框架，需要的是应急响应。
- 用户已经明确感知到问题、只是在拖延：那是行动力或激励问题，不是感知失灵。
- 把任何长期趋势都包装成危机：有些缓慢变化确实无害，应先用累计幅度检验（推导，非书中明示）。

### 书中警告的失败模式 / 容易误用的地方

- 作者明确指出"真正的青蛙通常会从热水里蹦出来"——这是一个比喻而非动物行为事实。因此不能把它当作生物学论据来引用，只能作为思维模型使用（书中明示）。
- 容易把对策理解成"要更警觉"。警觉本身也会漂移，有效的是外置指标与强制复查（推导，非书中明示）。
- 一旦越过不可逆阈值，事后恢复的成本远高于维持成本，因此必须在阈值前行动（推导，非书中明示）。

### 容易混淆的邻近模型

- 与小决定泛滥：判断方法是问"如果一次到位，我会不会拒绝？"——会拒绝且当时没察觉 → 温水煮青蛙；每次都知道但觉得无所谓 → 小决定泛滥。
- 与技术负债：技术负债是温水煮青蛙的一个具体实例，若场景明确是工程/流程妥协的累积，优先用技术负债（它带有"偿还"这一解法）。
