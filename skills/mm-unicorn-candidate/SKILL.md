# 独角兽候选人（unicorn candidate）

## R — 原文 (Reading)

> 组织经常设置不切实际的岗位，这种岗位只能由独角兽候选人（unicorn candidate）来填补。这个说法是指，找到这样的候选人可能跟找到独角兽一样不容易（也就是基本不可能）。
>
> — 《思维模型》, 第8章 > 为谁安排什么岗位

---

## I — 方法论骨架 (Interpretation)

当一个岗位的要求清单叠加到几乎没有人能同时满足时，这个岗位就成了"独角兽岗位"——只有像独角兽一样几乎不存在的候选人才能填补。招聘失败的原因不在市场，而在岗位设计本身。

判据是**时间加排除法**：一个岗位长期招不到合格候选人，且薪酬与职位匹配、公司声誉没有问题，那么基本可以判定你找的是独角兽。这两个排除条件不能跳过——薪酬低于市场或公司口碑差，招不到人是正常的市场反馈，不是岗位设计问题。

三条解法：把职位**拆分**开雇用多人（一个人要会的东西分给两个专精的人）、在**内部培养**员工（招一个有潜力的人补齐短板）、或两者结合。

这个模型也能外推到招聘之外：有些人对恋爱对象或政治候选人提出不切实际或过于具体的要求，本质上也是在找独角兽。共同机理是——**要求清单是加法，而满足条件的人数是乘法**，每加一条要求，合格人群就以倍数缩小。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一个岗位开放数月，面试了不少人但没有一个合格， recruiter 和用户都开始怀疑"市场上没人"。
2. 岗位的 JD 越写越长：既要有行业经验又要会新技术，既要能带团队又要能自己写代码，既要有大厂背景又要能适应初创节奏。
3. 用户纠结"要不要降低标准"，需要一个判断标准而不是凭感觉妥协。
4. 非招聘类比：用户对合作方、伴侣、合伙人的条件清单长到现实里不存在。

### 语言信号

- "这个岗位招了大半年了，一个合适的都没有"
- "我们要找的人既要懂 A 又要精通 B，还要能带团队"
- "是不是该降低点要求了"
- "市场上根本没有这种人"
- "内部有没有人能培养起来"
- "We can't find anyone for this role" / "nobody checks all the boxes"

### 与相邻 skill 的区分

- 与 `mm-10x-engineer` 的区别: 十倍工程师讨论的是"顶级个体产出真的能高十倍吗"这一**产出分布问题**；独角兽候选人讨论的是"岗位要求是否可被单个人满足"这一**岗位设计问题**。
- 与 `mm-joy-s-law` 的区别: 乔伊法则说"最聪明的人通常在为别人工作"，指向的是**人才在哪**；本 skill 指向的是**你要的人存不存在**。
- 与 `mm-generalists-versus-specialists` 的区别: 通才/专才描述人才类型，本 skill 处理"把多种专长压在一个岗位上"造成的招聘失败，解法之一正是按专才拆岗。

## E — 可执行步骤 (Execution)

1. **先排除市场原因**
   - 完成标准: 明确回答两个问题——薪酬是否与职位匹配、公司声誉是否有明显负面。任一为否，先解决那个问题，退出本 skill。
2. **量化"长期"**
   - 完成标准: 给出岗位开放时长与面试人数；两者都明显偏高仍无合格者，才进入下一步。
3. **把要求清单拆成"必需"与"加分"**
   - 完成标准: 逐条标注，并对每条必需项给出"缺了它这件事就做不成"的理由；无法给出理由的降级为加分项。
4. **检查必需项之间是否互斥**
   - 完成标准: 找出两两难以共存的要求组合（如"大厂流程经验"与"从零搭建能力"、"深耕十年"与"掌握最新技术"），这是独角兽的核心证据。
5. **给出三条解法中的可执行项**
   - 完成标准: 明确输出其一或其组合——(a) 拆岗：把岗位切成几个专精角色并给出切法；(b) 内部培养：指定候选人 + 补齐短板的具体计划与周期；(c) 组合：招一个核心专长者 + 内部补另一侧。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 岗位刚开放不久、样本量太小——此时招不到人只是信息不足，不是岗位设计问题。
- 薪酬明显低于市场、或公司声誉有硬伤——先解决这些，否则判定无效（书明示的排除条件）。
- 真实需求确实是极少数顶尖人才（如核心算法负责人）——此时长周期搜寻是合理策略，不是独角兽问题。

### 容易误用的地方

- 书中明示的判定前提：必须先排除**薪酬与职位不匹配、公司声誉欠佳**等原因，才能判定是独角兽问题。跳过这一步会把市场反馈误读成岗位问题。
- （推导, 非书中明示）"降低标准"不是本模型推荐的解法。书中给的三条是拆岗、内部培养、二者结合——都是重构需求，而不是接受不合格的人。
- （推导, 非书中明示）对初创公司而言，早期岗位往往天然要求多面手，此时应优先用"内部培养+外部补位"而非强行拆岗（拆岗需要足够人头）。

### 容易混淆的邻近模型

- **十倍工程师（10x-engineer）**: 关于个体产出差异，不是关于岗位可达性。
- **通才与专家（generalists-versus-specialists）**: 人才类型划分，本 skill 的解法常常用到它。
