# 十倍工程师与十倍团队（10x engineer / 10x team）

## R — 原文 (Reading)

> 不用招募世界一流的全明星人才，只要精心设计适合的项目和岗位，使优秀人才根据自己独特的个性取得非凡的业绩，就能在组织内部创造出庞大的产出。
>
> — 《思维模型》, 第8章 > 开篇

---

## I — 方法论骨架 (Interpretation)

"十倍工程师"指产出数倍于同侪的个体。但作者的关键洞察是：**"十"是虚指，而十倍产出通常不是个人固有属性，而是"人—岗—环境"匹配的结果。**

这个区分极其重要，因为它决定了管理者的动作方向：

- 若十倍是**个人属性** → 唯一动作是去市场上抢人，而按乔伊法则，最优秀的人大概率不在你这儿，于是你无解。
- 若十倍是**匹配结果** → 它可以被设计出来：找到这个人独特个性与具体岗位/项目之间的契合点，产出就能大幅拉开。

作者明确站在后者：**不用招募世界一流的全明星人才**，也能在组织内部创造庞大产出。

于是就有了"十倍团队"这个更重要的概念：不追求找到一两个十倍个体，而是让**多名成员同时成为十倍贡献者**——管理者帮每个人都找到匹配的位置，团队整体就能挑战重量级。

关键判据是：**当你看到某人产出平平，先问是"人不行"还是"位置不对"。** 同一个人在 A 岗位平庸、在 B 岗位出色，是极其常见的现象，而这恰恰说明产出差距主要来自匹配而非天赋。

它的反面警告同样明确：只追十倍人才是陷阱——这种人才极为罕见，且其产出随角色、项目、组织变化往往**不可复制**。挖来的明星换个环境就失速，正是因为它本来就是匹配产物。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队产出长期上不去，用户判断"缺一个厉害的人"，准备高薪挖角。
2. 有人在原岗位表现平平，用户在考虑辞退或调岗——需要先排查匹配问题。
3. 小团队要承担超出体量的任务，需要整体提升产出而非单点突破。
4. 招聘难、预算有限，用户觉得"没有大牛就没戏"。
5. 管理者想设计岗位与项目分配，让每个人都在擅长的位置上。

### 语言信号 (用户的话里出现这些就应激活)

- "我们需要招个十倍工程师"
- "团队里没人能扛事"
- "他在这个岗位一直不出活"
- "怎么让团队产出翻几倍"
- "挖个大牛来带一下"
- "we need a 10x engineer / how do we build a 10x team / hire rockstars"

### 与相邻 skill 的区分

- 与 `mm-joy-s-law` 的区别: 乔伊法则指出"最好的人不在你组织里"这一**不利事实**；本 skill 给出对策——既然难以靠挖人，就靠设计匹配在内部造出十倍产出。二者常连用：前者提出约束，后者给出解法。
- 与 `mm-rumsfeld-s-rule` 的区别: 拉姆斯菲尔德法则强调"用现有部队开打"的**行动纪律**（接受约束、不再等待）；本 skill 是在接受约束之后**提升产出的方法**（怎么让现有的人产出翻几倍）。前者解决"动不动"，后者解决"怎么变强"。
- 与 `mm-managing-to-the-person` 的区别: 以人为本的管理是通用的管理原则（对每个人用不同的管理方式）；本 skill 聚焦在**岗位与项目的匹配设计**上，是产出导向的具体应用。
- 与 `mm-peter-principle` 的区别: 彼得原理解释"人为何会被提升到不胜任的位置"——是匹配被破坏的机制；本 skill 是主动修复匹配的方法。二者视角相反。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先把"招大牛"的假设放到一边**
   - 完成标准: 明确承认挖角方案的成本与不确定性（可参考 `mm-joy-s-law`），并确认本轮先做内部匹配诊断。
   - 判停条件: 若任务确实需要某项内部完全不具备的专业能力（如特定资质），转招聘规划。
2. **对每位成员做"独特个性"盘点**
   - 完成标准: 为团队每人写出 3 条：他做什么事时明显比别人快/好、他主动揽过什么活、他在什么情境下明显失速。依据是观察与事实，不是绩效评级。
3. **检查当前岗位是否匹配**
   - 完成标准: 逐人比对"他的独特个性"与"岗位实际要求"，标出明显错配的人。至少找出 1-2 处错配。
4. **重新设计岗位与项目分配**
   - 完成标准: 给出具体调整方案——换项目、换职责边界、换协作对象、或改变工作方式（独立 vs. 结对、探索 vs. 维护）。每个调整都要说明它释放的是哪种能力。
5. **同步清掉抑制产出的环境因素**
   - 完成标准: 列出 2-3 个与能力无关但严重拖慢产出的因素（会议密度、审批链、上下文切换、工具与信息获取），并给出减轻措施。匹配再好也会被这些抵消。
6. **设观测指标并复盘**
   - 完成标准: 为每人定 1 个可观测的产出指标与 1 个复盘周期（如 4-6 周），到点判断调整是否生效；无效则重新匹配，不急着下"人不行"的结论。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 用户需要的是招聘渠道、薪酬设计、人才规划——那是招聘问题，不是匹配问题。
- 团队确实缺少某项硬性的专业能力或资质——匹配设计替代不了能力缺口。
- 产出问题根源在流程、目标不清或战略摇摆——先把这些修好，重排岗位无济于事。
- 用于给低绩效找借口：把一切绩效问题都归为"位置不对"，会拖延必要的绩效处置。

### 容易误用的地方

- 书中明示：只追十倍人才是陷阱——这种人才极为罕见，且其产出随角色、项目、组织变化往往不可复制。
- （推导, 非书中明示）把"十倍"当成可承诺的目标：它是虚指，用来描述显著差距，不是 KPI。
- （推导, 非书中明示）只重排岗位而忽略环境——会议、审批、上下文切换可以轻易吃掉匹配带来的增益。
- （推导, 非书中明示）误读为"不需要优秀的人"。作者说的是**不必招全明星也能大幅提升产出**，不是"招谁都一样"。起点能力仍然重要，匹配是把潜力兑现出来的条件。

### 容易混淆的邻近模型

- **乔伊法则（Joy's Law）**: 说明为什么不能靠挖人；本 skill 说明那该怎么办。
- **彼得原理（Peter Principle）**: 匹配被系统性破坏的机制（升到不胜任的位置）。
