# 魔鬼辩护人（Devil's advocate position）

## R — 原文 (Reading)

> 第二个有助于你消除"证实偏差"的思维模型是"魔鬼辩护人"（Devil's advocate position）。这曾经是天主教会在封圣过程中的一个正式岗位。
>
> — 《思维模型》, 第1章 少犯错 > 进步总在葬礼后

---

## I — 方法论骨架 (Interpretation)

天主教会在封圣程序中专设一个职位，其职责是从"魔鬼的角度"反驳封圣——不是因为他不信，而是**制度性地保证有人反对**。这个设计承认了一个事实：在一个所有人都希望结论成立的场合，反对意见不会自然出现，因此必须**被安排出来**。

为什么需要安排？因为质疑已定决策的**社会代价**很高：在团队一片赞同时唱反调，会被视为不合作、消极、或对领导者不忠。于是理性的个人选择沉默，而集体因此失去纠错机会（这与群体思维 groupthink 的机制直接相关）。把"反对"变成一个**指定角色**，就把这份社会代价从个人身上移走了——他不是不忠，他是在履职。

书中给出三种做法，且明确指出第三种更有效：

1. **逼自己写下既定决策的另一种情况**（自任辩护人）。
2. **指定一名团队成员来做**。
3. **主动把已知持相反观点的人纳入决策流程**——最有效，因为前两种仍然是"演"出来的反对，第三种是真的。

它的收益有两层：一是迫使你针对自己的观念提出**更有说服力的论点**（经得起攻击的论证才是真的强）；二是让所有人更容易**从其他角度看问题**。

关键判据（芒格的标准，书中引用）：**我能否比对方更好地陈述他的论点？** 如果不能，你就没有资格说你已经考虑过反对意见。这条标准杜绝了"先树个稻草人再轻松驳倒"的伪反对。

## A1 — 书中的应用 (Past Application)

### 案例: 封圣程序中的正式岗位与芒格的发言标准
- **问题**: 作者要说明制度性反对的价值，以及什么样的反对才是有效的。
- **方法论的使用**: 两个对照。其一，天主教会在封圣过程中专设"魔鬼辩护人"这一正式岗位，从魔鬼的角度反驳封圣——反对被制度化为一个角色，而不是留给某个人自愿承担。其二，芒格的标准："如果我不比对方更了解他的论点，就绝不允许自己发表任何意见。"
- **结论**: 有效的反对不是姿态，而是要求你把对方论点陈述得比对方更好。这也解释了为什么书中认为"纳入真正持相反观点的人"比"指定某人演反方"更有效——前者天然就了解那个论点。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **决策已基本敲定、团队一致通过**: 越是没人反对，越需要安排反对（这是本 skill 最强的触发信号）。
2. **重大投入前的最后审查**: 立项、并购、大额采购、不可逆决策——需要有组织地攻击一次方案。
3. **领导的提案无人质疑**: 权力差使反对意见消失，需要制度化的角色来补位。
4. **方案已被讨论了很久、大家开始疲倦**: 此时反对最可能变成走过场，需要提高反对质量。
5. **用户想验证自己的方案有多结实**: 不只是想听鼓励，而是想知道哪里最脆。

### 语言信号 (用户的话里出现这些就应激活)

- "大家都同意了，但我心里没底"
- "谁来唱个反调"
- "有没有什么我们没想到的反对理由"
- "帮我挑挑这个方案的毛病"
- "这个决定还有翻盘的可能吗"
- "反对意见好像没人提，是不是不太好"
- "Let's play devil's advocate." / "Poke holes in this." / "What could go wrong?"

### 与相邻 skill 的区分

- 与 `mm-confirmation-bias` 的区别: 证实偏差是**病症**（筛选支持性证据）；魔鬼辩护人是**治疗手段**之一（主动构造反对）。书中明确把魔鬼辩护人列为消除证实偏差的第二个工具。
- 与 `mm-thinking-gray` 的区别: 灰度思考作用于**判断形成之前**（推迟判断，让结论不先形成）；魔鬼辩护人作用于**判断形成之后**（攻击已定结论）。两者是书中并列的两个工具，一前一后。
- 与 `mm-groupthink` 的区别: 群体思维描述的是**压制异议的集体现象**（病）；魔鬼辩护人是**针对它的制度设计**（药）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认已存在一个待攻击的既定决策**
   - 完成标准: 明确写出那个待审查的决定及其理由。
   - 判停条件: 若还没有形成任何方案，停止——此时需要的是生成方案（divergent-thinking）或推迟判断（thinking-gray），而不是攻击一个不存在的目标。
2. **选择反对方的承担者：自己 / 指定成员 / 真正的持异见者**
   - 完成标准: 三选一并说明理由。书中明确第三种最有效，应优先推荐：找出已知持相反观点的那个人，把他纳入流程。
   - 判停条件: 若第一种（自任）是唯一可行选项，明确标注其局限——自己攻击自己容易手下留情。
3. **以最强形式陈述反方论点**
   - 完成标准: 按芒格标准——把反对论点陈述得**比反对者本人更好**（更强、更完整、更有证据）。写完后请真正的反方（或对方）确认："我有没有准确地代表你的立场？"
   - 判停条件: 若陈述出来的反方轻易被驳倒，说明这是稻草人，重写，不得进入下一步。
4. **逐条攻击方案的支撑假设**
   - 完成标准: 对方案的每个关键假设问"如果这个不成立会怎样"，列出 3-5 条最致命的攻击点，并给出每条的杀伤力评级。
5. **区分"可修补"与"致命"**
   - 完成标准: 把攻击点分成两类：能通过调整方案修补的（记录为待办），与一旦成立整个方案就崩塌的（必须回应）。
   - 判停条件: 若存在致命攻击点且无法回应，明确建议**停下改变方案**，而不是带着它继续推进。
6. **记录反对过程并输出修订后的方案**
   - 完成标准: 输出清单：哪些假设被攻击后加强了论证、哪些需要修补、哪些仍未解决。把魔鬼辩护人的结论写进决策记录，而不是只留在讨论里。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **方案尚未形成时**: 没有目标可攻击，反对会退化成抬杠，破坏创造阶段的氛围。
- **时间极紧、需要立即行动时**: 完整的反对流程需要时间。紧急时先行动、事后补做。
- **已有大量真实反对意见时**: 若团队本来就在激烈争论，再安排一个指定反对者是冗余，反而会稀释真实的分歧。

### 书中警告的失败模式 / 容易误用的地方

- **书中对本模型未给边界**（`boundary` 字段为"书中未提"），以下为基于机制推导的警告（推导, 非书中明示）：
- **仪式化走过场**: 最典型的失败——指定某人"演"一下反方，提两条无关痛痒的意见，然后全体通过。识别标志：反对意见没有触及任何关键假设，且无人因此改变方案。
- **稻草人式反对**: 故意把反方论点说弱再驳倒，制造"已经考虑过反对意见"的假象。芒格标准（第 3 步）就是为此设的关卡。
- **把反对者污名化**: 如果唱反调的人因此被视为"不合作"，那么下次没人愿意担任这个角色，机制就会失效。必须保护反对者的地位，并公开说明这是履职而非不忠。
- **反对变成拖延**: 无限期地寻找反对理由会阻碍行动。第 5 步的"可修补 vs 致命"分类就是收敛机制——修完可修补的、回应完致命的，就应当推进。

### 容易混淆的邻近模型

- **红队（red teaming）**: 是魔鬼辩护人在军事/安全领域的系统化、对抗性版本，通常更正式、更结构化；魔鬼辩护人是它在一般决策中的轻量形式。
- **对立假设（alternative-hypothesis）**: 是在解释现象时提出另一个候选解释；魔鬼辩护人是针对**已定决策**做反对，对象是方案而非解释。
