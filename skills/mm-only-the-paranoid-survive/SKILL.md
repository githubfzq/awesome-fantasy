# 只有偏执狂才能生存（Only the paranoid survive）

## R — 原文 (Reading)

> 英特尔前首席执行官安迪·葛洛夫在1999年出版的同名著作中写道：“只有偏执狂才能生存。”
>
> — 《思维模型》, 第9章 > 激活力场

---

## I — 方法论骨架 (Interpretation)

**"只有偏执狂才能生存"** 是英特尔前首席执行官安迪·葛洛夫在其 1999 年同名著作中提出的原则：**即使身处鼎盛，也必须持续警惕并加固护城河**。

**为什么成立**：市场支配地位容易带来骄傲自满，而**颠覆往往在你状态最好时萌芽**。原因有二——一是成功会让人把现有做法当成真理，失去对替代路径的敏感；二是当你最赚钱的时候，正是新进入者最有动力来分这块蛋糕的时候，也是你自己最不愿意动现有收入结构的时候。于是威胁有时间在你看不见的地方长成。

书中给出的正面范例：英特尔在存储芯片统治地位达到巅峰时，就预见了日本制造商的威胁，主动转向微处理器，并打出"Intel Inside"这一品牌战役。

**这个原则的代价**：偏执要求你**警惕大量最终无害的细小威胁**。如果对每一个都投入，资源会被耗散殆尽。因此书中给出的配套要求是：**必须能区分信号与噪声**——例如监控技术采纳生命周期，看一项技术到底走到了曲线的哪一段。

**关键判据**：不是"有没有威胁"，而是"这个威胁现在处在采纳曲线的哪一段、以什么速度在移动"。处在早期采纳者阶段的威胁值得监控；正在跨越鸿沟进入早期大多数的威胁，才值得真正投入资源应对。

**书中给的重要限定**：**偏执也不保证成功。** 英特尔转向微处理器之后，最终仍被智能手机芯片的兴起所击败。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 业务正处于历史最好状态，团队内部出现"别折腾了"的声音。
2. 出现了几个看起来还很小的竞争/技术苗头，在纠结要不要当回事。
3. 担心自己"温水煮青蛙"，想知道该建立什么样的监测机制。
4. 想主动做一件会短期伤害现有业务、但长期必要的事（自我颠覆）。
5. 已经在警惕了，但被大量噪声搞得疲于奔命，需要收敛。
6. 看到同行被颠覆，想复盘"他们当初漏掉了什么信号"。

### 语言信号

- "我们现在挺好的,有必要折腾吗"
- "这个新东西现在还很小,要不要管"
- "会不会哪天突然被颠覆掉"
- "怎么建立早期预警"
- "要不要主动砍掉自己的现金牛"
- "每天都有新概念,到底哪个是真的"
- "only the paranoid survive / Andy Grove / strategic inflection point / disrupt ourselves / weak signals / early warning"

### 与相邻 skill 的区分

- 与 `mm-crossing-the-chasm` 的区别: 跨越鸿沟是**判断某个具体威胁何时会真正成势**的工具（看它有没有从早期采纳者跨入早期大多数）；本 skill 是**整体的防御姿态与资源分配原则**。实际用法是：用鸿沟给每个威胁定位，再用本 skill 决定对哪些投入。
- 与 `mm-disruptive-innovations` 的区别: 颠覆性创新描述**颠覆是如何发生的**（从低端/边缘切入再向上侵蚀）；本 skill 是**面对颠覆应有的心态与行动原则**。前者解释现象，后者规定行为。
- 与 `mm-moat` 的区别: 护城河是**你现有的防御工事清单**；本 skill 要求的是**在工事看起来最坚固的时候仍持续加固、并警惕工事被绕过**。本 skill 的输出通常就是"该往护城河的哪一段再投一次"。
- 与 `mm-boiling-frog` 的区别: 温水煮青蛙讲**渐变之所以察觉不到**这一认知陷阱；本 skill 是对策——**主动**去感知那些微弱的、遥远的变化。一个描述失败机制，一个给出防御纪律。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先确认当前是否处于"鼎盛"**
   - 完成标准: 明确当前业务状态与团队心态。若已明显下滑，本 skill 不适用，转止血类处理。
   - 判停条件: 若确实处于鼎盛，明确指出书中机制——颠覆往往在你状态最好时萌芽，成功会让人把现有做法当真理。
2. **列出所有可能颠覆你的威胁，宁多勿少**
   - 完成标准: 得到 5-10 条威胁清单，覆盖技术换代、渠道迁移、商业模式变化、监管变化、用户代际更替。此阶段不做筛选。
3. **用技术采纳生命周期给每条威胁定位**
   - 完成标准: 每条明确标注处于创新者 / 早期采纳者 / 鸿沟中 / 早期大多数 / 后期大多数，并给出判断依据与移动速度。
4. **区分信号与噪声，做强制收敛**
   - 完成标准: 只保留 2-3 条值得投入的**信号**（正在跨越鸿沟、或以可观测的速度逼近），其余归入**监控清单**（设触发条件，不投资源）。必须写明每条被划为噪声的理由——避免因为"看起来不靠谱"就随手划掉。
5. **对保留的信号做对冲投入，并设定复盘节奏**
   - 完成标准: 给出具体的对冲动作（小规模试水、收购/合作、组织独立小团队、护城河加固项），每项标明投入上限与验证指标；同时给出固定的复盘周期，用第 3 步的定位变化来决定是加码还是降级。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 业务已明显下滑、正在失血——此时需要止血与转向，不是偏执式预防。
- 资源极度紧张的早期团队——偏执的代价（警惕大量最终无害的威胁）会把有限资源耗散掉。
- 已经确定的单一威胁要评估——直接用跨越鸿沟定位即可，不需要整体框架。
- 组织已因过度警惕而焦虑瘫痪——此时应先恢复行动力，而非继续加码预警。

### 容易误用的地方

- **书中明示**: **偏执也不保证成功。** 英特尔转向微处理器之后，最终仍被智能手机芯片的兴起击败。不能把"我们足够警惕"当成安全保证。
- （推导, 非书中明示）把噪声当信号。书中明确指出偏执的代价是必须警惕大量最终无害的细小威胁——所以第 4 步的强制收敛不是可选项，而是这个模型能否成立的前提。
- （推导, 非书中明示）只警惕不行动。偏执的产出是"加固护城河的具体投入"，不是一份威胁报告。
- （推导, 非书中明示）把偏执变成组织焦虑。如果团队因为持续预警而失去行动力，说明模型已被误用——应回到第 4 步收敛到 2-3 条，其余只监控不投入。
- （推导, 非书中明示）只对外部威胁偏执。英特尔的案例是**主动转向**——最难的是对自己最赚钱的业务下手，而这恰恰是书中范例的核心。
