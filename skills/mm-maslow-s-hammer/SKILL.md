# 马斯洛之锤（Maslow's hammer）

## R — 原文 (Reading)

> 我记得见过一台精密又复杂的自动洗车机，它洗车洗得很不错。不过，它也只会洗车。任何被塞进它的滑道里的东西，都会被它当成是要洗的车子。我猜，如果你手里只有锤子，那么一切看起来都像钉子。
>
> — 《思维模型》, 第6章 > 权衡成本与收益（章首）

---

## I — 方法论骨架 (Interpretation)

马斯洛 1966 年在《科学心理学》里用自动洗车机作比喻：那台机器洗车洗得很好，但它**只会洗车**——任何被塞进滑道的东西，都被当成是要洗的车。由此得出那句名言：**如果你手里只有锤子，那么一切看起来都像钉子。**

这个模型的真正锋利之处不在于"人会用自己熟悉的工具"，而在于后半句——**工具会反过来塑造你对问题的定义**。你不是"用锤子去解决钉子问题"，而是"把所有问题都重新描述成钉子问题"。问题在被解决之前，先被工具扭曲了。

作者把这个模型放在决策章的开头，用意非常明确：**决策领域里那把"锤子"就是利弊清单**。多数人遇到任何选择，第一反应都是列好处坏处——不是因为利弊清单适合这个问题，而是因为他们只会这个。

对应的 remedy 有两条：

1. **扩充工具箱**。多掌握几个模型，遇到问题时才有得选。
2. **按问题复杂度挑模型**。作者强调：某些决策极为复杂、后果严重，需要更复杂的思维模型；但在比较简单的情况下，运用复杂模型就是**杀鸡用牛刀**。

第二条常被忽略：马斯洛之锤不是"简单工具永远不好"，而是"**工具的复杂度要匹配问题的复杂度**"。只有锤子的人既会在复杂问题上砸钉子，也会在有了新工具后对小事过度建模。

关键判据：**先判断问题的复杂度（选项数、后果严重性、不确定性），再选工具；而不是先拿起顺手的工具。**

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队/个人反复用同一种方法处理所有问题（所有问题都上 OKR、都做 A/B、都搞复盘、都列清单）。
2. 讨论被某个单一视角垄断（技术视角、财务视角、增长视角），其他角度进不来。
3. 拿到新工具/新框架后，看什么都像它的应用场景。
4. 感觉"问题被重新定义过"，且重新定义的方向恰好贴合现有工具。
5. 反过来：用极重的工具处理极轻的问题（杀鸡用牛刀）。

### 语言信号

- "这个问题也用我们那套方法来做吧"
- "不管什么需求，先上个系统再说"
- "我们团队只会这一招"
- "他眼里什么都是增长问题"
- "是不是把简单问题搞复杂了"
- "if all you have is a hammer / everything looks like a nail / law of the instrument"

### 与相邻 skill 的区分

- 与 `mm-pro-con-list` 的区别: 利弊清单是**那把锤子本身**（作者明确指认为决策领域的锤子），马斯洛之锤是**关于"只会用锤子"这一现象的元警告**。发现某人拿清单套所有问题时，两个 skill 同时成立，但切入角度不同。
- 与 `mm-generalists-versus-specialists` 的区别: 通才与专家讨论的是**人的知识结构广度**，马斯洛之锤讨论的是**工具与问题之间的匹配关系**。通才不一定不会犯锤子病，专家也未必只会被困住。
- 与 `mm-ockham-s-razor` 的区别: 奥卡姆的剃刀主张**在解释力相当时选更简单的那个**；马斯洛之锤警告的是"工具单一导致问题被扭曲"。前者是简约原则，后者是多样性原则，方向相反但可互补。

## E — 可执行步骤 (Execution)

1. **识别当前被默认使用的那把"锤子"**
   - 问：如果这个问题交给这个团队/这个人，他们第一反应会用什么方法？
   - 完成标准: 明确指出那把锤子是什么（如利弊清单、A/B 测试、加人、重构）。
2. **检查问题是否被工具重新定义过**
   - 问：我们现在讨论的"问题"，是它本来的样子，还是被某个工具翻译过的版本？
   - 完成标准: 找出至少一处"为了套用工具而做的简化或改写"。
   - 判停条件: 若问题确实天然匹配该工具，说明未犯锤子病，可直接使用工具并结束。
3. **评估问题的复杂度：选项数、后果严重性、不确定性**
   - 完成标准: 给出复杂度评级（简单 / 中等 / 复杂）。
4. **按复杂度匹配工具，既防不足也防过度**
   - 简单且后果轻微 → 轻量工具（利弊清单即可，不必建模）。
   - 后果严重或含不确定性 → 升级工具（决策树、成本收益分析等）。
   - 完成标准: 明确说明"当前工具是匹配、不足、还是过度"，并给出替换建议。
5. **补一条：建立工具箱的多样性**
   - 若反复出现锤子病，说明是工具箱问题而非单次失误。
   - 完成标准: 给出 2-3 个应补进来的具体模型，并说明各自适配什么场景。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 工具确实匹配问题：熟练使用擅长的方法不是锤子病，频繁复用本身不是问题（推导，非书中明示）。
- 用户在单一专业领域内深度钻研：专注不等于视野狭窄，别把深耕病理化（推导，非书中明示）。

### 容易误用的地方

- 书中未提边界，但作者强调"**某些决策极为复杂、后果严重，需要用到更复杂的思维模型；但在比较简单的情况下，运用复杂模型就是杀鸡用牛刀**"——暗示容易从一个极端走到另一个极端：为了避开锤子病而对小事过度建模。
- （推导，非书中明示）容易把"指出锤子病"变成空泛的"你要有多元思维"。 remedy 必须是具体的：给出 2-3 个可替换的模型及其适配场景（步骤 5）。
- （推导，非书中明示）容易只批判简单工具。锤子病的本质是**匹配失当**，大模型套小问题同样是锤子病。

### 容易混淆的邻近模型

- 利弊清单（pro-con-list）：本书中被明确指认为决策领域的那把锤子。
- 奥卡姆的剃刀（ockham-s-razor）：主张简约，与本 skill 主张的多样性方向相反，需按场景权衡。
