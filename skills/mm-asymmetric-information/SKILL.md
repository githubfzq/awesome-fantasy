# 信息不对称（asymmetric information）

## R — 原文 (Reading)

> 道德风险和委托代理问题都可能由信息不对称（asymmetric information）导致。"信息不对称"是指交易双方得到了不同的信息。也就是说，可得的信息分配不对等。
>
> — 《思维模型》, 第2章 > 危险行业

---

## I — 方法论骨架 (Interpretation)

信息不对称描述的是一种局面：**交易双方掌握的信息不同，可得信息的分配不对等**。它是道德风险与委托代理问题的共同成因——正因为一方看不到另一方的行为或真实情况，另一方才能隐蔽地做出对自己有利的选择。

重要的是，信息优势方**不一定**是卖家或专家。作者特意指出方向可以反转：在保险市场上，投保方往往比保险公司更了解自己的风险状况（这也是逆向选择的前提）。消费者并非永远处在劣势，判断时要具体看"关于哪件事、谁更清楚"。

它的后果是市场效率下降：信息劣势方因为无法分辨好坏，只能按平均水平出价，于是优质方退出，市场萎缩甚至崩溃（见 `mm-adverse-selection` 与 `mm-market-for-lemons`）。

缓解手段有三条主线：强制披露信息（立法要求披露利益关系、佣金）、提升信息公开度（网络让历史记录可查，如 Carfax 车辆历史报告恢复了买卖双方的信息对称）、以及引入第三方核验与信号机制。

关键判据：**关于这项交易的某个关键属性，是否只有一方知道、且另一方无法低成本核实？** 如果可以低成本核实，那就只是"还没查"，不构成结构性不对称。

## A1 — 书中的应用 (Past Application)

### 案例: 房地产经纪人与理财顾问的信息优势

- **问题**: 房地产经纪人比卖家更懂市场行情，卖家因此难以质疑他给出的定价建议与"赶紧接受这份报价"的劝告。理财顾问比客户更懂金融市场，而且他获得的报酬并不总是透明的——作者指出，若客户知道某款产品的推荐带有佣金，就不太可能投资该产品。
- **方法论的使用**: 作者把这两个场景抽象为同一个结构：一方知道（市场真实行情 / 佣金安排），另一方不知道且无法核验，于是信息优势方可以隐蔽地做出对自己有利的选择。解法也一致——披露与提高透明度：公开佣金与利益关系，让信息劣势方也有判断依据。
- **结论**: 作者同时提醒方向可反转——消费者并非总处劣势，保险业中投保方往往信息占优。因此不能默认"专家=优势方"，必须先定位"关于哪件事谁更清楚"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 面对专业报价或服务方案，看不懂、无法判断是否合理：装修报价、医疗方案、法律意见、云服务账单。
2. 买二手/非标商品，卖家比你清楚真实状况：二手车、二手房、二手设备、域名、账号。
3. 接受带佣金的推荐：理财产品、保险、带货、招商加盟，怀疑对方有未披露的利益。
4. 管理或协作中，执行方掌握你无法看到的真实情况：外包进度、远程办公产出、门店实际经营。
5. 设计平台规则时，需要决定披露哪些信息才能让市场不萎缩。

### 语言信号 (用户的话里出现这些就应激活)

- "我不懂这一行，只能听他的"
- "这个报价我根本看不明白"
- "他是不是有什么没告诉我"
- "有没有隐藏费用/佣金"
- "他说的我不敢不信，也不敢全信"
- "asymmetric information / information gap / disclosure / hidden fees"

### 与相邻 skill 的区分

- 与 `mm-adverse-selection` 的区别: 信息不对称是**状态**（信息分布不均），逆向选择是**后果**（高风险者因此留下、低风险者退出，市场质量恶化）。先有信息不对称，才可能有逆向选择。
- 与 `mm-principal-agent-problem` 的区别: 信息不对称是成因之一，委托代理问题是结果形态（委托人得到次优结果）。同一局面下，信息落差回答"为什么他能这么做"，代理问题回答"结果差在哪"。
- 与 `mm-market-for-lemons` 的区别: 柠檬市场是信息不对称导致的具体市场崩溃现象（蜜桃退出、市场只剩柠檬），是信息不对称的一个极端后果，不是同义词。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位是哪件"事"的信息不均**
   - 写出具体属性：真实质量？市场行情？佣金安排？实际进度？
   - 完成标准: 一句"关于 X，A 知道而 B 不知道"。
   - 判停条件: 若该信息可低成本自行核实（公开可查），停止本 skill，改为建议用户去查。
2. **确认优势方是谁，不要默认**
   - 逐方检查：卖家/专家不一定占优，投保方、使用者、执行方常常掌握私有信息。
   - 完成标准: 明确写出优势方与劣势方。
3. **判断劣势方是否有退出选项**
   - 问：如果无法分辨好坏，劣势方会不会干脆不出价/退出交易？
   - 完成标准: 若是，标注"存在市场萎缩风险"，转 `mm-adverse-selection` 处理。
   - 判停条件: 若劣势方无法退出（刚需、独家），则重点转向披露与核验而非市场设计。
4. **选择缓解手段**
   - 三选一或组合：强制披露（利益关系、佣金、缺陷）、提升公开度（历史记录、第三方报告、评价沉淀）、信号与担保（质保、认证、押金、延后兑付）。
   - 完成标准: 每条措施写明"把哪一项私有信息变成了公开信息"。
5. **核验措施是否真的被看见**
   - 披露不等于被理解：检查信息是否以劣势方能懂的形式呈现（如 Carfax 把车况变成一份可查报告）。
   - 完成标准: 写出可读性与触达方式的具体安排。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 信息可得、只是用户懒得查的情况：那是行动力问题，不是结构性不对称。
- 双方信息对称的纯议价/博弈场景：应改用博弈论或议价分析，信息框架没有解释力。
- 信息落差对决策无实质影响时（例如卖家知道自己的血型）：不构成经济学意义上的不对称（推导，非书中明示）。

### 书中警告的失败模式 / 容易误用的地方

- 作者指出消费者并非总处劣势，保险业中投保方往往信息占优——默认"专家一定占优"是最常见的误判。
- 容易把信息不对称直接等同于"对方在骗我"。它只是结构条件，是否导致损害取决于激励（推导，非书中明示）。
- 披露本身不足够：信息必须被劣势方真正理解并能在决策中使用，否则等于没披露（推导，非书中明示）。

### 容易混淆的邻近模型

- 与逆向选择：因果链的两端。信息不对称是**条件**，逆向选择是**结果**；只消除信息不对称（如 Carfax）就能阻断逆向选择。
- 与柠檬市场：柠檬市场是信息不对称在二手车市场的具体表现，是"种"与"个例"的关系；其他市场（保险、招聘）也有逆向选择但不叫柠檬市场。
