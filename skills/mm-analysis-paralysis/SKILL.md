# 分析瘫痪（analysis paralysis）

## R — 原文 (Reading)

> 这种意外后果有一个名称——"分析瘫痪"（analysis paralysis），指的是由于过度分析大量可用信息，你的决策工作陷入瘫痪。
>
> — 《思维模型》, 第2章 > 好事过头成坏事

---

## I — 方法论骨架 (Interpretation)

分析瘫痪描述的不是"决策做得慢"，而是"决策做不出来"。起因是两个正当诉求的冲突：你想迅速决定，又想收集更多信息确保正确。在信息稀缺的年代，多收集几乎总是对的；但在信息超载的环境里，后者会被推向极端——每多查一份资料都提供了新的疑虑，于是收集本身取代了决定。

这里有一个被大多数人忽略的关键洞察：**不做选择本身就是一个选择——你选择了保持现状**。而这往往比所有可选方案都更糟。作者举的例子正是：人们常常留在自己不喜欢的岗位上，不是因为比较后觉得这份工作最好，而是因为面对所有可能性而不确定下一步，于是默认不变。

它成立的原因是"追求最优"与"信息收集"之间没有天然的停止点——你永远可以再多查一点，所以必须外置一个停止规则。

解药因此是三条：区分可逆/不可逆决策（可逆的就别花大力气）、限制选项数量（不是越多越好）、为可逆决策设快速通道。

## A1 — 书中的应用 (Past Application)

### 案例: 咖啡机、Yelp 餐馆与不想干的工作

- **问题**: 作者给出三个由轻到重的例子——为了决定买哪种咖啡机花掉大把时间；面对 Yelp 上无穷无尽的餐馆选项思来想去；更严重的是，人们常常留在自己不喜欢的岗位上，只因为面对所有可能性而不确定下一步。
- **方法论的使用**: 作者指出这不是"信息不够"的问题，恰恰是"信息太多、选项太多"导致决策工作瘫痪。核心洞察是不做选择本身就是一个选择——选择了保持现状，而这个默认选项通常比所有可选方案都更糟。
- **结论**: 解法不是收集更多信息，而是给决策流程设停止规则：区分可逆与不可逆决策、限制选项数量、为可逆决策设快速通道。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 反复比较同类商品/方案，已经看了几十份评测还不下单、不定方案。
2. 一直在"调研""再看看""等更多信息"，但始终没有决策时点。
3. 因为不确定下一步而滞留在一个自己明确不满意的现状（工作、关系、城市）。
4. 团队讨论多轮无果，每次都以"再收集点数据"收场。
5. 明显已经到收益递减阶段还在追加分析投入：新信息不再改变结论。

### 语言信号 (用户的话里出现这些就应激活)

- "我再看看，等收集完信息再说"
- "选不出来，各有各的好"
- "等我再想想，想清楚了再动"
- "选项太多了，不知道从哪下手"
- "我不是不想换，是不确定换了之后……"
- "analysis paralysis / overthinking / can't decide / too many options"

### 与相邻 skill 的区分

- 与 `mm-reversible-vs-irreversible-decisions` 的区别: 可逆/不可逆决策给出**判据与流程分配**（能退回来就快速试错），分析瘫痪描述的是**失效状态**（卡住了）。前者是解药，后者是病症；判断"该不该快速决定"用前者，判断"我是不是卡住了"用后者。
- 与 `mm-paradox-of-choice` 的区别: 选择的悖论讲"选项越多满意度越低"（选择本身的心理代价），分析瘫痪讲"信息过多导致无法行动"（决策流程的失效）。前者解释为什么选完不开心，后者解释为什么选不出来。
- 与 `mm-decision-fatigue` 的区别: 决策疲劳是**资源耗尽**导致的决策质量下降（做太多决定后疲劳），分析瘫痪是**信息过多**导致的决策停滞（不是累了，是卡住了）。前者靠休息与减少日常决策，后者靠设停止规则。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认"卡住"而非"信息不足"**
   - 问：最近三次收集的新信息，有没有改变你的排序？
   - 完成标准: 若连续多次"没改变"，确认已进入收益递减，停止收集。
   - 判停条件: 若新信息仍在实质改变排序，说明确实需要更多信息，停止本 skill 的建议路径。
2. **点明"不选择就是选择保持现状"**
   - 明确写出当前默认选项是什么，以及继续拖延三个月的后果。
   - 完成标准: 用户能说出"我其实一直在选 X（现状）"。
3. **先分类：这个决定可逆吗**
   - 能退回来 → 走快速通道；不能退 → 才投入系统性深思熟虑（转 `mm-reversible-vs-irreversible-decisions`）。
   - 完成标准: 明确归类并给出对应的时间预算。
   - 判停条件: 若不可逆，转入重量级流程，本 skill 的收敛压力相应降低。
4. **削减选项与信息源**
   - 把候选收敛到 3 个以内，把信息源收敛到 2-3 个可信渠道；设定信息收集的时间框。
   - 完成标准: 有明确的候选清单、信息源上限与时间盒。
5. **设决策时点与"足够好"标准**
   - 写下：在某个具体时间前做决定，且满足哪几条就算"够好"（满意即可，不追求最优）。
   - 完成标准: 有具体日期 + 2-3 条"够好"判据。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 信息确实严重不足、连基本选项都未厘清时：此时需要的是调研，不是催促进度（推导，非书中明示）。
- 真正的不可逆决策：这类决策值得慢，强行加速会造成不可逆的错误（推导，非书中明示）。
- 把审慎的深思熟误判为瘫痪：判断标准是"新信息是否还在改变结论"，而非"花了多少时间"（推导，非书中明示）。

### 书中警告的失败模式 / 容易误用的地方

- 书中未提本模型的局限；作者把它与信息超载、完美主义、决策疲劳组合使用（推导，非书中明示）：这提示它往往是多个因素叠加的结果，单靠"设截止日期"可能不够。
- 关键警告是"不做选择本身就是一个选择"——默认选项通常最糟，因为它不是被选出来的，而是被剩下的（书中明示）。
- 容易把解法理解成"少想点"。真正的解药是改变决策流程（区分可逆性、限制选项、设快速通道），而不是压制思考（推导，非书中明示）。

### 容易混淆的邻近模型

- 与信息超载：信息超载是**环境状态**（可用信息超过处理能力），分析瘫痪是**行为结果**（决策停摆）。信息超载可能导致分析瘫痪，也可能只导致效率下降。
- 与决策疲劳：一个是"卡住"，一个是"累了"。判断方法是问：如果休息一晚上，明天能决定吗？能 → 决策疲劳；仍然不能 → 分析瘫痪。
