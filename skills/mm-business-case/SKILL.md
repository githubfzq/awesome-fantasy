# 商业案例（business case）

## R — 原文 (Reading)

> 所谓的“商业案例”，就是概括你决策背后原因的文档。
>
> — 《思维模型》, 第6章 > 谨防未知的未知数（章末）

---

## I — 方法论骨架 (Interpretation)

商业案例是一份概括你决策背后原因的文档。它的表达形式是从第一性原理出发:先把前提(原理)摆出来,再解释这些前提如何推出结论(你的决定)——也就是"有理有据"。

它为什么有用:把推理链条显式写下来,会暴露链条上的漏洞。口头叙述时你能轻轻跳过一步,写下来就跳不过去了——那一步会明晃晃地摆在那里,要么补上,要么承认它是个假设。

它同时是与同事讨论这个决定的起点。终极目的是说服别人(或自己)这个决定是正确的;但更现实的价值在于,它给了别人一个可以逐条反驳的靶子,而不是只能整体接受或整体拒绝。

形式可长可短:几段话的非正式版本,到附带现场演示的详尽报告都算。作者强调它不只适用于商业领域,个人重大决定同样适用。

典型组合拳:先用情景分析想象另一条路会如何展开,再用成本收益分析系统比较,成功概率不确定的分支用决策树,最后汇总成一份简洁的商业案例。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户要立项、采购、招人、转型,需要一份说明"为什么该做"的文档。
2. 用户自己已经倾向某个决定,想验证这个决定到底有没有站得住的理由。
3. 用户要做个人重大决定(换城市、转行、创业、读研),想把散乱的想法整理成可讨论的东西。
4. 用户需要说服领导或同事,但只会说"我觉得这样更好",需要把直觉转成可检查的论证。

### 语言信号 (用户的话里出现这些就应激活)

- "我想写个立项报告 / 可行性说明"
- "怎么跟领导说这件事该做"
- "我自己也没想清楚为什么想这么做"
- "帮我梳理一下做这个决定的理由"
- "这个决定值得吗,我说服不了自己"
- "business case" / "make the case for" / "justify this decision"

### 与相邻 skill 的区分

- 与 `mm-arguing-from-first-principles` 的区别: 从第一性原理出发是一种**推理方法**(拆到不可再拆的基本事实再重建);商业案例是这种推理的**书面产物**,还额外承担"作为讨论起点"和"说服"的职能。
- 与 `mm-cost-benefit-analysis` 的区别: 成本收益分析是商业案例里常用的一个组件(量化比较),但商业案例还包括前提、假设、风险与结论;只有数字没有前提,不叫有理有据。
- 与 `mm-decision-tree` 的区别: 决策树处理"有多个不确定分支时怎么算";商业案例是最终汇总出来的那份文档,决策树可以嵌在其中一段。

## E — 可执行步骤 (Execution)

1. **先写结论与决定本身**
   - 完成标准: 用一句话说清楚"我决定做 X(或不做 X)",放在最前面;读者不必读完才知道你要什么。
2. **列出前提,并区分事实与假设**
   - 完成标准: 把推理依赖的每条前提单列一行,逐条标注是"已知事实/数据"还是"假设";对每条假设写明它成立所需的条件。
3. **演示从前提到结论的推导**
   - 完成标准: 明确写出"因为前提 A + B,所以……";每跳一步都停下来检查是否有跳步。
   - 判停条件: 若发现某一步推不下去,回到步骤 2,把缺失的那条补成显式假设,而不是用修辞糊过去。
4. **补上比较与不确定性**
   - 完成标准: 至少列出被放弃的主要替代方案及放弃理由;若涉及不确定结果,嵌入情景分析、成本收益分析或决策树的结论。
5. **写明证伪条件与复盘点**
   - 完成标准: 给出"如果观察到 X,说明这份商业案例错了"以及复盘的日期与指标。
6. **按读者裁剪篇幅**
   - 完成标准: 明确读者是谁(自己/团队/决策层),据此选择几段话的简版还是带演示的详版。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 决定已经执行完毕、文档只是事后追认:此时写出来的不是推理,是辩解。
- 低成本可逆的小决定:写详尽报告的成本高于决定本身的价值,几句备忘即可。
- 组织文化里这份文档只是审批流程的一个章:此时重点是流程,不是推理,本模型帮不上忙。

### 书中警告的失败模式 / 容易误用的地方

- 书中强调它不只适用于商业领域,个人重大决定同样适用——不要因为叫"商业"案例就只在公司场景用。(书中明示)
- 常见误用:先有结论再倒推前提。商业案例的价值恰恰在于暴露漏洞,倒推出来的文档只会把漏洞藏得更深。(推导,非书中明示)
- 常见误用:把篇幅当质量。作者明确形式可短可长,几段话也算。(书中明示)

### 容易混淆的邻近模型

- 与成本收益分析(cost-benefit analysis): 后者是量化组件,前者是完整文档。
- 与情景分析(scenario analysis): 情景分析负责展开不同的未来,商业案例负责在此基础上给出一个当下决定及其理由。
