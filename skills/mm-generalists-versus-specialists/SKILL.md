# 通才与专家（generalists versus specialists）

## R — 原文 (Reading)

> 有些人希望对很多事都稍有涉猎，成为通才（generalists），另一些人则希望深入了解某个领域，成为专家（specialists）。……在规模很小的机构中，专家可谓“奢侈品”。你更需要通才，因为有很多类型的问题需要解决，但只有少数几名员工可以解决问题。
>
> — 《思维模型》, 第8章 > 齐心协力

---

## I — 方法论骨架 (Interpretation)

通才对很多事都稍有涉猎，专家在单一领域深入钻研。这不是"哪种人更好"的问题，而是**组织规模与问题分布决定的人才配置问题**。

机制在于岗位的成本结构：一个全职专家岗要成立，前提是"只有专家才能解决的问题"足够多，多到能填满这个岗位的全部工时。

- **小机构**：问题类型很多，但每类问题的出现频率都不高，人手又少。任何单一专业方向都养不起一个全职岗位——所以专家是"奢侈品"。这时需要通才覆盖大部分问题，少量的专业问题靠外部资源（顾问、外包、兼职）解决。
- **大机构**：问题总量大且可以细分，某类专业问题的密度足以养一个全职岗位，而专家在特定领域能取得比通才更好的成果，所以雇专家更划算。

关键判据是一句可以操作的话：**先问"这类专业问题出现的频率，是否高到足以养一个全职岗位"。** 答"是"就雇专家，答"否"就让通才覆盖 + 外部解决。

这个模型还有一个隐含的动态性：同一组织在不同阶段会需要不同类型的人。规模变了，答案也会变——所以这是一个需要周期性重算的判断，不是一次性的组织架构决定。

## A1 — 书中的应用 (Past Application)

### 案例: 家庭医生与专科医生 & 综合商店与专业商店

- **问题**: 需要判断什么时候该用通才、什么时候该用专家。
- **方法论的使用**: 作者用了两组对照。医疗上，家庭医生是通才，负责初步诊断，遇到传染病或肿瘤就转介给专科医生——因为普通诊所遇到的传染病和肿瘤病例频率，不足以养一个全职专科医生。零售上，沃尔玛、塔吉特是综合性商店，家得宝、百思买、汽车地带是专业性商店——后者规模足够大，单一品类能撑起整个商业模式。
- **结论**: 通才做广度覆盖与分诊，专家做深度解决；选择取决于问题密度是否支撑得起一个专职岗位，而不是取决于"专家更高级"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 小团队在讨论"要不要招一个专职的 X（设计师/数据/安全/法务）"。
2. 个人在职业发展上纠结"我应该往深走还是往广走"。
3. 组织在决定某项能力是自建团队还是外部采购/外包。
4. 团队规模快速扩张或收缩后，需要重新盘点人才结构。

### 语言信号 (用户的话里出现这些就应激活)

- "我们要不要招个专职的……"
- "这个问题要不要找外部顾问"
- "我这十个人的团队，需要专门设这个岗吗"
- "我该往专精走还是什么都学一点"
- "外包还是自建 / 自研还是买"
- "Should we hire a specialist or a generalist"

### 与相邻 skill 的区分

- 与 `mm-foxes-versus-hedgehogs` 的区别: 狐狸与刺猬描述的是**认知风格**（重细节 vs 重愿景），用于岗位适配（狐狸做战略、刺猬做营销）；通才与专家描述的是**知识覆盖宽度**，用于组织配置。
- 与 `mm-joy-s-law` 的区别: 乔伊法则否定"靠聚集明星取胜"，指向重新设计岗位；本模型在承认现有队伍后解决"用什么类型的人填坑"。
- 与 `mm-economies-of-scale` 的区别: 规模经济解释为什么大组织单位成本更低；本模型用它解释为什么大组织才养得起专家。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **统计问题分布，而非问题清单**
   - 完成标准: 列出待解决问题类型，并为每类估算**单位时间出现频率**（每周/月几次）与单次解决耗时。
2. **计算是否养得起一个全职岗**
   - 完成标准: 用"频率 × 单次耗时"估算全职负载率；明确给出"足以 / 不足以养一个全职岗位"的结论。
   - 判停条件: 若负载率明显低于 50%，直接跳到步骤 4（通才 + 外部资源方案）。
3. **若养得起，评估专家相对通才的增量**
   - 完成标准: 写出专家在该领域能带来什么通才做不到的结果（质量、速度、风险），并换算成可比较的收益。
4. **若养不起，设计"通才 + 外部"组合**
   - 完成标准: 明确哪些问题由内部通才覆盖、哪些触发外部专家介入、触发条件是什么、外部资源从哪里来。
5. **设定重算节点**
   - 完成标准: 给出具体的复查条件（团队人数变化、某类问题频率翻倍等），因为规模变化会翻转答案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 问题本身要求极高的专业深度才能避免灾难性后果（如航空适航、临床手术）——即使频率低也不能让通才凑合。
- 评估某一个具体候选人的能力，而非岗位/结构设计。
- 组织架构已经确定、只是需要人上岗的执行阶段。

### 书中警告的失败模式 / 容易误用的地方

- 书中未提反例；隐含边界是"随组织规模变化而变"，同一组织在不同阶段需要不同类型的人才。
- （推导, 非书中明示）用频率判据时会忽略**问题的严重性**：低频但高损的风险（安全、法律）不适用"养不养得起"的纯经济性判断。
- （推导, 非书中明示）职业发展场景下，个人不像组织那样能随时"外包"——把该模型直接套到个人身上会忽略个人的不可替代性来源。

### 容易混淆的邻近模型

- **狐狸与刺猬（foxes versus hedgehogs）**: 认知风格维度，不是知识覆盖维度。
- **规模经济（economies of scale）**: 解释本模型成立的底层原因。
