# 拐点（inflection point）

## R — 原文 (Reading)

> 有时候，这个点也被称为"拐点"（inflection point），也就是增长曲线出现弯曲或转折的地方。但请注意，在数学领域，拐点实际上是指曲线从凹变凸（或凸变凹）的分界点。
>
> — 《思维模型》, 第4章 > 利用链式反应

---

## I — 方法论骨架 (Interpretation)

"拐点"这个词有两个彼此冲突的用法，混用会造成实实在在的误读，作者专门为此加了提示。

**通俗用法**：增长曲线上"出现弯曲或转折"的地方——势头明显换挡，比如用户量突然开始起飞。它描述的是一个能被感觉到、但边界模糊的转折。

**数学用法**：曲线二阶导数变号的点，即由凹变凸（或凸变凹）的分界点。它精确，但含义和通俗用法不同：在 S 形曲线上，数学拐点位于**增长最快**的那一点（加速结束、减速开始），而不是"开始起飞"的那一点。

所以在采纳曲线上，通俗所说的拐点通常落在临界点附近——起飞的那一刻。关键判据是：**先确认说话人用的是哪个定义**，再看曲线在该处的曲率是否真的变了号。同一条曲线上，两种定义指向的往往不是同一个位置，对应的行动也完全不同：数学拐点意味着"此后增速开始下滑，别再加码"；通俗拐点意味着"杠杆突然变大，该加码了"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户指着一条增长曲线说"我们到拐点了"，但说不清是哪一种拐点，需要先把定义对齐再谈行动。
2. 判断投入时机：现在加码是踩在加速段，还是已经过了增速最高点、边际回报开始下滑。
3. 复盘时把"事后看到的转折"当成"当时可预测的拐点"，需要用曲率数据检验它是否真的存在。
4. 跨部门沟通中，一方用数学含义、另一方用通俗含义讨论同一个"拐点"，导致结论相反。

### 语言信号

- "我们是不是到拐点了"
- "增长曲线在这里开始弯曲"
- "什么时候会起飞"
- "增速是不是已经见顶了"
- "We've hit an inflection point"

### 与相邻 skill 的区分

- 与 `mm-s-curves` 的区别: S 形曲线给的是整条曲线的形状与三段划分；拐点是曲线上的**一个位置**，需要先有 S 曲线（或其他曲线）才能定位它。
- 与 `mm-critical-mass` 的区别: 临界量讲的是"达到某个数量后链式反应自持"，判据是规模阈值；拐点是几何/统计意义上的曲率变化点，判据是二阶导变号。

## E — 可执行步骤 (Execution)

1. **对齐定义**
   - 完成标准: 明确问出（或替用户判定）此处"拐点"指通俗的"趋势转折"，还是数学的"凹凸性改变"，并在结论里写明用的是哪一种。
2. **拿到时间序列并估算曲率**
   - 完成标准: 至少有 5 个以上等间隔时间点；算出相邻区间增长率，再看增长率本身是在上升还是下降（即二阶导符号）。
   - 判停条件: 若数据点不足以判断曲率方向（<5 个，或间隔不均且无法归一化），直接跳到步骤 4，明确说"当前数据无法定位拐点"。
3. **定位拐点并给出两种含义下的位置**
   - 完成标准: 分别标出数学拐点（增速由升转降处）与通俗拐点（增速明显换挡、接近临界点处），说明两者是否重合。
4. **按拐点位置推导行动差异**
   - 完成标准: 给出一句可执行的判断——"在拐点前，加码的边际回报在上升"或"已过拐点，加码的边际回报在下降，应转向换曲线/提效率"。
5. **做前瞻性标注**
   - 完成标准: 把该拐点写成"如果后续 X 个周期内曲率保持此符号，则判定成立"，避免把事后观察当成事前预测。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 过程本身近似线性（如匀速增长的订阅收入），没有曲率可言，找拐点是硬凑。
- 数据点太少或噪声太大，二阶导符号反复横跳——此时任何"拐点"都只是噪声。
- 用户只是想说"发生了重要变化"，并不真的在做曲线分析——用普通的趋势判断即可，不必引入曲率语言。

### 容易误用的地方

- **作者明确提示**：日常用法与数学定义存在偏差，混用会造成误读。这是本模型最核心的失败模式——两个人对着同一条曲线说"拐点"，却指向不同位置。
- （推导，非书中明示）把事后看到的转折当成当时可预测的拐点，是后见之明偏差与本模型的合谋；必须用"事前是否写下预测"来拦一道。
- （推导，非书中明示）数学拐点处增速最高，容易被误读成"还要继续加速"；实际上过了这一点，增速就开始下滑了。
