# 长截图分段读取

## 为什么需要这个技能

WorkBuddy 的 Read 工具会把长图等比缩放到可读范围。一张 886×6223 的手机长截图被压到几百像素高之后，
小字（标签、字段名、按钮文案）会糊成色块，而模型的补全倾向会**自己编出看起来合理的文字**。

这不是"读得不够仔细"，而是分辨率不足导致的系统性误读。表现是：字段名读错（"恋爱三观画像"读成"标签三词形容"）、
凭空多出条目（把图里的图标脑补成"攀岩""颜控"这类标签）、数字读错。

**后果**：基于误读的信息给出建议，比不给建议更糟。

## 标准流程

### 1. 先拿真实尺寸

```bash
sips -g pixelWidth -g pixelHeight "/path/to/shot.jpg"
```

### 2. 分段裁剪 + 放大（PIL）

macOS 上 managed Python 默认无 PIL，用 miniconda 的 python3（已带 PIL）。
先验证：`/Users/fanzuquan/miniconda3/bin/python3 -c "import PIL; print(PIL.__version__)"`

```python
from PIL import Image
p = '/path/to/shot.jpg'
im = Image.open(p)
W, H = im.size
# 每段高度建议 800~1500px（按内容密度调），放大 1.8~2.5 倍
segs = [(0, 1150, 'seg1'), (1150, 2100, 'seg2'), (2100, 4300, 'seg3'), (4300, H, 'seg4')]
for y0, y1, name in segs:
    c = im.crop((0, y0, W, y1))
    c = c.resize((int(W * 1.8), int((y1 - y0) * 1.8)), Image.LANCZOS)
    c.save('/tmp/crop/%s.png' % name)
    print(name, c.size)
```

**分段原则**
- 段与段之间留 **50~100px 重叠**，避免字段被切断在两段交界处。
- 内容密集区（表单、标签墙、聊天记录）用更小的段高。
- 有意义的空白区（大图、插画）可以整段跳过，只做定位。
- 输出成 **PNG**（无损），不要再用 JPEG，二次压缩会继续损失小字。

### 3. 逐段 Read

对每个 PNG 调 Read，一段一段看。**不要**只读第一段就下结论。

### 4. 交叉核验

凡是准备写进结论、且来自小字（数字、标签、按钮文案）的字段，问自己一句：
**这是我在图里看到的，还是我推出来的？** 分不清就在结论里标注为推测。

## 输出时的纪律

- 区分「读到的」与「推断的」。用户按读到的信息行动，推断错了是硬伤。
- 不要因为截图里出现了某个关键词，就假设整张图都在讲这件事。
- 如果放大后仍读不清，直说读不清，不要用"应该是……"填坑。

## 常见坑

| 坑 | 现象 | 处置 |
|---|---|---|
| 直接 Read 整张长图 | 缩略后小字糊掉，模型编字 | 一律先分段放大 |
| 分段不重叠 | 关键字段被切在两段之间 | 留 50~100px 重叠 |
| 放大倍数不够 | 1.2× 仍然糊 | 用 1.8× 起，必要时 2.5× |
| 用 JPEG 存中间件 | 小字继续劣化 | 中间件一律 PNG |
| 只读一段 | 漏掉下半部分字段 | 逐段读完再综合 |
| 忽略状态栏/时间戳 | 错过关键时间信息（截图时间、消息时间） | 顶部状态栏单独作为一段读 |
