# 隔离（quarantine）

## R — 原文 (Reading)

> 还有一种遏制策略是隔离（quarantine），也就是限制人员或货物的流动，以便防止疾病传播。

> — 《思维模型》, 第7章 > 唯一的制胜法宝就是别参战

---

## I — 方法论骨架 (Interpretation)

隔离是一种具体的遏制策略:**通过限制人员或货物的流动,防止有害事物传播**。

它与"消灭源头"路线最大的不同在于——**它不要求你赢**。你不需要识别并清除每一个有害个体,只需要在传播路径上设一道闸,把暴露面降到可接受的范围内。这在源头难以根除、识别成本高、或误伤代价大时,是性价比最高的选择。

书中给的两个例子都体现了这个思路:**垃圾邮件文件夹**不是消灭垃圾邮件,而是把可疑邮件挪到另一个地方,让你不必在收件箱里与它遭遇;**推特用额外的按钮或点击把恶意攻击者与机器人隔开**,不是封掉所有攻击者,而是让他们更难直接触达受众——多加一次点击,就少一大批传播。

关键判据有三条:**(1) 传播路径是否明确?**隔离必须切在真实路径上,否则只是心理安慰。**(2) 闸口的代价是否可接受?**多加一次点击、多一道确认,成本要低到不会让正常流程瘫痪。**(3) 误隔离了怎么办?**把好人关进隔离区是这套方法的主要副作用,必须有申诉/复核通道。

隔离的本质是**用可接受的摩擦换取暴露面的下降**,所以设计的核心不是"拦得多严",而是"拦在哪个位置最划算"。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 系统里出现了无法立刻清除的有害内容或账号(垃圾信息、刷量、骚扰、恶意脚本),用户需要降低它触达用户的概率。
2. 一个故障节点、不可信数据源或实验性模块可能污染主流程,用户想把它放在隔离环境中。
3. 组织中某个团队、流程或人的问题正在影响其他人,用户想先隔开而不是立刻处置。
4. 用户在设计产品流程,想通过加摩擦(确认、延迟、可见性降级)来降低滥用。

### 语言信号

- "先把它隔离开,别影响主流程"
- "能不能加一层,让可疑的进不来"
- "这个数据源不可信,先别接进核心表"
- "垃圾信息太多了,怎么降下来"
- "多加一次确认会不会好点"
- "quarantine it" / "sandbox this" / "isolate the node" / "add friction"

### 与相邻 skill 的区分

- 与 `mm-containment` 的区别: 遏制是**目标与总类**(防止进一步扩张),隔离是**实现遏制的一种具体手段**(切断传播路径);定策略用遏制,选手段用隔离。
- 与 `mm-honeypot` 的区别: 蜜罐是**主动设一个假目标把攻击者引到隔离环境**,隔离是**被动设闸**;蜜罐要引诱,隔离要阻断,方向相反。
- 与 `mm-stop-the-bleeding` 的区别: 止血追求**立刻降低流失速率**,可以粗暴(下线、截断);隔离追求**持续可控的边界**,代价更低、可长期维持。

## E — 可执行步骤 (Execution)

1. **识别真实传播路径**
   - 完成标准: 画出有害事物从源头到受害者的每一条路径,标注每条路径的流量占比;只切在真实的、主要的路径上。
2. **选定闸口位置与摩擦代价**
   - 完成标准: 明确闸门设在哪一步(入口校验、可见性降级、额外确认、独立文件夹、隔离环境),并给出正常用户为此付出的额外成本估计;成本过高则换位置。
   - 判停条件: 若源头可以直接、低成本地清除,优先清除而非隔离。
3. **设计误隔离的出口**
   - 完成标准: 明确被误隔离者如何被发现、如何申诉、多久复核一次;没有出口的隔离会累积信任损失。
4. **测量暴露面的下降**
   - 完成标准: 给出可观测指标(触达率、投诉率、污染记录数),并确认有害事物确实被挡住而不是只是看不见了。
5. **明确隔离不是终局**
   - 完成标准: 说明隔离之后仍要解决的源头问题,并给出后续动作与时间点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 源头可以低成本、彻底地清除:直接清除,隔离会留下长期维护成本。
- 传播路径不明、你只是在"以防万一"地设闸:切错位置的隔离不产生效果,只产生摩擦。
- 把隔离永久化:它控制传播,不解决问题本身,长期化会掩盖源头。(推导,非书中明示)

### 容易误用的地方

- 书中未提边界;以下为基于机制推导的警告(推导,非书中明示)。
- 摩擦加错了地方:加在正常用户必经路径上,会同时压低正常转化与滥用,净效果可能为负。
- 没有申诉通道的隔离:被误隔离的往往是活跃用户或真实数据,沉默的误伤最难被发现。
- 只把内容藏起来(移出视线)而不切断传播:看起来解决了,实际仍在到达用户。

### 容易混淆的邻近模型

- 与遏制(containment): 手段 vs 目标,隔离是实现遏制的主要方式之一。
- 与蜜罐(honeypot): 阻断 vs 引诱,方向相反但都依赖隔离环境。
