# 转型（pivot）

## R — 原文 (Reading)

> 转型（pivot）指的就是转变战略方向。相关例子多不胜数：你可能会惊讶地发现，推特最初是个播客网站，任天堂事实上可以追溯到1889年，当时它是一家纸牌制造商。
>
> — 《思维模型》, 第9章 > 缺少执行的愿景不过是幻想

---

## I — 方法论骨架 (Interpretation)

转型不是"再做一版"，而是**换方向**。这个区分很重要：前者在执行层面修修补补，后者承认此前选定的战略方向本身不成立。

触发时机在书里写得很清楚：**在做了大量客户开发之后，仍然无法达成产品/市场匹配**。注意两个限定词——"大量"和"之后"。没有大量客户开发就谈转型，是在用换方向来逃避尚未完成的验证；而大量验证之后还不转，则是另一种浪费。所以转型既不是怯懦，也不是本能反应，它有一个**由证据决定的时间点**。

为什么这么难？书中给了三条原因：**它要损害组织惯性**（整个团队、流程、考核都围着旧方向转）；**要公开承认失败**（对投资人、对团队、对自己）；**而且还要在此时找到一个更好的方向**（在最疲惫、信誉最低的时候）。三条叠加，让转型在组织里几乎总是被推迟到最后一刻。

可以怎么破？书里建议**借助外部顾问客观审视处境**——因为内部的人同时是那个决策的利益相关者和执行者，很难客观。

判据不是"我感觉不行了"，书中给了三条可核查的依据：**待办任务**（客户到底雇你干什么）、**客户类型测算**（这类客户够不够多）、以及**亮点**是否存在（有没有一小撮人已经在异常热烈地用你的东西）。

判据一句话：**是执行不够、证据不足，还是方向本身被证伪了？**

## A1 — 书中的应用 (Past Application)

### 案例: 任天堂、贝宝与星巴克的转向
- **问题**: 公司创立时的方向，和最终让它成功完全是一个相同的方向吗？如果不是，中间发生了什么？
- **方法论的使用**: 作者用三个跨度极大的例子说明转型不是修补而是换赛道——**任天堂**可以追溯到 1889 年，当时是一家纸牌制造商，中间经历过"超级怪手"这类玩具产品，最终才在游戏机上成为霸主；**贝宝**最初做的是手持设备之间的扫描支付，转向在线支付后才跑通；**星巴克**更极端——成立 13 年之后才卖出第一杯拿铁。这些都不是"优化产品"，而是换掉了整个战略方向。
- **结论**: 作者用"相关例子多不胜数"来强调：转型不是失败者的专利，而是成功者的常态路径。关键在于能否在正确的时机（大量客户开发之后）客观地承认方向不对，而不是无限期地把资源耗在一个已被证伪的方向上。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **多轮客户开发后仍然拉不动**: 该做的事都做了、假设反复被推翻，需要在坚持与换方向之间做判断。
2. **团队因为"已经投入太多"而不肯承认方向有问题**: 需要外部视角和客观依据来打破沉没成本与组织惯性。
3. **职业、关系、教育等非商业领域的方向调整**: 书中明确说转型适用于这些领域，判断逻辑相同。
4. **出现了一个明显更好的相邻机会，但旧方向还有 residual traction**: 需要在两边分配资源。

### 语言信号 (用户的话里出现这些就应激活)

- "我们已经投了这么多，现在放弃太可惜了"
- "要不要换个方向试试？"
- "这条路好像真的走不通"
- "我做这行十年了，现在转行是不是太晚"
- "承认这条路错了，团队会怎么看我"
- "团队一直坚持原来的方向，但数据一直不好"
- "Should we pivot?" / "We've spent too much to quit now." / "Maybe we backed the wrong horse."

### 与相邻 skill 的区分

- 与 `mm-product` 的区别: 产品/市场匹配判定的是**有没有到达目的地的状态**（到了就加码），转型是**在没到达且一段时间内到不了时的应对动作**。顺序上是先判定匹配，再决定是否转型，不能颠倒——很多人把"还没做够"误当成"方向错了"。
- 与 `mm-sunk-cost-fallacy` 的区别: 沉没成本谬误解释**为什么转不了**（已投入的资源在心理上绑架了决策），转型讲的是**该不该转、依据是什么、怎么转**。前者是障碍诊断，后者是行动框架。
- 与 `mm-customer-development` 的区别: 客户开发是判断的**输入来源**（它的结果决定该不该转），转型是对这个结果做出的**方向级响应**。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先确认前置条件：是否已完成"大量客户开发"**
   - 完成标准: 要求用户列出已完成的客户接触次数、被验证/推翻的假设清单。达标才进入下一步。
   - 判停条件: 若客户接触极少、假设几乎没被真正检验过，**判定还不是转型的时候**，停止本流程并把用户送回客户开发。
2. **用三条依据逐项核验**
   - 完成标准: 对每一项给出明确结论：① 待办任务——能否清楚说出客户雇我们完成的任务，说不清记为红灯；② 客户类型测算——这类客户的总量与付费意愿是否足以支撑目标，不足记为红灯；③ 亮点——是否有一小撮用户已经在异常热烈地使用，完全没有记为红灯。
   - 判停条件: 若三条全红，且第 1 步达标，则可以明确给出"应当转型"的判断。
3. **区分该调整还是该转型**
   - 完成标准: 明确地把问题定性为两类之一：若毛病在执行（获客渠道、产品质量、团队能力），则应**调整**而非转型；若毛病在方向（客户任务、付费方、价值主张本身），才成立**转型**。要求用户说出一句"如果改变 X，整个战略是否随之改变"来确认。
4. **引入外部视角**
   - 完成标准: 按书中建议，具体化"外部顾问"的来源名单（行业前辈、投资人、非本项目的同行），并列出要问他们的 3 个问题。这一步不是走过场——它的作用是绕开组织惯性与承认失败的心理成本。
5. **列出候选新方向并做最小验证**
   - 完成标准: 基于亮点和待办任务的信息，给出 2-3 个候选方向，每个配一个两周内可完成的最小验证动作，优先选择能复用现有资产的一个。
6. **算清代价并设停损点**
   - 完成标准: 明确写出转型的代价清单（短期收入骤减、重新培训、团队流失、对外信誉），给出转型期的最低现金/心理承受线，以及"若候选方向在 X 周内未达到 Y 信号则停止"的明确止跌线。书中明示转型代价巨大，这一步不能省。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **还没认真验证过当前方向**: 此时的"转型"多半是逃避困难的借口，会造成每一次都不深入的连续换赛道。
- **问题明确出在执行力或资源不足**: 换方向不会让执行力变好，只会把同样的问题带到一个新领域。
- **周期性低谷**（季节性、短期市场波动）: 在低谷期做方向级决策会把短期波动误判为长期趋势。

### 书中警告的失败模式 / 容易误用的地方

- **书中明示**: 转型**极其困难**，因为它要损害组织惯性、要公开承认失败、还要同时找到一个更好的方向。这三条必须在执行前就明确告知用户，否则计划会严重低估阻力。
- **书中明示**: 转型**适用于职业、人际关系、子女教育等各领域**，但**代价巨大**（短期收入骤减、重新培训）。所以它不是一个轻量建议工具，给出前必须算清代价。
- （推导, 非书中明示）**把转型当逃生舱反复使用**: 每遇到困难就换方向，会形成"永远在做新东西、永远没验证过"的模式。第 1 步的前置检查就是防这个。
- （推导, 非书中明示）**转型出旧方向而不带资产**: 好的转型通常复用已有能力或客户理解（任天堂从纸牌到玩具再到游戏，始终在"让人玩"这件事上）。完全不相关的跳跃风险极高。
- （推导, 非书中明示）**外部顾问变成背书工具**: 找顾问是为了得到客观判断，但人会本能地挑选那些会肯定自己倾向的人。应要求至少有一位明确被告知"请尝试推翻我的判断"。

### 容易混淆的邻近模型

- **亮点（bright-spots）**: 亮点既是判断该不该转型的依据之一（有亮点说明方向可能只对了一半），也是寻找新方向的起点。
- **沉没成本谬误（sunk-cost-fallacy）**: 它解释了为什么"已经投了这么多"这句最常见的话其实不成立——已投入的资源无论如何都收不回来，不该影响接下来的选择。
