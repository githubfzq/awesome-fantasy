# 管理债务 / 设计债务 / 多样化债务（management debt / design debt / diversity debt）

## R — 原文 (Reading)

> 创业文化将这个概念扩展到了其他形式的"债务"："管理债务"（Management debt）是指未能妥善安排长期管理团队的成员或流程。"设计债务"（Design debt）是指没有风格统一的产品设计语言或品牌风格指南。"多样化债务"（Diversity debt）是指没有雇用必要的员工来确保团队多样化。
>
> — 《思维模型》, 第2章 > 越来越热

---

## I — 方法论骨架 (Interpretation)

技术负债的核心是"现在省事、以后昂贵、而且会生利息"。作者把这个结构从代码外推到任何具备同样机制的领域：管理债务（长期管理团队的成员或流程没安排好）、设计债务（没有统一的设计语言或品牌风格指南）、多样化债务（没雇用必要员工确保团队多样化）。作者还进一步扩展到清洁债务、节食债务、关系债务。

判据是：**该领域是否存在"现在不投入、以后必须连本带利补"的机制**。书里给出的后果都很生活化——屋中凌乱、腰围扩大、关系恶化。这些都不是一次性问题，而是会自行恶化的：一周不收拾的家不会停在"一周没收拾"的状态，它会继续变乱。

这个模型的实用之处在于把"我知道该做但一直没做"这件事，从道德自责转成了财务问题：欠账可以记、利息可以算、还本可以排期。一旦能算利息，优先级就自动浮现了——利息高的先还。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队规模扩大但管理层和流程还是创业期的样子，决策全靠创始人拍板。
2. 产品各页面风格不统一、品牌物料各做各的，每次新增功能都要重新发明一套。
3. 团队背景高度同质，意识到缺少多样化但一直没落实在招聘上。
4. 个人或关系的"我知道该做但一直没做"：不运动、不收拾、不联系重要的人。

### 语言信号

- "管理这块先凑合，等业务稳定了再规范"
- "每个设计师出的图风格都不一样"
- "团队全是同一类人，会不会有问题"
- "一直说要锻炼/收拾/联系他，就是拖着"
- "management debt / we'll fix it later"

### 与相邻 skill 的区分

- 与 `mm-technical-debt` 的区别: 技术负债限于代码与架构层面的欠账，已有成熟的量化与偿还实践；本模型是把它外推到管理、设计、多样化乃至个人生活领域，欠账形式更软、利息更难算。
- 与 `mm-compound-interest` 的区别: 复利描述的是正向收益的指数累积；债务描述的是欠账的指数恶化。方向相反，但机制对称。

## E — 可执行步骤 (Execution)

1. **选定一个领域，问"这里现在省掉的事，将来会以什么形式连本带利补回来"**
   - 完成标准: 能说出一个具体的恶化机制，而不是笼统的"以后会麻烦"。
   - 判停条件: 若找不到会自行恶化的机制，这不是债务，是普通待办，停止本模型。
2. **列出欠账清单**
   - 完成标准: 每项写明三件事——欠的是什么、利息是什么（每个周期多付的成本）、什么时候到期。
3. **估算利息并排序**
   - 完成标准: 每项有一个周期成本估计（时间、钱或机会），按利息从高到低排序。
4. **定一个最小的还本动作并排期**
   - 完成标准: 针对利息最高的一项，给出本周/本月可执行的最小动作，并写进日程。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 只是普通待办堆积、不会自行恶化时，用一般优先级排序即可，套"债务"框架会制造虚假的紧迫感。
- 纯代码与架构层面的欠账，直接用技术负债，那里有更成熟的偿还方法。

### 容易误用的地方

- 书中未给出边界（`boundary` 字段为"书中未提"），以下为推导:（推导, 非书中明示）管理债务、设计债务、多样化债务的利息很难客观量化，容易变成"谁嗓门大谁说了算"；建议只做量级排序（高/中/低），不要追求精确数字。
- （推导, 非书中明示）有些欠账可以永远不还——如果某个领域将来根本不会继续投入，那它就是一次性取舍而非债务，别为它支付焦虑成本。
