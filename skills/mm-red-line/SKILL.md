# 红线／底线（red line / line in the sand）

## R — 原文 (Reading)

> 当你通过可信的威胁进行"威慑"时，就是画清了红线（red line）。……如果有人跨过这条线，就会遭到报复……这条线也被称为底线（line in the sand）。
>
> — 《思维模型》, 第7章 > 改变战局

---

## I — 方法论骨架 (Interpretation)

红线是威慑（deterrence）的**具体形态**：不是等对方越界后再惩罚，而是在事前公开宣告一条界线与越界后果，从而直接改写对方对每个选项的收益估计——对方不是"怕你生气"，而是算出来"越线不划算"。

它成立依赖三个条件，缺一条就只是嘴上的狠话：

1. **界线可观测**——对方能 unambiguously 判断自己是不是越线了。"别太过分"不是红线，"超过约定交付日 3 个工作日"才是。
2. **后果明确**——必须说清越线后你会做什么，不能只说"后果自负"。对方要能把后果放进自己的收益矩阵里算。
3. **威胁可信**——你有能力、也有意愿真的执行。这点最关键：威慑生效于对方的**预期**，而预期来自你过去的兑现记录。

关键判据是：**如果对方真的越线，你此刻会不会执行你宣布的后果？** 会，这条线才是真的；犹豫，那它就不是红线，是一次情绪表达——而一次不兑现之后，你再画的线都会被折价。

所以画红线的真正成本不在"说"，而在"说完后你就失去了不执行的自由"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 合作方/供应商反复试探边界（延期、加价、超范围），用户在想"要不要正式警告一次"。
2. 团队或家庭中某人反复做同一件越界的事，用户已经说过好几次"下次不行了"但没用。
3. 用户准备发一条"再这样我们就终止合作"的强硬声明，想确认这么说是否明智。
4. 谈判前想设计一套"让步底线 + 越线动作"，避免临场被逐步蚕食。
5. 用户在纠结"我该不该把话说死"——怕说了收不回，又怕不说对方继续踩。

### 语言信号 (用户的话里出现这些就应激活)

- "我得给他划条线了"
- "再这样我就不客气了 / 我们就终止合作"
- "这是我的底线，不能再退了"
- "已经警告过他好几次了，没用"
- "他在不断试探我的底线"
- "We need to draw a line / this is a line in the sand"
- "If they cross this line, we walk away"

### 与相邻 skill 的区分

- 与 `mm-deterrence` 的区别: 威慑是一般原理（用可信威胁改变对方收益矩阵），红线是它的**操作形态**——把威胁落成一条具体可观测的界线。用户已在讲"哪条线"时用红线，还在问"要不要吓住他"时用威慑。
- 与 `mm-nuclear-option` 的区别: 核选项是红线的极端形态——后果是同归于尽式的极端行为。若用户描述的后果是"我也完蛋"，那是核选项而非普通红线。
- 与 `mm-zero-tolerance-policy` 的区别: 零容忍是不分级、初犯即重罚的政策化红线，取消了"逐级升级"的空间。用户问"要不要给一次改过机会"时，是二者的分水岭。
- 与 `mm-call-your-bluff` 的区别: 叫你摊牌是**对方**用来检验你红线真假的动作，是红线的风险面。用户说"他故意挑衅看我敢不敢"，应切到叫你摊牌。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **还原对方的收益矩阵**
   - 完成标准: 列出对方此时面对的 2-3 个选项，以及他当前对每项后果的估计，并指出他为何仍在越界（越界收益 > 他预估的代价）。
2. **把界线写成可观测事件**
   - 完成标准: 产出一句"当 X 发生时"的描述，X 可被第三方客观判定，不含"过分""不尊重"这类主观词。
   - 判停条件: 若用户坚持只能主观描述，跳到步骤 5 并明确告知这条线在争议时会失效。
3. **写出越线后的具体动作**
   - 完成标准: 后果是**你的一个可执行行为**（暂停付款、终止条款生效、走仲裁），而非"后果自负"；并写明启动时点与执行人。
4. **做可信度压力测试**
   - 完成标准: 回答三个问题——我有能力执行吗？执行的代价我承受得起吗？对方相信我会执行吗（过去的兑现记录如何）？任一项为否，则先缩小红线范围或换更轻的后果。
5. **决定传达方式并预告**
   - 完成标准: 明确是公开宣告还是私下告知、书面还是口头，且措辞冷静、不含情绪性修饰。
6. **预设兑现方案**
   - 完成标准: 写下一句"如果对方真的越线，我在 24 小时内会做 ______"，并确认用户此刻真心愿意执行。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 对方不是算计后选择越界，而是**不知道**边界在哪——这时需要的是说清楚与建立流程，不是威胁。
- 关系以长期信任为主、且对方以往可信——过早亮红线会把合作框架扭成对抗框架，代价大于收益。
- 用户只是想发泄情绪，并不打算执行任何后果——这只会消耗信誉，不如不说。
- 涉及人身安全、违法侵害等情形，正确动作是求助与留证，不是谈判式划线。

### 容易误用的地方

- 书中明示：若威胁不可信或不兑现，信誉受损，对手的收益矩阵就不会按你希望的方式改变。也就是说，**不兑现的红线比不画更糟**——它教会对方你的话可以打折。
- （推导, 非书中明示）红线画得太密、太远：什么都设红线，等于没有红线。应只留给真正不可接受的那 1-2 条。
- （推导, 非书中明示）后果定得过重会降低可信度——对方会判断"他不可能真这么做"，反而削弱威慑。适度、确定、可执行优于极端、模糊、难以执行。

### 容易混淆的邻近模型

- **核选项（nuclear option）**: 后果是玉石俱焚的极端行为，属于红线的极端档位。
- **承诺（commitment）**: 红线是一种向外的承诺；承诺模型更广义，也包含对内的自我约束。
