# 利弊清单（pro-con list）

## R — 原文 (Reading)

> 这种权衡利弊的方法虽然在一些简单情况下挺管用，但也存在不少缺点。第一，这个清单假定只有两个选项，而正如你在前面看到的，选项通常会多得多。第二，它假定所有好处和弊端拥有同样的权重。
>
> — 《思维模型》, 第6章 > 权衡成本与收益

---

## I — 方法论骨架 (Interpretation)

利弊清单是**列出某决定的好处与弊端再两相权衡**的最简决策框架，也是绝大多数人的默认思考工具。作者没有否定它——"在一些简单情况下挺管用"——但立刻列出了四条结构性缺陷：

1. **假定只有两个选项**。而现实中的选项通常多得多（做/不做之外还有"晚点做""小范围做""换个做法"）。
2. **假定所有好坏同等重要**。一条"能改变世界"和一条"通勤近"被当成等权的一票。
3. **孤立看待相互关联的因素**。有些条目会互相触发或互相抵消，清单把它们摊平成互不相关的行。
4. **好处通常比弊端显眼**。收益是主动想象出来的，弊端是被动遭遇的，因此清单会**系统性地高估积极面**。

第四条最隐蔽也最致命：你列出的"弊端"只包含你能预见到的，而**经验越有限，越难列全——你根本不知道自己漏掉了什么**。

作者用自己的经历给了一个活案例：2000 年毕业后他考虑转行做风险投资，清单上只见好处（改变世界、高额回报、不用承担创始人风险），完全没列全弊端（必须不断社交、持续拒绝别人的心理负担、入行极难、大部分时间耗在困境公司上）。事后证明并不适合他。

**判定它是否够用的两个问题**：①选项是否真的只有两个？②后果是否轻微？两者都答"是"才可以用；任何一条答"否"，就该升级为打分式成本收益分析或决策树。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 面对一个小型的"要不要做"决策，想快速理清思路（换不换手机、要不要接这个活、去不去这个会）。
2. 用户已经开始列优缺点，需要帮助把清单列全、尤其是补上被忽略的弊端。
3. 用户拿一张利弊清单来做一个影响很大的决定，需要提醒他工具不够用。
4. 团队讨论卡在"感觉好处多、但又说不上哪里不对"，需要把隐性担忧显性化。
5. 需要判断当前决策该用哪个层级的决策工具。

### 语言信号

- "我列了个优缺点清单"
- "好处挺多的，坏处好像没什么"
- "要不要做，帮我权衡一下"
- "感觉不该做，但说不出哪里不对"
- "两个选项各有利弊，选哪个"
- "let me make a pro con list / pros and cons / weigh the upsides"

### 与相邻 skill 的区分

- 与 `mm-cost-benefit-analysis` 的区别: 成本收益分析给每条利弊**打分并加权求和**，处理"权重不等"这个缺陷；利弊清单默认等权。后果轻微、条目之间量级接近时用清单，量级悬殊时用成本收益分析。
- 与 `mm-decision-tree` 的区别: 决策树处理**不确定性与时序**（这一步之后还有多种可能结果），利弊清单是一张平面表。选项中含明显的不确定性分支时，用决策树。
- 与 `mm-maslow-s-hammer` 的区别: 马斯洛之锤是**关于工具选择本身的元警告**（别拿唯一的工具套所有问题）；本书中作者正是把利弊清单指认为决策领域的那个"锤子"。用清单前先看这个警告。

## E — 可执行步骤 (Execution)

1. **先做适用性检查**
   - 问两个问题：①选项真的只有两个吗？②后果轻微吗？
   - 完成标准: 明确判定"可以用清单"或"应升级工具"。
   - 判停条件: 若选项 >2 或后果严重，跳到步骤 5 升级为打分式成本收益分析或决策树。
2. **穷举选项，确认是否真的只有两个**
   - 主动提出第三、第四条路（推迟、小范围试、折中方案、外包）。
   - 完成标准: 至少确认过"做/不做"之外还有没有别的选项。
3. **列好处，然后强制列弊端——且弊端数量不得少于好处**
   - 针对第四条缺陷（好处更显眼），刻意反向投入：问"一年后我会后悔什么""最坏情况是什么""别人在这个决定上踩过什么坑"。
   - 完成标准: 弊端条目不少于好处条目；若列不出来，说明认知盲区大，应去请教有经验的人。
4. **标记相互关联与权重悬殊的条目**
   - 问：哪些条目会互相触发/抵消？哪一条的量级明显压过其他所有条？
   - 完成标准: 标出关联关系，并圈出 1-2 条主导性因素。
   - 判停条件: 若存在压倒性的主导因素，说明清单已不必要——直接按那条决定。
5. **若不满足适用条件，升级工具并说明升级理由**
   - 权重悬殊 → 打分式成本收益分析（给每条赋权重）；含不确定性 → 决策树（给分支赋概率）；含无形成本 → 引入效用值。
   - 完成标准: 明确告诉用户"这个问题的复杂度超过了利弊清单"，并给出替代方案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- **选项超过两个**：清单默认二选一，多选项下会漏掉更好的方案（书中明示缺陷一）。
- **各条目权重悬殊**：等权假设会让一堆小事压过一件大事（书中明示缺陷二）。
- **因素相互关联**：清单把耦合因素孤立看待，会重复计数或漏掉连锁效应（书中明示缺陷三）。
- **决策后果严重且不可逆**：应改用决策树等更重的工具（作者建议，书中明示）。

### 容易误用的地方

- 书中明示的缺陷四：**好处通常比弊端显眼，因而系统性地高估积极面**。作者自己的风投转行案例就是活证据——清单上只有好处，没列全弊端，事后证明不适合他。
- 书中明示：作者建议至少升级为**"打分式"成本收益分析或决策树**。
- （推导，非书中明示）最容易犯的错：把"我列不出弊端"当成"没有弊端"。经验不足时恰恰是清单最不可靠的时候。

### 容易混淆的邻近模型

- 成本收益分析（cost-benefit-analysis）：加权打分版，是本书推荐的升级路径之一。
- 马斯洛之锤（maslow-s-hammer）：对"只会用利弊清单"这一现象本身的元警告。
