# 雾件（vaporware）

## R — 原文 (Reading)

> 有一种相关的商业实践称为雾件（Vaporware），也就是公司对外宣布一款实际上尚未完成的产品

> — 《思维模型》, 第7章 > 底线在哪儿

---

## I — 方法论骨架 (Interpretation)

雾件是**对外宣布一款实际上尚未完成的产品**。它不是简单的"跳票",而是一种有目的的传播动作:用一句"我们即将推出",去改变两类人的决策。

对**客户**:宣布即将有更好的选择,会让一部分人推迟当下的采购——他们等你的产品,而不是去买别人的。对**竞争对手**:宣布你即将进入,会让对方重新评估投入——要不要抢在你前面、要不要放弃这块市场、要不要也宣布一个对应的东西。

它成立的原因是**预期可以替代实物产生作用**。客户和对手做决策时依据的是对未来可得性的判断,而判断只需要一个可信的信号,不需要产品真的存在。所以只要宣布足够可信,未完工的产品也能产生真实的市场效果。

书中列出的三种用途很关键:**(1) 测试用户需求**——宣布后看市场反应,再决定要不要真做;**(2) 评估业界反应**——收集反馈;(3) 让竞争对手停止争夺同一市场**——用"这里马上是我的了"冻结对方投入。前两种是信息收集,第三种是竞争武器。

对应的判据是:**这个宣布改变了谁的决策、改变了什么?**如果宣布只是同步进度,它是路线图;如果宣布的主要效果是让客户等待、让对手退让,它就是雾件——而后者承担的是信用成本。

---

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户在等某家厂商已宣布的产品,想判断还要不要继续等、会不会永远等不到。
2. 用户是产品/市场负责人,在考虑要不要提前官宣一个未完工的东西来试探需求或压制竞对。
3. 用户发现竞对突然宣布了一个"即将推出"的东西,想知道这是真在做还是在拖住自己。
4. 用户在评审自家路线图的对外口径,想划清"进度同步"和"雾件"的界线。

### 语言信号

- "他们去年就宣布了,到现在还没影"
- "要不要先官宣一下探探市场反应"
- "竞对刚宣布要做一个,我们要不要跟"
- "客户说在等那个产品,所以不下单了"
- "这个发布会的东西真能交付吗"
- "vaporware" / "announced but never shipped" / "we're about to launch"

### 与相邻 skill 的区分

- 与 `mm-potemkin-village` 的区别: 雾件骗的是**未来**(宣布还没做出来的东西),波将金村骗的是**现在**(摆出已经做好的样子);一个是"承诺",一个是"布景"。
- 与 `mm-deterrence` 的区别: 威慑靠**威胁后果**改变对方行为,雾件靠**提供预期**(我这儿会有更好的)改变对方行为;一个推,一个拉,但都有可能只是虚张声势。
- 与 `mm-minimum-viable-product` 的区别: MVP 是**先交付最小可用版本再迭代**(东西真的能用),雾件是**只宣布不交付**;前者有实物,后者只有信号。

## E — 可执行步骤 (Execution)

1. **确认"未完成"这个事实**
   - 完成标准: 明确该产品当前是否有可交付版本、是否有公开可用版本、是否有外部可验证的试用;只有"已宣布 + 无实物"两条同时成立才进入雾件分析。
   - 判停条件: 若已开工且按期推进,按正常路线图处理,不要套雾件。
2. **识别宣布动作的受益方向**
   - 完成标准: 逐条回答——它让客户推迟了什么采购?让哪个竞争对手改变了什么投入?若两者皆无,可能只是进度同步而非雾件。
3. **评估发布方的代价与可信度**
   - 完成标准: 列出该宣布对发布方的信用成本(跳票后的品牌损失、渠道关系、后续发布的可信度),以及它过去跳票的记录;给出"可信/不可信"的明确判断。
4. **给出用户侧动作**
   - 完成标准: 若用户是等待方——给出停止等待的判据(设定截止日期、要求书面承诺、同时推进备选方案);若用户是发布方——给出越线检查(若不打算在合理周期内交付,就不要官宣,改用私下访谈或小范围测试来收集需求)。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 已开工、有明确交付节点并按期推进的路线图公告:那是进度同步。
- 因为技术难题或合规原因延期,且持续如实披露进度的项目:跳票不等于雾件,关键在于宣布时的意图。
- 内部小范围的概念测试:没有对外改变任何人决策,不构成雾件。

### 容易误用的地方

- 书中未给边界条件;以下为基于机制推导的警告(推导,非书中明示)。
- 把"跳票"直接等同于雾件:意图是判据,延期是结果;只看结果会误判大量真实存在困难的团队。
- 反向误用:自己用雾件试探需求时,忘了它同时会**训练市场不信你的下一次宣布**——信用是一次性资产。
- 雾件确实可能拖住对手,但对手可能已经把你的宣布折扣处理;不要假设宣布一定有效。

### 容易混淆的邻近模型

- 与波将金村(potemkin-village): 未来 vs 现在的欺骗,常同时出现(先雾件后布景)。
- 与最小可行产品(minimum-viable-product): 有实物 vs 无实物。
