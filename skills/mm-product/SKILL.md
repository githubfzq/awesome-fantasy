# 产品/市场匹配（product/market fit）

## R — 原文 (Reading)

> 率先进入市场并不是关键。确切地说，从长远来看，率先实现产品/市场匹配的才是赢家……一旦一家公司实现了产品/市场匹配，就很难被逐出市场。
>
> — 《思维模型》, 第9章 > 缺少执行的愿景不过是幻想

---

## I — 方法论骨架 (Interpretation)

先发不如先对。这是这个模型的第一句话，也是在纠正一个很普遍的误解：**第一个做的人不一定是赢家**，第一个把产品和市场对准的人才是。

什么叫对准？书里给的现象层面的描述非常具体：**客户主动要求增加供应**。不是你去说服他们买，而是他们在拉着你多给一点。一旦到了这个状态，公司就很难被逐出市场——即便出现质量更好或价格更低的竞品，也往往替换不掉它。

为什么竞品更好也抢不走？因为匹配达成时会发生一种类似**共振频率**的跃升：这本书强调，它不是"略好一点"，而是"**好很多倍**"。线性的差距是可以被追赶的（对手做三个月就追上了），但当一个产品在某个具体人群、具体任务上对了，它带来的体验差距是非线性的——用户的迁移意愿不是按改进幅度线性变化的，而是在某个点之后突然归零。

这个模型的适用范围远不止产品。作者明确给出了迁移版：**人员/组织匹配、成员/团队匹配、文化/策略匹配、信息/受众匹配**。判断逻辑都一样：两边是不是严丝合缝地对上了？

由此也得到一个反直觉但很重要的结论：**如果你的做法是`先做出来、再去找人买`，你可能把顺序搞反了**。如果把 `mm-pivot` 的判据看一眼会更清楚：书中的转型发生于"做了大量客户开发之后仍无法达成匹配"。

同时必须知道的边界：**即使实现了匹配，护城河仍可能失效，最终仍可能需要转型**。匹配不是终点站的到达证明，它仍然需要维护。

判据一句话：**把产品拿走，客户会不会主动来找你要回来？**

## A1 — 书中的应用 (Past Application)

### 案例: 政治候选人的信息/受众匹配
- **问题**: 为什么有些候选人的主张在局外人看来并不出彩，却能激起某个群体极强的热情？
- **方法论的使用**: 作者把它当作产品/市场匹配在传播领域的迁移版——**信息/受众匹配**。桑德斯和特朗普的做法是精准触及特定群体的痛处：他们的表达在别的群体听来刺耳甚至荒谬，但在目标受众那里正好击中了那个长期没人替他们说的点。这里"产品"是候选人传达的信息，"市场"是那个特定的选民群体，两者严丝合缝地对上了。
- **结论**: 这解释了为什么"对手质量更好/更温和"起不到替换作用——对一个已经在情感和信息上达成匹配的受众来说，一个"更体面"的竞品根本不构成替代品。作者用它说明该模型可以脱离商业产品，用来理解任何"供给方与接收方是否对准"的情形。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **产品在用但增长停滞、留存差**: 用户投入很久却拉不动，需要判断是执行不够还是压根没对上市场。
2. **出现"更好的竞品"、自己在犹豫要不要慌**: 需要用"是否被替代"来反向验证自己的匹配强度。
3. **招聘、组队、搭班子的场景**: 用户抱怨"他能力很强但就是不合"、"我和这个公司气场不合"，这是人员/组织与文化/策略匹配的问题。
4. **内容/表达没人看**: 用户在自我怀疑"是不是我写得不好"，实际很可能是信息/受众没匹配。

### 语言信号 (用户的话里出现这些就应激活)

- "我们的产品其实比他们好，但就是卖不动"
- "用户在流失，我不知道哪里不对"
- "他履历很好，但感觉跟团队合不来"
- "我发的内容没人看，是不是我水平不行"
- "我们该加功能还是改方向？"
- "为什么比我们晚进场的人反而做起来了"
- "Do we have product/market fit?" / "Users aren't sticking around." / "A cheaper competitor just launched."

### 与相邻 skill 的区分

- 与 `mm-customer-development` 的区别: 客户开发是**达成匹配的手段**（怎么通过快速试验去逼近它），产品/市场匹配是**达成的状态**（到了没有）。用户问"我还该做什么"用前者，用户问"我到了没有 / 该加码还是该转"用后者。
- 与 `mm-first-mover-advantage` 的区别: 先发优势讲的是"第一个进场能得到什么"，书中明确否定它在长期的关键作用——**率先进入市场并不是关键，率先实现匹配才是**。"先发就能赢"的说法在这本书里是被明确反驳的对象。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先问"客户有没有主动来要"**
   - 完成标准: 收集具体证据——有没有非付费流量下的主动询单、有没有用户自发推荐、有没有人要求开放还没做的功能、有没有用户抱怨"为什么不让我多买"。这是书里给的首要标志。
   - 判停条件: 若三个以上渠道都找不到任何主动索取信号，判定未达成匹配。
2. **做撤回测试**
   - 完成标准: 对每个主要客户群问"如果明天这个产品消失，谁会真的难受？"。要求点名具体人或具体群体，答不出名字就算没对上。
3. **检查竞争优势是否非线性**
   - 完成标准: 让用户回答"相比替代品，我们在那个具体任务上好多少"。按书中的说法，达成匹配时的差距应该是**好很多倍**而不是略好；若答案是"差不多，我们便宜 10%"，判定未达成，产品仍处于可被替换的状态。
4. **看替代的实际发生情况**
   - 完成标准: 明确列出已出现的竞品（质量更好/价格更低的），并检查目标客户有没有真的流失过去；或反过来，若已有这样的竞品而客户仍留下，则为达成匹配提供了强证据。
5. **给出加码 / 转型 / 深挖的决策**
   - 完成标准: 三种之一是明确的结论 —— 达成匹配则加码（资源集中到这个匹配的扩张）；未达成但能看到明确的人群与任务，则指定该补什么；反复尝试后仍未达成，则应转介给 `mm-pivot` 讨论转型。同时提醒书中明示的边界：即使达成匹配，护城河也可能失效，最终仍可能需要转型。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **还没有任何真实用户**: 没有市场反馈就没有可判定的匹配状态，此时应做客户开发而不是分析匹配。
- **受管制或单一供给的环境**: 用户没得可选时，"没人流失"不能证明匹配。
- **纯执行问题**（Bug、交付慢、渠道没铺）: 用这个模型分析会导向不必要的全面转型。

### 书中警告的失败模式 / 容易误用的地方

- **书中明示**: **即使实现了产品/市场匹配，护城河仍可能失效，最终仍可能需要转型**。匹配带来的是一段领先期，不是永久安全。
- （推导, 非书中明示）**把小规模亲切反馈当成匹配**: 亲友和早期热心用户的正向反馈几乎必然出现，它不代表"客户主动要求增加供应"。第 1 步强调非付费流量下的主动索取就是为了过滤这种噪声。
- （推导, 非书中明示）**混淆"用户多"与"匹配好"**: 通过强投放买来的用户会在停投后立刻消失，这与"很难被逐出市场"是相反的状态。要看自然留存而非总用户量。
- （推导, 非书中明示）**一次匹配被当成永久资产**: 人群会迁移、替代品会换代，第 5 步的定期复检就是防这个。

### 容易混淆的邻近模型

- **客户开发（customer-development）**: 它是找到匹配的过程方法，而本模型是对结果状态的判定。两者是"手段 vs. 目标"。
- **转型（pivot）**: 转型是在大量客户开发之后仍未达成匹配时的应对动作。是否要转，取决于本模型的判定结果，顺序不能颠倒。
